# Runic IR v4

This is the serialized contract between the frontend adapters and the Rust backend (D1). Its types live in `crates/runic-ir` (`src/lib.rs`), and that crate is the authority whenever this document and the code disagree. The `runic-ir` validator and reference interpreter define its meaning. The code generator in `crates/runic-codegen` must agree with that interpreter (D8).

Schema 4 was introduced in M1 and extended additively in M2 with values, statements and functions ([design](design/M2-VALUES.md)) in M3 with component instances, lists, slots, refs and more events ([design](design/M3-COMPONENTS.md)), and in M4 with scheduling, effects, derived values, promises and host services ([design](design/M4-EFFECTS.md)); M6 adds class records, their reactive fields, class hierarchies and class references, imperative mounts, ResizeObservers and animation objects ([design](design/M6-OVERLAYS.md)), and HTML fragments for `{@html}` ([design](design/M6-SVELTEKIT.md)). The frontends in `frontend/` emit it directly. Older schema 2/3 artifacts are still accepted and migrated with `runic_ir::migrate`.

## Program

```jsonc
{
  "schema": 4,
  "meta": { "title": "…", "sourceHash": "<sha256>", "frontend": {…}, "provenance": […], "mappings": [{ "id": "clsx@2.1.1", "version": 1, "sha256": "…" }] },
  "renderer": "cpu",                 // D12: "cpu" | "gpu"
  "capabilities": ["dom", "css", "window", "click", "keyboard", "text-input"],
  "styles": { "css": "…", "assets": [{ "path": "assets/x.woff2", "sha256": "…", "bytes": 1234, "mime": "font/woff2" }],
              "guards": [{ "selector": "…", "unless": "…", "when": "scroll-target", "message": "…" }] },  // M6: declarations the style engine drops, reported once an element matches selector and not unless (once one is scrolled into view with when)
  "records":   [ { "name": "Item", "fields": [ { "name": "label", "type": "string" } ] } ],  // "class": true marks class instances (M6), "extends": b a subclass, "abstract": true, "tuple": true a tuple (M6 overlays); fields may be "reactive"
  "functions": [ Function, … ],
  "globals":   [ { "name": "DEFAULTS", "type": T, "init": Expr } ],  // module constants, evaluated once in order
  "components": [ Component, … ],
  "root": 0,                         // index of the mounted component
  "containerAttrs": { "data-v-app": "" },  // optional: attributes the framework sets on #root at mount
  "body": { "data-x": "1" },         // optional (M6): attributes of <body> (a Kit app.html)
  "container": { "style": "display: contents" },  // optional (M6): the container element replaces div#root, with these attributes
  "restoreFocus": true,              // optional: refocus an element a list move blurred (React DOM)
  "fragments": [ { "html": "<span>…</span>", "nodes": [FragmentNode] } ],  // optional (M6): HTML parsed at build time for `html` nodes
  // schedule.controlledRestore: restore controlled values after every event (React)
  // schedule.commitEventsIgnored: events dispatched during the DOM update reach only window and document listeners (React DOM disables its event system while it commits)
  "schedule": {                      // optional: the framework's update scheduling (defaults shown)
    "flush": "microtask",            // or "event-microtask": a default task outside input events
    "checkpoint": "dispatch",        // or "listener": a microtask checkpoint after each listener
    "changeWithClick": false,        // a checkbox's change listeners run in the click dispatch
    "cleanups": "interleaved",       // or "batched": a phase's cleanups (also of destroyed instances) before its effects
    "postWritesDeferred": false,     // writes from post effects update in a later default task
    "mount": "microtask",            // when the mount's effects run: "sync" | "microtask" | "task"
    "cleanupReadsPrevious": false,   // cleanups read state as before the running flush
    "continuous": []                 // M6: events whose updates render as a default task (React: ["scroll"])
  }
}
```

`meta.mappings` lists the mapping packs ([D9](design/M6-LIBRARIES.md#mapping-packs-d9)) the frontend used: `<package>@<version>`, the pack format version (1) and the SHA-256 of the pack module. It is provenance only: packs lower to ordinary IR (expressions, functions and template nodes), so the backend never sees a package.

CSS refers to embedded assets as `url("runic-asset:<index>")`. The runtime resolves them from bytes compiled into the binary. Every object rejects unknown fields.

## Types and values

Types follow the value model (D16, [M2-VALUES](design/M2-VALUES.md)). Unit types serialize as strings and the others as single-key objects:

| Type | JSON | Native representation |
|---|---|---|
| number | `"number"` | `f64` with JavaScript semantics (`NaN`, `-0`, shortest round-trip `toString`) |
| string | `"string"` | `JsString`: immutable UTF-16, so indexing and `.length` count code units |
| boolean | `"boolean"` | `bool` |
| no value | `"void"` | result type of functions without a value |
| nullable | `{"maybe": T}` | `Maybe<T>`: `undefined`, `null` or a value |
| array | `{"array": T}` | `JsRef<Vec<T>>`: shared, mutable, identity equality |
| record | `{"record": i}` | generated struct behind `JsRef` (index into `records`) |
| class reference | `{"class": c}`, `{"classes": [c…]}` | `Obj`: the program's enum of instances by class (a variant per concrete class record holding its `JsRef`); identity equality (M6) |
| map / set | `{"map": [K, V]}` / `{"set": T}` | insertion-ordered, SameValueZero keys |
| function | `{"fn": {"params": [T…], "result": T}}` | reference-counted closure (a component function's closure keeps its instance) |
| element | `"element"` | opaque element handle (refs), identity equality |
| attribute bag | `"attrs"` | `js::Attrs`: ordered `(name, value)` entries (attribute text, absent, boolean presence, or an `on<event>` listener; M6 overlays: `on<event>capture` capture listeners, values of other types for components' props, style objects with the object they were made from); compared by entries, listeners by function identity (M5), values by `===` |
| event | `"event"` | `js::Event`: the event object of a dispatch, read through `event.*` built-ins; identity equality (M5) |
| regexp | `"regexp"` | `js::RegExp`: a RegExp object (pattern, flags and a mutable `lastIndex`), read and used through `regexp.*` built-ins; identity equality (M5) |
| date | `"date"` | `js::Date`: a Date object (a mutable time value), read and changed through `date.*` built-ins; identity equality; `to-string` is `toString()`, `to-number` the time value (M5) |
| promise | `{"promise": T}` | `JsPromise<T>`: pending or settled, reactions run as microtasks; identity equality; never a promise of a promise. M6: a promise rejected while it never had a reaction is reported as Chromium reports it: at the end of each microtask checkpoint the rejections it left are handed to a default-priority task, which writes the console error line `Uncaught (in promise) Name: message` for those still without a reaction; a reaction added after that is reported unsupported (Chromium revokes the report) |
| mounted | `"mounted"` | `js::Handle`: an imperatively mounted component instance (`mount`), identity equality (M6) |
| contexts | `"contexts"` | `js::Handle`: the contexts an instance sees (`context.all`), identity equality: the same value for every call in one instance (M6) |
| animation | `"animation"` | `js::Handle`: a running CSS animation or transition of an element (`element.getAnimations()`), identity equality: the same object while the runtime tracks the animation; read through `animation.finished` (`promise<animation>`), `animation.playState` (`string`) and `animation.pending` (`boolean`), which, like `element.getAnimations`, need the native style engine (the interpreter throws `RunicLayoutError`) (M6) |

**Class instances** (M6, [design](design/M6-LIBRARIES.md#library-code-steps-3-to-6)) are records with `"class": true`: nominal (the frontend never shares a class record with a structurally equal one), with one field per instance field, `#private` ones included under their `#name`. Methods, accessors and constructors are ordinary functions (a method takes the instance as its first parameter; a constructor returns it), so the interpreter and code generator need no other construct. Class records differ from plain ones in three ways: deep state never proxies them (Svelte's `$state` proxies plain objects and arrays only, so a `proxied` cell holds the instance itself, and mutating it in place while the template reads it is `E_REACTIVITY`); they are not plain data (`JSON.stringify`, `JSON.parse`, `structuredClone` and `Object.keys`/`values` reject them); and `to-string` of one is `E_CLASS` (its `toString` method would not be dispatched).

**Reactive class fields** (M6 stage B, [design](design/M6-LIBRARIES.md#reactive-class-fields-stage-b); Svelte's `$state`, `$state.raw`, `$derived` fields) are fields of class records marked `"reactive": "state"`, `"raw"` or `"derived"`; a derived field also names its function, `{ "name": "total", "type": "number", "reactive": "derived", "derived": 12 }`, which takes the instance and returns the field's type (a component function when the class is declared in a component script: the field is then read only in that component). They are signals of the instance:

- **Construction.** A `record` expression gives no value for derived fields; the value given for a `state` field is stored as a write stores it.
- **Reads.** `get` of a reactive field is a dependency of the running tracked effect or derived value, like a cell, unless that computation created the instance (Svelte does not track the signals a reaction creates). `get` of a derived field computes it if it never was or if what its last computation read changed, then gives the cached value; a recomputation `===` to the cached value keeps it, so its readers see no change.
- **Writes.** `assign` to a `state` field stores proxies of plain objects and arrays, as `proxied` cells do; a `raw` field stores the value as it is. A value `===` to the old one changes nothing (the field keeps the old value: `-0` written over `0`); otherwise the write queues the flush and makes the field's readers out of date. Mutations through the proxies a `state` field holds are reactive as those of `proxied` cells are. Derived fields are not assignable.
- **Bindings** that may read a reactive field (directly or through the functions they call) are re-evaluated in every flush pass after such a write; they write the DOM only where a value changed.

**Class hierarchies and class references** (M6, [design](design/M6-LIBRARIES.md#inheritance-and-class-unions)):

- **Records.** A subclass record names its base, `"extends": b`; its fields start with all of the base's fields, with the same names, types and markers (a derived field keeps its function), so a field has one index in a whole hierarchy. `"abstract": true` marks a class no `record` expression constructs. A class without subclasses keeps the plain `record` type, so programs without inheritance are unchanged.
- **Types.** `{"class": c}` is an instance of class `c` or of one of its subclasses, and requires `c` to have subclasses. `{"classes": [c…]}` is an instance of one of two or more classes (ascending, none a subclass of another) or of their subclasses. Both are class references: the value carries its class. Its *classes* are the class records it can be an instance of; its concrete classes are those that are not abstract.
- **Conversions.** `upcast {value, type}` widens a class instance (a record, or a class reference) to a class reference whose classes include all of its own; `downcast {value, type}` narrows a class reference to a record or class reference of some of its classes and throws a `TypeError` when the instance's class is not one of them. Both also convert a Maybe of one into a Maybe of the other, where nullish values pass. Frontends upcast wherever an instance meets a wider declared type and downcast where TypeScript narrowed one (`instanceof`, discriminants, `as`): a downcast fails only where the source's static types were unsound.
- **Dispatch.** `match-class {value, cases: [{record, local, body}], else?}` evaluates the class reference `value`, binds it to the `local` of the case for its exact class (typed as that record) and evaluates its `body`; otherwise `else`, which may be omitted when the cases cover every concrete class. All branches have one type, the result. Frontends call an overridden method through a match over the receiver's classes, each case calling the override its class resolves to; members all classes resolve alike are called directly.
- **Fields.** `get` and field `assign` accept a class reference when every one of its classes has the same field at that index.
- Methods of a class with subclasses take the class reference `{"class": c}` as their instance; so do derived field functions declared there, for every subclass's copy of the field.

Literal values (`lit`) are numbers, strings and booleans. String literals are Unicode text; a literal containing a lone surrogate is rejected by the frontend (`E_STRING`), although computed strings may contain one.

## Functions

```jsonc
{ "name": "total", "component": 0,            // optional: the component whose cells it may read and write
  "captures": [Local], "params": [Local], "locals": [Local],
  "result": "number", "body": [Stmt],
  "derived": true }                            // optional: a cached derived value of its component
Local = { "name": "sum", "type": "number", "boxed": false }
```

The local index space of a function is `captures`, then `params`, then `locals`. `boxed` marks a local that a closure captures and mutates, so it is shared by reference; unboxed captures are copied when the closure is created. Module-level functions have no `component`.

A `derived` function (Svelte `$derived`, Vue `computed`; no parameters) is cached per instance: it is recomputed when what it read changed, and a recomputation with the same result keeps its value, so dependents re-run only when its value changed. "Same" is SameValue (Vue `computed`), or `===` with `"derivedStrict": true` (Svelte `$derived`: `NaN` replaces `NaN`, `-0` keeps `0`).

## Components and instances

```jsonc
{
  "name": "Row",
  "cells":    [ { "name": "label", "type": "string", "init": Expr, "prop": "label", "tracking": "identity" } ],
  "handlers": [ { "event": "click", "params": [Local], "locals": [Local], "body": [Stmt] } ],
  "template": [ Node ],
  "templateLocals": [Local],                       // list items, slot params, template temporaries
  "slots": [ { "name": "row", "params": [T…] } ],  // slots the template renders
  "effects": [ { "run": 7, "phase": "post", "deps": { "kind": "tracked" },
                 "unmount": { "removal": "after", "order": "post" } } ]
}
```

- **Instances.** Every component can be instantiated many times; the root has one instance. An instance owns one value per cell, is created when its `component` node mounts (props, then cell initialisers) and destroyed with that node. Instance identity is the parent instance, the node, and the list keys and slot renderers on the path between them. Functions with `component: k` run in an instance of `k`.
- **Cells** are the instance's reactive state. `init` may only read cells declared earlier. A cell with `prop` receives that prop from the parent (`init` is its default): when the parent's value changes (SameValue) the cell is set and becomes dirty; a write by the child calls the parent's `bind` closure if there is one. With `undefinedDefault: true` (M6, Svelte's `$props()`), a passed `undefined` takes the default (`init`, evaluated in the child) at creation and whenever the passed value becomes `undefined`; such a prop of type `T` may be passed `maybe<T>`, and `null` passed to a non-nullable one throws `TypeError` (`RunicPropsError`).
- **Effects created at run time** (M6): `effect.pre(f)` / `effect.post(f)` called while an instance is created (its cell initialisers, and what they call) add a tracked effect to that instance after the component's own: `f` returns nothing or a cleanup. A pre effect runs at once (Svelte runs `$effect.pre` when it is created) and again before its instance updates when what it read changed; a post effect runs with the instance's post effects. Their cleanups run after DOM removal, pre effects parent first and post effects children first. Called while an effect of an instance runs (and no instance is being created), they add a child of that effect (bits-ui's `TimeoutFn` made in a `watch` callback): it runs in the same flush pass after the effects of its phase already there, and before its parent runs again or is destroyed, the children its last run created are destroyed, their cleanups running in creation order before the parent's. Called at any other time they throw `RunicEffectError`.
- **Contexts** (M6): `context.set(key, v)` while an instance is created stores `v` under the literal `key` (a compile-time identity: the frontend names each context, `Collapsible.Root#1`) and returns it; `context.get(key)` (type `maybe<T>`) finds the nearest value up the instance's parents, where a parent is the instance that renders it (for slot content: the instance rendering the slot, also through slot content forwarded by another component). Outside creation both throw `RunicContextError`; a value of another type under the key throws `TypeError`.
- **Imperative mounts** (M6, [design](design/M6-OVERLAYS.md)): a component lists `mounts`, each `{ "component": c, "slots": [SlotDef], "source"? }`: a component its functions mount and the content it provides for that component's slots (template content of the mounting component: its `params` are its template locals). `mount {site, target, props?, context?}` in a function of the component (not in templates) creates an instance of the site's component: its `props` (`{name, value}`, each typed as the prop cell, a nullable one where the prop takes its default when undefined) are evaluated once, its cells initialise and its pre effects run, its slots render the site's content in the calling instance (snippets keep their owner's scope: a `slot` node there renders the caller's own slot), and context lookups continue at the instance whose `context` value (`context.all`) is given, or nowhere without one. Its DOM is appended to `target`, which must be the body (`document.body`; another element is reported unsupported: its owner's updates would interleave with the mounted content), before an empty anchor text, so it is the body's last content at its mount. It is updated after the root in every flush pass (its pre effects as it updates) and its post effects run in the pass after its mount; it lives until `mounted.unmount(m)` (a promise fulfilled at once; nothing for an instance no longer mounted) destroys it at once: cleanups that run before DOM removal, the removal (with focus loss), then the others, each at its tree position, as at any destruction. Destroying the mounting instance does not unmount it (the mounting code does, as bits-ui's Portal does in its effect's cleanup). The interpreter renders mounted content with its next render, so the `blur` and `focusout` of a focused element that `mounted.unmount` removes run then, not nested in the call as natively (a known deviation of the reference model).
- **Tracking** decides when a write makes a cell dirty for bindings: `identity` (default) when the new value is not SameValue to the old one; `deep` also after any heap mutation since the last flush (Vue `ref`; what it holds is marked reactive); `proxied` (Svelte `$state`) stores proxies of plain objects and arrays (a new identity over the same storage) and is dirty after mutations through proxies; `none` never. `readonly` cells (React state and props) must not be mutated in place.
- **Handlers** run when an event reaches a listener. Their local index space is `params` (the listener's `args`), then `locals`. `event` is the event object; `payload` is a shorthand for the input value (`input`), the new checked state (`change`, boolean) or `event.key` (`keydown`). The listeners of one event share a task unless `schedule.checkpoint` is `listener`; document and window listeners each run as a callback of their own.
- **Flushes.** The first write after a flush queues a flush job (`schedule.flush`). A flush runs passes until effects stop writing: commit the state (render snapshots), update the tree (pre effects run as each instance updates or is created), run cleanups of destroyed instances, then layout and post effects children first. Closures created while a snapshot is current keep it (React reads). M6: listeners of the events in `schedule.continuous` queue the flush as a default-priority task, not in their checkpoint (React's continuous lane); default-priority tasks queued inside a frame (its rendering step's events, layout, ResizeObserver callbacks) run after the frame; and with `schedule.flush` `event-microtask` a write while a discrete event's listeners run moves a pending default-priority flush into the microtask queue (React's sync lane renders the pending updates with it).
- **Effects.** `run` is a function of the component returning nothing or a cleanup; with `values` dependencies it may take the new values and the previous ones. `phase` is `pre`, `layout` or `post`; `deps` is `tracked` (the cells, derived values and heap slots the last run read), `once`, `always` (after every update of the instance or an ancestor) or `values` (`{"values": [Expr], "initial": bool}`, compared with `Object.is`). `unmount` places the cleanup at destruction: before or after DOM removal, at the pre- or post-order position of the destroyed subtree. An effect with `render: true` (at most one per component; a tracked pre effect without a cleanup) stands for the instance's render (Vue's render effect: it reads what the template reads): each of its runs is a re-render.
- **Domains** (`{ "kind": "text", "maxUtf16": 256 }`) appear only in migrated schema 3 programs; they constrain a text cell on every write.

## Statements

| Statement | Meaning |
|---|---|
| `{ "op": "set", "cell": i, "value": e }` | Write cell `i`. Later `current` reads observe the write. |
| `{ "op": "let", "local": i, "value"?: e }` | Initialise a local |
| `{ "op": "assign", "target": Place, "value": e }` | Place is `{local}`, `{cell}`, `{object, field}` or `{array, index}` |
| `{ "op": "expr", "value": e }` | Evaluate for effects |
| `{ "op": "if", "test": e, "then": […], "else": […] }` | |
| `{ "op": "while", "test": e, "body": […], "update": […], "label"? }` | `for` loops put their update in `update`, which `continue` still runs |
| `{ "op": "for-of", "local": i, "iterable": e, "body": […], "label"? }` | Over arrays, sets and strings (by code point); maps through `keys()`/`values()` |
| `{ "op": "break" \| "continue", "label"? }` | |
| `{ "op": "return", "value"? }`, `{ "op": "throw", "value": e }` | |
| `{ "op": "try", "body": […], "catch"?: { "local"?, "body" }, "finally"?: […] }` | |

Frontends lower `switch` to `if` chains with explicit fall-through, compound assignments and `++`/`--` to `assign`, and destructuring to `let` sequences. Exceptions are values of any type; `RangeError`/`TypeError` thrown by built-ins are records with `name` and `message`.

## Expressions

Every expression has a statically known type, which the validator infers and checks.

| Expression | Type | Meaning |
|---|---|---|
| `lit {value}`, `undefined {type}`, `null {type}` | value / `type` | Literals; `undefined`/`null` carry their Maybe type |
| `cell {cell, read: "current" \| "snapshot"}` | cell type | `current`: latest value, including writes earlier in this handler. `snapshot`: the value the last render observed (React state). In templates and initialisers both mean the committed value. |
| `local {local}`, `payload` | local type / event payload | |
| `attrs {items, merge?}` | attrs | An attribute bag from items in order, each `{name, value}` (value: string, `maybe<string>`, boolean, `maybe<boolean>`, for `on<event>` names a function taking the event or nothing; M6: for `style` a record of string or `maybe<string>` fields (a style object) or, where keys may be absent (`...(c && { k: v })`), a `map<string, maybe<string>>` of the keys in insertion order, for other camelCase names a function of any type, a callback for a component that declares the prop; M6 overlays: for `on<event>capture` a capture listener of the element (run from the root down to the target before the target's and the bubbling listeners, also for events that do not bubble), for `style` also a `map<string, string>` or a nullable style map, for other names a value of another type (number, array, record, element, …, or nullable: `runic_ir::builtins::bag_value_type`), which a component declaring the prop receives and an element it is spread onto sets as a number's text (others are reported unsupported)), `{spread}` (a bag) or `{attach}` (M6: an attachment, a function of the element returning nothing or a cleanup, under a key of its own); a later entry of a name wins. `undefined` and `null` entries are kept apart (merging tells them apart). With `merge: true` (Vue's `mergeProps`), an entry, or each resolved entry of a spread, combines with an earlier one of its name in place: `class` keeps the earlier value when both are equal and otherwise joins the non-empty trimmed values with a space (absent counts as empty); other names take the later value |
| `event` | event | The event object of the running handler (handlers only; closures read it through a local) |
| `global {global}` | global type | A module constant |
| `not`, `neg`, `bit-not`, `to-string`, `to-number`, `to-boolean`, `typeof`, `utf16-length` `{arg}` | | `!`, unary `-`, `~`, `String(x)`, `Number(x)`, `Boolean(x)`, `typeof`, `.length` |
| `add`, `sub`, `mul`, `div`, `rem`, `pow`, `min`, `max`, `bit-and`, `bit-or`, `bit-xor`, `shl`, `shr`, `ushr` `{left, right}` | number | JavaScript number operators |
| `concat {left, right}` | string | `+` on strings |
| `eq`, `ne` | boolean | `===`/`!==` on equal types (identity for heap values; Maybe compares its states) |
| `lt`, `le`, `gt`, `ge` | boolean | Ordering of numbers (and strings by code units, via built-ins) |
| `and`, `or` | boolean | Short-circuit on booleans; other operand types are lowered with `with` and `cond` |
| `nullish {left, right}` | type of `right` | `??` |
| `cond {test, then, else}` | type of `then` | `?:` |
| `record {record, fields}`, `array {type, items}` | record / array | Construction; array items may be `{spread: e}` |
| `get {object, field}`, `index {array, index}` | field / element type | Field read; checked array read (out of range throws `RangeError`, see deviations) |
| `some {value}`, `unwrap {value}` | Maybe / inner | Wrap into Maybe; unwrap (throws `TypeError` when nullish) |
| `optional {value, local, then}` | Maybe | `?.`: undefined when `value` is nullish, otherwise `then` with the unwrapped value in `local` |
| `call {function, args}`, `call-value {callee, args}` | result type | Direct and indirect calls |
| `closure {function, captures, stable?}` | fn | A function value; `captures` are the caller's local indices. `stable`: one function object per instance (or program), for script-level functions of Svelte and Vue and module functions |
| `builtin {name, args, type}` | `type` | A catalogue built-in (below) |
| `with {local, value, body}` | type of `body` | Bind `value` to `local`, then evaluate `body` |
| `upcast {value, type}`, `downcast {value, type}` | `type` | A class instance as a wider class reference; a class reference as a narrower class type (`TypeError` when it is not; M6) |
| `match-class {value, cases, else?}` | type of the branches | A branch per exact class of a class reference, binding the instance to the case's `local` (M6) |
| `mapped {rule, guard, fast, reference}` | type of `reference` | Only in migrated schema 3 programs |
| `slot-provided {name}` | boolean | Whether the running instance was given content for its slot `name` (M6: a snippet prop tested for presence) |
| `mount {site, target, props?, context?}` | mounted | Mount an instance of mount site `site` of the running function's component (M6, see [components](#components-and-instances)) |

**Built-ins** are a catalogue in `runic-ir` (`builtins.rs`) with type rules, interpreter implementations in `runic-js` and Rust spellings in `runic-codegen`. The families are `Math.*` (except `random`), `Number`/number methods, string methods, array methods (including callbacks and in-place mutation), `Array.from`/`Array.isArray`, `Object.keys/values/entries/assign`, `JSON.stringify`/`JSON.parse` into a declared type, `Map`/`Set`, `structuredClone` and the global conversion functions. The full list is in [M2-VALUES](design/M2-VALUES.md); each family has Node-generated test vectors in `crates/runic-js/tests/vectors/`. M4 adds host operations: `timer.timeout/interval/frame/clear`, `clock.now/date`, `microtask.queue`, `storage.get/set/remove/clear` (localStorage), `promise.new/resolve/reject/then/catch/finally/all` with the internal `promise.pending/fulfil/adopt/fail` of async functions, and `flush.tick` (a microtask running any pending flush, then fulfilling) and `flush.after` (fulfilled when the pending flush ends). M5 adds the event object members `event.type/key/code/ctrlKey/shiftKey/altKey/metaKey/repeat/clientX/clientY/button/buttons/deltaX/deltaY/target/currentTarget/defaultPrevented/value/checked` (M6 overlays: also `event.pointerId`, 1 for pointer events and reported unsupported for others, `event.isComposing`, whether a key event's target is a text control composing with an IME, and `event.pointerType`: `mouse` for pointer, context menu and auxiliary click events and clicks with a `detail`, empty for other clicks; other events report it unsupported) (`value`/`checked`: the target control's state at dispatch; `currentTarget` is null after the dispatch) and `event.preventDefault/stopPropagation/stopImmediatePropagation`, and `window.listen/unlisten` and `document.listen/unlisten` (`addEventListener`/`removeEventListener`: a literal event kind and a listener taking the event or nothing, identified by its function value; adding a registered listener again does nothing). Dates (`date.*`) and locale-sensitive formatting and collation (`intl.*`) follow the regular expressions below, and the host services `console.*`, `clipboard.*`, `history.*`, `location.*` and `random.*` after them.

**Host services** (M5, [design](design/M5-PLATFORM.md#host-services)) follow the `localStorage` shape: built-ins in their own namespace, one `runic-runtime` module each (OS-backed in apps, in memory and seeded by the case in probes), modelled by the interpreter.

- `console.log/info/warn/error/debug(args…)`: one or more strings, numbers, booleans or nullable ones. The line is the arguments' ToString joined with spaces: Chromium's console message text (also Playwright's `msg.text()`; `-0` prints `0`). A first argument of string type followed by more arguments must be a string literal without `%` (Chromium keeps a format string in its message text and converts the arguments of `%d`/`%i`/`%f`/`%s`, while DevTools substitutes them). Apps write the line to stderr.
- `clipboard.write(text)` → `promise<void>`, `clipboard.read()` → `promise<string>` (`navigator.clipboard.writeText/readText`). The promise settles in a host task after the running task (Chromium's reply comes from the browser process: after `setTimeout(0)` and message tasks, in either order with animation frames). A clipboard holds text: lone surrogates become U+FFFD. An operation while another is pending throws `RunicHostError` (Chromium settles overlapping operations in an order depending on their kinds). Apps use the OS clipboard; a failure rejects with a `NotAllowedError`, and a clipboard without text reads as empty.
- `history.push(url?, state?)`, `history.replace(url?, state?)` (`pushState`/`replaceState`; M6: the state is a string or null, default null, and `history.state()` reads the current entry's; fragment navigations create entries with a null state): the URL resolves against the current one (WHATWG URL parsing, plus Chromium's escaping of `^` and `|` in paths; an empty URL keeps the current one, fragment included); no events. Absolute URLs, other origins and lone surrogates in the path throw `RunicHistoryError` (Chromium throws a SecurityError naming the origin). Pushing truncates later entries; at most 50 entries are kept.
- `history.back()`, `history.forward()`, `history.go(n)` (an integer; a literal must be non-zero, and a computed `0`, which reloads in Chromium, throws `RunicHistoryError`): a traversal in a host task after the running task. Out of range does nothing. It fires `popstate` at the window, then, when the URLs differ only in their fragments (absent and empty differ), `hashchange` as a task of its own. A traversal while another is pending throws `RunicHistoryError` (Chromium may drop the second). `history.length()` is the entry count.
- `location.pathname/search/hash()` (`search` and `hash` are empty for an empty query or fragment) and `location.set-hash(v)`: a fragment navigation unless the fragment already is `v` without one leading `#` (an absent fragment counts as empty). It pushes an entry, or replaces the current one while the document loads (the mount), then fires `popstate` at once, nested in the setter with no microtask checkpoint, and queues `hashchange`. A second fragment navigation while loading throws `RunicHistoryError` (Chromium delays the `hashchange` of loading-time navigations past the load event, in an order not modelled). `location.href` and other origin-dependent members are rejected by the frontend.
- `document.title()` and `document.set-title(t)` (M6, `document.title`: the stored title, ASCII whitespace stripped and collapsed on reading; the window title stays `meta.title`); `document.getElementById(id)` → `maybe<element>` (the first in tree order inside the program's DOM).
- `focus.current()` → `maybe<element>` (`document.activeElement`, none for the body); `focus.reset()` (M6, a router's focus reset: blurs the focused element and moves the sequential focus starting point to the document start); `focus.start(e)` (the starting point becomes `e`, as following a fragment to it does, without focusing it).
- `url.resolve(input, base)` → `maybe<string>` (M6, `new URL(input, base)` over origin-less URLs: `/path?query#fragment` with the parsing and escaping of `history.push`; none for absolute URLs of another origin); `url.query-pairs(q)` → `array<array<string>>` (the name–value pairs of `URLSearchParams`, application/x-www-form-urlencoded parsing). The globals `encodeURIComponent`, `decodeURIComponent` and `decodeURI` (`URIError` "URI malformed").
- `host.reply()` → `promise<void>` (M6): fulfilled in a host task after the running task, as an I/O round trip whose result is known (Kit's version check that finds no new version). `host.unsupported(description)`: the native runtime reports the behaviour as unsupported and throws `RunicUnsupportedError`; the interpreter stops with `E_UNSUPPORTED`.
- `random.number()` (`Math.random()`) and `random.uuid()` (`crypto.randomUUID()`): apps use OS randomness; probes and the interpreter use `runic_js::random` (SplitMix64 seeded by the case's `seed`, default 1; a number is the top 53 bits over 2^53, a UUID two outputs big-endian with the version 4 and variant bits), restarted with each app instance (`reload`).
- Templates and derived values must not use these built-ins, directly or through the functions they call (`E_REACTIVITY`): their values change without notifying the framework, and derived values are computed when read.

The session history outlives app instances: a probe `reload` starts a new document at the current entry; a traversal to an entry of an earlier document is outside the model (the probe stops, the interpreter rejects the step).

**Regular expressions** (M5) have exact ECMAScript semantics without a JS engine: `runic_js::regexp` implements RegExpBuiltinExec (`lastIndex`, global and sticky), `@@replace` with GetSubstitution (`$$`, `$&`, `` $` ``, `$'`, `$n`, `$nn`, `$<name>`), `@@split`, `@@match`, `@@matchAll` and `@@search` around the `regress` engine, matching UTF-16 code units (code points with `u`), so indices and `lastIndex` count code units. Vectors from Node cover them (`tests/vectors/regexp.json`, including every case-insensitive character pair). The built-ins:

- `regexp.new(source, flags)`: a literal or `new RegExp(source, flags)`. Flags are a literal (`dgimsuy`; `v` is rejected); a literal pattern is compiled at build time (`E_REGEXP`), a runtime one throws `SyntaxError` as in JavaScript.
- `regexp.source/flags/global/ignoreCase/multiline/dotAll/unicode/unicodeSets/sticky/hasIndices/lastIndex/toString` `(re)`, `regexp.set-lastIndex(re, n)`, `regexp.test(re, s)`, `regexp.exec(re, s)`.
- `string.regexp-replace/regexp-replaceAll(s, re, r)` with a string `r`, or a function `r` and the literal capture count `n`: `r` takes the match, the `n` captures, the position and the string (or a prefix of them; the groups object is unsupported); `replaceAll` throws `TypeError` without `g`.
- `string.regexp-match(s, re)`, `string.regexp-matchAll(s, re)` (all matches as an array: matching runs on a copy, so iterating eagerly is not observable), `string.regexp-search(s, re)`, `string.regexp-split(s, re, limit?)`.
- Match arrays are arrays of the captures (index 0: the match). Their extra properties are read through `match.index/input(m)` (`maybe<number>`/`maybe<string>`: undefined for other arrays, such as the result of a global `match`), `match.has-groups(m)` and `match.group(m, name)` (a literal name; undefined for a group that did not participate; `TypeError` when the pattern has no named groups, like `m.groups.name`).

Captures that do not participate are undefined. Results declare their elements: `maybe<string>`, or `string` where the frontend proved from a pattern known at build time (a literal, or a const holding one) that every capture participates in every match (not inside an alternative, a group quantified with minimum 0 or a negative lookaround); a capture that does not participate then throws `TypeError`, which proven patterns never do. `exec` and `match` return `maybe<array<…>>`, `matchAll` `array<array<…>>` and `split` `array<…>` in either form; replacement function parameters for captures are `string` or `maybe<string>` alike. The frontend reads `m[k]` that TypeScript types as `string` as `string` only where the pattern proves capture `k` present, keeps it nullable where undefined is handled (`??` with a fallback other than `undefined`, conditions, `!`, templates) and rejects it otherwise; `m.at(k)` reads any capture as `maybe<string>` (`array.at` of `maybe<T>` elements returns `maybe<T>`, one undefined).

Where `regress` deviates, `runic_js::regexp` corrects it, verified by the vectors: without `u`, an escaped surrogate pair is two characters; case-insensitive matching without `u` treats ı ſ ϴ ẞ Ω K Å and the Greek letters with iota subscript as matching only themselves (they are replaced, in the input and the pattern, by caseless stand-ins from a block of code units the input does not use); with `u` and `i`, `\W` in a class keeps ſ and K out; with a Unicode flag, a `lastIndex` inside a surrogate pair moves to the pair's start (V8); syntax errors carry V8's message for the error kinds the vectors cover (the message of rarer invalid runtime patterns may be worded differently).

**Dates** (M5) follow V8 (`runic_js::date`, a port of V8's date code and its `Date.parse`, pinned by Chromium vectors in `tests/vectors/date.json`). The built-ins:

- `date.new(tv)`: a Date holding TimeClip(`tv`). The frontend lowers `new Date()` to `date.new(clock.date)`, `new Date(s)` to `date.new(date.parse(s))`, `new Date(d)` to `date.new(date.getTime(d))`, `new Date(n)` to `date.new(n)`; `Date()` is the `toString` of the current time.
- `date.local(y, m, d, h, min, s, ms)` and `date.utc(…)`: the time value of components in local time (`new Date(y, m, …)`) or UTC (`Date.UTC`); the frontend supplies the defaults. `date.parse(s)`: `Date.parse`, ISO strings and V8's legacy formats (`Jan 2 2026`, `2026/01/02 10:00 PM`, `toString`/`toUTCString` output, …).
- `date.getFullYear/getMonth/getDate/getDay/getHours/getMinutes/getSeconds/getMilliseconds(d)`, their `getUTC…` forms, `date.getTimezoneOffset(d)` and `date.getTime(d)` (also `valueOf`).
- `date.setFullYear/setMonth/setDate/setHours/setMinutes/setSeconds/setMilliseconds(d, …)`, their `setUTC…` forms and `date.setTime(d, t)`: change the Date and return its new time value (V8's argument handling and local-time arithmetic).
- `date.toString/toDateString/toTimeString/toUTCString(d)` as V8 prints them (`toGMTString` is `toUTCString`), `date.toISOString(d)` (RangeError for an invalid date) and `date.toJSON(d)` (`maybe<string>`: null for an invalid date; the frontend accepts it only where null is handled).

Local time uses the environment's time zone: the manifest's `timezone` in probes and the interpreter (default UTC), the system zone in production (`TZ`, `/etc/localtime`; unknown zones fall back to UTC). Offsets come from the IANA database bundled with `jiff` (2026c, rearguard like ICU); a local time in a gap or fold takes the offset before the transition (ICU's `UCAL_TZ_LOCAL_FORMER`, V8's choice); instants beyond years ±9999 move by 400-year cycles. `toString` names the zone in the default locale with names read from Chromium (`runic_js::intl` data), standard or daylight saving time as V8 decides it (outside 1970–2038 in an equivalent year). 589 of the 598 bundled zones match Chromium at every sample instant; the others (Morocco and Western Sahara, America/Vancouver, America/Edmonton and their aliases, Europe/Chisinau) differ from Chromium's older time zone data in offsets or names. They are unverified: probes and the interpreter refuse them as a case's `timezone` and the validator as a `timeZone` literal, while production uses the bundled rules. `Date` values are not JSON-serialisable (`JSON.stringify` and `structuredClone` reject them), and `+` with a number is rejected (JavaScript concatenates).

**Intl** (M5): formatting and collation for the verified locales en-US, en-GB, de-DE, fr-FR and ja-JP (and en, de, fr, which format as en-US, de-DE and fr-FR):

- `intl.format-date(tv, options, locale?)`: `toLocaleString`, `toLocaleDateString`, `toLocaleTimeString` (of `date.getTime(d)`) and `Intl.DateTimeFormat#format` (of a Date, a number, or the clock).
- `intl.format-number(x, options, locale?)`: `Number.prototype.toLocaleString` and `Intl.NumberFormat#format`.
- `intl.compare(a, b, options, locale?)`: `localeCompare` with locales or options and `Intl.Collator#compare` (also as a comparator value: the frontend makes a function); `string.localeCompare(a, b)` collates for the default locale.
- M6: `intl.plural-select(n, options, locale?)` → `string` (`Intl.PluralRules#select`), `intl.plural-categories(options, locale?)` → `array<string>` (`resolvedOptions().pluralCategories`), `intl.display-of(code, options, locale?)` → `maybe<string>` (`Intl.DisplayNames#of`: undefined with `fallback: "none"` and no name), and `intl.locale(tag, kind)` → `string`: the constructor's check of a runtime locale (`kind` `"p"` plural rules: a malformed tag throws a `RangeError`; `"n"` display names: an unverified display locale is unsupported), evaluated where JavaScript constructs the object, before the method's arguments. Plural rules use Chromium's own ICU data for every locale it has them for; display names exist in en-US, en-GB, de-DE, fr-FR, ja-JP, en, de, fr and ja (`crates/runic-js/tests/vectors/intl-locales.mjs` → `src/intl/locale_data.rs`). Tags are a language with an optional script and region, canonicalized as V8 does; variants, extensions and regions aliasing several regions are unsupported at run time (`RunicUnsupportedError`, reported by the runtime; the interpreter stops with `E_UNSUPPORTED`).

`options` is a literal string `m=<method>;loc=<tag>;<option>=<value>…` (methods: dates `d`, `t`, `a`, `f`; numbers `n`, `f`; collation `l`, `c`; plural rules `p`, options `type`; display names `n`, options `type`, `fallback`, `languageDisplay`, `style` `long`); the validator parses it with `runic_js::intl` (`E_INTL`). A literal locale is part of it; a locale computed at runtime is the last argument and must name a verified locale when the program runs: a malformed tag throws Chromium's `RangeError` (`Invalid language tag: …`), and a well-formed tag without verified data is reported unsupported (`RunicUnsupportedError`; Chromium formats it with its own data or falls back to its default, neither of which is verified). Without either, the default locale is the manifest's `locale` (default en-US) in probes and the system's (`LC_ALL`, `LC_TIME`, `LANG`; unverified locales fall back to en-US) in production. Supported options:

- dates: `weekday`, `year`, `month`, `day`, `hour`, `minute`, `second`, `hour12`, or `dateStyle` with `timeStyle` `medium`/`short` (and `hour12`); `timeZone` (a verified IANA name). The defaults follow ECMA-402's ToDateTimeOptions for each method. Rejected: `timeStyle` `full`/`long`, `timeZoneName`, `era`, `hourCycle`, `fractionalSecondDigits`, `dayPeriod`, calendars and numbering systems.
- numbers: `style` `decimal`, `percent`, `currency` (USD, EUR, GBP, JPY, CHF, CNY, INR, CAD, AUD) with `currencyDisplay` `symbol`, `narrowSymbol`, `code`; `minimumIntegerDigits`, `minimum`/`maximumFractionDigits`, `minimum`/`maximumSignificantDigits` (ECMA-402 2023 resolution; out-of-range values are rejected), `useGrouping`. Rejected: other notations, `signDisplay`, units, rounding options.
- collation: `sensitivity`, `numeric`, `caseFirst`, `ignorePunctuation`, `usage: "sort"`.

**Library support** (M6, [design](design/M6-LIBRARIES.md#library-code-steps-3-to-6)): built-ins that libraries compiled from source (bits-ui) and their packs (svelte-toolbelt, runed) lower to.

- `attrs.has(bag, name)`, `attrs.get(bag, name)` (type `maybe<T>` for a string, boolean or function `T`, M6 overlays also for a value of another type (a number, an array, a record, an element; a style entry gives the object it was made from, or a new `map<string, maybe<string>>` of its properties): the resolved entry, `undefined` when absent; another kind of value throws `TypeError` `RunicAttrsError`; a function of another type is adapted when it takes a prefix of the parameters, its result discarded where none is expected), `attrs.without(bag, names…)`: rest props that reach a component's declared props.
- `attrs.merge-props(bags…)`: svelte-toolbelt 0.10.6's `mergeProps` (`runic_js::merge_props`): the first bag, then each later bag's string keys in order: functions under the event names of its `EVENT_LIST` compose (each runs with the event unless it was cancelled), `class` values join as clsx joins strings, `style` objects merge (later properties win) and print as `name: value;` joined by spaces, other values win unless `undefined`; attachment keys win unless `undefined`; `hidden` and `disabled` that are `false` are removed. Two other functions under one key (`executeCallbacks`) and a style string meeting another style value throw `RunicUnsupportedError`.
- `effect.pre(f)`, `effect.post(f)`, `context.set(key, v)`, `context.get(key)`: see [components](#components-and-instances). `effect.root(f)` (M6, Svelte's `$effect.root`) runs `f` (no parameters, returning nothing or a cleanup) at once and untracked in an effect root and gives the root's id (a number): effects `f` creates belong to the root, not to an instance (a pre one is reported unsupported: Svelte re-runs it or not depending on its siblings' cleanups); they run, tracked, after the instances' effects of each flush pass, until `effect.destroy-root(id)` runs their cleanups in creation order and then `f`'s. (Svelte runs a root created during an instance's creation among that instance's effects in creation order; the order differs only where both write state an order-dependent way.) `Map.new(m)` (M6) copies a map of the same type, its entries in order. `attrs.style-map(bag)` (M6 overlays: a bag used as a style object, bits-ui's arrow style built with a computed key) → `map<string, maybe<string>>`: text entries as they are, typed numbers as their text, absent and null ones undefined; another kind of value is reported unsupported. `reactive.untrack-call(f, args…)` calls `f` without tracking what it reads (Svelte's `untrack`). `uid.next(prefix)`: `prefix` and a program-wide counter from 1 (Svelte's `$props.id()`, `c1`, `c2`, … in creation order).
- `element.isConnected(e)`, `element.hasAttribute(e, name)`; M6: `element.getAttribute(e, name)` → `maybe<string>`, `element.localName(e)`, `element.textContent(e)` → `string` (the text of its descendant text nodes; M6 overlays), `element.parent(e)` → `maybe<element>` (none for the program's top-level elements: the container is not the program's); `element.style-get(e, name)` and `element.style-set(e, name, value)` (the inline style through the CSSOM: `style.transitionDuration` is `transition-duration`; an empty value removes the property, an invalid one changes nothing); `element.getAnimations(e)` → `array<animation>`: the element's running CSS animations and transitions (docs/CONTRACT.md, library DOM APIs), read through `animation.finished(a)` → `promise<animation>`, `animation.playState(a)` → `string` and `animation.pending(a)` → `boolean`. `element.listen/unlisten(e, "beforematch", f)` (svelte/events `on`): the runtime never fires `beforematch` (no find-in-page). `mutation.observe(o, e, attributes)` is reported unsupported; `mutation.disconnect(o)` of an observer that never observed does nothing. M6 overlays: `context.all()` → `contexts` (the contexts of the instance being created, Svelte's `getAllContexts()`; `RunicContextError` outside creation), `mounted.unmount(m)` → `promise<void>`, `document.body()` → `element` (not a host service: it never changes), `document.elementFromPoint(x, y)` → `maybe<element>` (the element the native hit test finds at a viewport point, a text's or anonymous box's element; none outside the viewport; a layout read), `document.querySelector(selector)` → `maybe<element>` (the program's elements matching a selector of the supported subset, first in document order; `html`, `head` and the container are not the program's: the interpreter throws `RunicUnsupportedError` for them). Also M6 overlays: `element.getClientRects(e)` (an array of `DOMRect` records: the border box, none without a box; an inline element's line boxes are reported unsupported), `document.clientWidth/clientHeight()` (the document element's client size: the viewport's without scrollbars), `window.devicePixelRatio()` (among the window metrics), `element.listen/unlisten(e, "scroll", f)` (a scroll listener added by script, identified by its function value, released with its element), `visual-viewport.listen/unlisten(kind, f)` (`resize` or `scroll`: the visual viewport resizes with the window, its `resize` listeners called after the window's in the same rendering step; it never scrolls without pinch zoom), `window.listen-capture/unlisten-capture` and `document.listen-capture/unlisten-capture(kind, f)` (capture listeners, called before the event's path: the window's, then the document's), `element.listen/unlisten(e, kind, f)` for every element event, `event.new(type, cancelable, bubbles?)` (an event created by script: members other than `type`, `defaultPrevented`, `preventDefault` and the propagation calls report it unsupported; dispatched by `element.dispatchEvent(e, event)` → `boolean` where its type is not a native one: the listeners `custom.listen/unlisten(e, type, f)` added for that type at the target and, where it bubbles, its ancestors, run at once; a native type is reported unsupported), `element.click(e)` (a click nested in the script, as `focus` runs its events; activation behaviour reported unsupported), `element.select(e)` (all text of a text control; nothing the interpreter observes), `element.contains(a, b)`, `focus.tabbables/focusables(container, includeContainer)` → `array<element>` and `focus.is-tabbable/is-focusable(e)` (tabbable 6.5.0, native layout), `mutation.new(callback)` (a MutationObserver record, `"name": "MutationObserver"`, one field `callback` of type `fn() -> void`, registered in creation order) and `mutation.observe-children(o, target, subtree)` (child-list observations: after a DOM update changes an observed child list, one microtask calls each such observer in creation order; the interpreter throws `RunicLayoutError`), M6 overlays (bits-ui's dismissible layer): `map.entries(m)` → `array<record>` (tuple records of the key and the value, `"tuple": true`, in insertion order), `map.dictionary-keys(m)` and `map.dictionary-values(m)` of a `map<string, V>` standing for a dictionary object (own-key order: array index keys ascending, then the others in insertion order), `event.keyboard(type, e)` (a keyboard event copied from `e`: key, code, modifiers, repeat and cancelability; never dispatched), `event.instance-of(e, interface)` (whether the interface Chromium creates for the event's type, or `CustomEvent`/`KeyboardEvent` for events created by script, is `interface` or derives from it; `RunicUnsupportedError` for a type the runtime does not know), `element.closest(e, selector)` (the nearest inclusive ancestor matching a selector of the subset; the interpreter throws `RunicUnsupportedError` where only the container or the html element would match). `element.isElement(e)` and `element.isDocument(e)` (an element value may be the document or the window as an event target; `element.isHTML` is false for them) and `element.focus-visible(e)` (`matches(":focus-visible")`: the focused element by Blink's modality rule; native only, like the layout built-ins). A `to-string` of a tuple record (or an array or nullable value of one) is rejected (`E_IR`). And `attrs.style-text(style)` (svelte-toolbelt's `styleToString`: `name: value;` per property, camelCase names in kebab case, undefined values printed as such, joined by newlines of which the first is a space). The interpreter has no style engine: the `style-*`, `getAnimations`, `animation.*` and `mutation.observe` built-ins throw `RunicLayoutError` there (as in a promise reaction: such errors are also reported uncaught).

Formats reproduce Chromium from locale data generated from it (`crates/runic-js/tests/vectors/intl.mjs` → `src/intl/data.rs`): every supported component combination's pattern, checked against Chromium at ~50 instants, number symbols and affixes, zone names. Numbers use ICU's model (shortest round-trip digits, half-expand rounding). Collation is ICU4X (`icu_collator` 2.3.1, compiled CLDR data). All of it is pinned by Chromium vectors (`tests/vectors/intl.json`). Intl objects are not IR values: `new Intl.DateTimeFormat(…)` with literal arguments, directly or through a `const`, is folded into its uses; `Intl.PluralRules` and `Intl.DisplayNames` constructed at their use may also take a runtime locale and options chosen by a condition (a `cond` over the option strings); other uses, other Intl constructors, `formatToParts` and other `resolvedOptions` members are rejected. `toLocaleUpperCase`/`toLocaleLowerCase` without a locale or with a verified literal one are `toUpperCase`/`toLowerCase` (no verified locale has special case mappings).

```jsonc
| { "kind": "html", "value": Expr, "fragments": [ 0, 3 ] }  // M6: {@html}
FragmentNode = { "tag": "span", "attrs": [ ["style", "…"] ], "children": [ FragmentNode ] } | { "text": "…" }
```

- **Tags** come from an allow-list in `validate.rs` (`TAGS`), which includes the inline SVG elements below (M6: also `dl`, `dt`, `dd`, `figure`, `figcaption`). Attribute names are lowercase letters, digits, `-` and (M6) `_`, starting with a letter or `_`, never `on…`.
- **HTML fragments** (M6, Svelte's `{@html}`): an `html` node shows the nodes of the program fragment among its `fragments` whose `html` is the value (`string` or `maybe<string>`; nullish and the empty string show nothing), inserted where the node stands and replaced by new nodes when the value changes (equal values keep them). HTML is never parsed natively: the frontend parsed every string that may be shown into `Program.fragments` (distinct, non-empty strings), and a value that is none of the node's fragments' strings throws `RunicUnsupportedError` (the runtime reports it; the interpreter stops with `E_UNSUPPORTED`). Fragment nodes are elements of `FRAGMENT_TAGS` (`TAGS` without links, controls and SVG) with literal attributes, and text; the validator caps all fragments together at 2^18 nodes, apart from the template limit. Fragment elements keep their identity while the value stays. Fragments are an additive extension of schema 4: programs without them are unchanged, and a program with them needs this version of the toolchain (older ones reject the unknown `html` kind and `fragments` field).
- **Inline SVG** (M5): `svg`, `g`, `path`, `circle`, `ellipse`, `line`, `polyline`, `polygon` and `rect` (`SVG_TAGS`) are created in the SVG namespace. Blitz renders an `<svg>` as a replaced element: it serialises the subtree's attributes, with `currentColor` replaced by each element's computed CSS `color`, and draws them with usvg into the content box (`object-fit: contain`), clipped by the UA rule `svg { overflow: hidden }` that Chromium also has. So the validator accepts only what both engines read the same way (`E_SVG`):
  - Placement: an `<svg>` is not inside another; the other SVG elements are children of `<svg>` or `<g>`; shapes have no children; an `<svg>` holds no HTML elements, components or slot outlets, and text only if it is literal HTML whitespace. `if` and `each` nodes may stand anywhere among them.
  - An `<svg>` needs a string `viewBox`. Its attributes are `xmlns` (only the literal `http://www.w3.org/2000/svg`), `width`, `height` (CSS sizes in both engines; author CSS may override them), `viewBox`, `class`, `id`, `role` (M6), the paint attributes and `aria-*`/`data-*`. Attributes that Chromium applies to the outer box but Blitz only to the drawing (`opacity`, `transform`, `display`, `style`, `color`, …) are rejected.
  - Paint attributes on every SVG element: `fill`, `fill-opacity`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-opacity`. Besides them and `class`, `aria-*`, `data-*`: `g` takes `opacity`, `transform`; each shape also its geometry (`path` `d`; `circle` `cx`, `cy`, `r`; `ellipse` `cx`, `cy`, `rx`, `ry`; `line` `x1`, `y1`, `x2`, `y2`; `polyline`/`polygon` `points`; `rect` `x`, `y`, `width`, `height`, `rx`, `ry`). No `id` (SVG children have no layout boxes in Blitz), `style` or `color` (`currentColor` is resolved from CSS `color` before usvg sees the attribute).
  - Values are strings or nullable strings (absent when nullish), static or bound; boolean values are rejected.
  - No listeners, spreads (they may carry listeners), refs or managed inline styles: Blitz hit-tests an inline `<svg>` as one box, where Chromium targets the painted shape. Class toggles are allowed.
  - Attribute changes, children added or removed and style changes inside an `<svg>` make Blitz serialise and parse it again.
- **Links** (M6): an `a` with an `href` is focusable (by the mouse, Tab and script) and is activated by a click on it or inside it, or by Enter while focused (a simulated `click`); unless the `click` was cancelled, its activation follows the link as a fragment navigation of this document, as the HTML standard's "navigate" does: a new session history entry (the current one replaced when the URL is the current URL), `popstate` at the window at once, then `hashchange` as a task when the fragment changed. Frontends accept only `href` values from a finite set of fragments (`#name`) that name no element and are not the document top (`#`, `#top`), except in SvelteKit apps, whose router owns links. M6: a followed link whose fragment names an element (by `id`) scrolls it into view (block start, inline nearest) after `popstate`, focuses it if focusable and otherwise clears focus and makes it the sequential focus navigation starting point (Chromium's `ElementFragmentAnchor`), then queues `hashchange`; the interpreter, without layout, reports it (`E_LAYOUT`); the document top and named anchors (`<a name>`) are reported unsupported. An `a` without `href` is an ordinary element.
- **Ids** may be dynamic; probes and conformance address the first element with an id in tree order, like `getElementById`.
- **Listeners:** at most one per element and event kind; `args` are evaluated at dispatch in the template scope. Events are `click`, `dblclick`, `contextmenu`, `input` (text inputs), `change` (checkboxes), `keydown` and `keyup` (from the focused element, before default actions), `pointerdown/up/move`, `mousedown/up/move`, `wheel` (all bubbling) and `pointerenter/leave`, `mouseenter/leave` (not bubbling). `popstate` and `hashchange` (M5) are fired at the window only: `window.listen` takes them, element and document listeners do not. Listeners run target first, then on the ancestors, then on the document and the window; `stopPropagation` ends the walk after the current element and `stopImmediatePropagation` at once. A cancelled event (`preventDefault`) skips its default actions: the checkbox toggle (reverted), button activation, text insertion, focus moving on mousedown, scrolling. Event sequences follow Chromium (docs/design/M5-PLATFORM.md). Activation, focus, Tab order and the disabled/readonly checks belong to the runtime's DOM semantics.
- **Selects:** `select` with `option` children; its `value` is the shown option's (a value no option has shows none: `""`; uncontrolled, the chosen option while it exists, else the first enabled one; option values default to their collapsed text). Picking an option dispatches `input` then `change`. A focused closed select changes with arrows, Home, End and typeahead (Linux Chromium); a press opens its popup, which takes the key downs, moves a highlight shown in the control, and commits on Enter (then a `click`), Escape or any press.
- **Radio buttons:** `input type="radio"` takes `checked` and `change` as a checkbox does. Its group is the radios with the same `name` in the same form owner (none: the document). Checking one unchecks the others without events; a click on an unchecked radio dispatches `click`, `input` and `change` to it only, a click on a checked one only `click`, and a cancelled click restores the group. Arrow keys move to the next or previous enabled radio of the group (wrapping), check it and dispatch `click`, `input`, `change`; Tab enters a group once, at its checked radio or else the first (last with Shift) one. A radio button checked by script (`checked` set true) unchecks the others of its group (the radios with its name in the same tree, also a detached one being built), without events; a checked radio button that becomes connected does the same, one by one in tree order, so the last checked one stays checked.
- **Live properties:** `value` and `checked` are controlled. With `schedule.controlledRestore` (React) they are restored after every dispatch that ran listeners, also when it wrote no state, and at every update (not between a picked option's `input` and `change`); otherwise a value is applied when it differs from the one last applied, and what the user typed or toggled stays until then (Svelte; Vue checkboxes). An element with `restore: "render"` also applies its `value` at every re-render of its instance (each run of the component's `render` effect), where the live value differs (Vue patching `value` of text inputs, text areas and selects). Equal values are left untouched, preserving selection and composition. Checkboxes and radio buttons require `checked`. A select controlled with `selectValue` instead of `value` shows the first option with that value, else the first enabled option, else keeps its selection (React DOM's `updateOptions`). A text area may also have `defaultValue` (with `value`): its text content (children), set when it changes and applied before `value`, which starts from it (React DOM keeps it equal to the controlled value). A text input or text area may have `adopt` (`{ when, handler, args? }`, Svelte's `bind_value`): when it mounts, after its attributes and spread and before its live properties, if `when` (boolean, template scope) holds and the control's value is not empty, the `input` handler runs once for an input event carrying that value.
- **Lists:** blocks are matched by `key` (SameValueZero; duplicates throw `RunicKeyError`) or by index. Reused blocks keep their nodes, instances and state; `reorder` names the framework's keyed diff, which decides which blocks move (a moved focused element is blurred, as in Chromium).
- **Slots:** a component node's slot definitions run in the parent instance with `params` bound to the child's slot arguments; a child without content for a slot renders its `fallback`. A definition with `when` (M6, a boolean, `slot-provided` of the parent's own slot: snippets forwarded through rest props) provides content only when it holds as the child is created.
- **Spread:** an element's `spread` (an attribute bag) applies after its `attrs`, whose names it never holds (the frontend guarantees this from every call site). Its attributes are set or removed, and its `on<event>` entries are listeners of the element, re-registered when the bag changes. A component's rest props are a prop cell of type `attrs` with `prop: "..."`; the call site passes the bag as the prop `...`. M6: a `style` string is set through `cssText` when it changed (a bag no longer holding it removes the attribute); a style object, and `hidden="until-found"`, are unsupported; callbacks are not attributes. With `spreadBooleanText` (Svelte's `set_attributes`), a boolean for a name without a boolean element property (`disabled`, `readonly`, `hidden`, `required`, `checked`, `autofocus`, `multiple`, `open`) is the text `"true"`/`"false"`; otherwise `true` is an empty attribute and `false` none. Attachments run, untracked, with the post effects of the instance that renders the element (before them), when the element mounts or the bag gains one (another key or function); their cleanups run after the render that removes the element or the attachment.
- **Class toggles** (`classes`): when the `class` value changes, the attribute is the value with names switched on appended and names switched off removed where they stand as words (Svelte's `to_class`); otherwise each changed toggle applies `classList.toggle`.
- **Managed inline style** (`styleText`, `styles`): when the style value changes, the value's declarations not given as properties, then the properties, are set through `cssText` (Svelte's `to_style`); otherwise changed properties are set or removed (`setProperty`/`removeProperty`). With `styleUpdate: "replace"` (Vue's `patchStyle`) an element has either a style text, set through `cssText` when it changes (an empty text is an empty attribute; becoming nullish after a non-empty text removes the attribute), or properties, which are all set again in order at mount and whenever one changes, after removing the nullish ones (from the first update on): a nullish or empty value removes the property, a value ending in `!important` (JavaScript's `/\s*!important$/`) sets it important, an invalid value changes nothing; property names are CSS or custom properties. Without `styleText` (and without `styleUpdate`) there is no style value (React DOM's `setValueForStyles`): each property is set through the CSSOM's `setProperty` when its value changed, initially when defined, so a property set again is appended; an absent or empty value removes it. Serialisation is the CSSOM's (`runic-css`, Stylo).
- **Refs** hold the element while it is mounted and `null` after removal. `element.focus`/`element.blur` move focus at once: the `blur`, `focusout`, `focus` and `focusin` listeners run nested in the call, with no microtask checkpoint.
- **Layout reads and scrolling** (CSSOM View) read the native layout after resolving it:
  - `element.getBoundingClientRect` returns a record of `x, y, width, height, top, right, bottom, left` (numbers, in that order) in layout units of 1/64 px.
  - `element.<metric>` for `offsetWidth/Height/Left/Top`, `clientWidth/Height/Left/Top`, `scrollWidth/Height`, `scrollTop/Left`: integers pixel-snapped as Blink snaps them (offsets relative to the `offsetParent`, ignoring scrolling).
  - `element.set-scrollTop/set-scrollLeft`, `element.scrollTo/scrollBy(left, top)` (each `maybe<number>`; absent keeps that axis or does not move it) and `element.scrollIntoView(block, inline)` (literal `start`, `center`, `end` or `nearest`) scroll at once, to whole pixels, clamped. `scrollIntoView` aligns the element in every scroll container from the element outwards, then in the viewport.
  - `window.innerWidth/innerHeight/scrollX/scrollY` and `window.scrollTo/scrollBy` do the same for the viewport.
  - Smooth scrolling is rejected.
  - The reference interpreter has no layout: these built-ins throw `RunicLayoutError` there, and the differential harness reports programs using them as incomplete. They are checked against Chromium only.
- **Focus:** controls and elements with `tabindex` are focusable. Mousedown focuses the pressed one (or nothing); Tab follows the sequential order (positive `tabindex` first, then tree order) and leaves the document past the end. Every move dispatches `blur` and `focusout` on the old element, then `focus` and `focusin` on the new one, naming each other as `relatedTarget`. When an update removes the focused element (or an ancestor), or a keyed diff moves its block, Chromium dispatches `blur` and `focusout` (no related target) at once, while the element is still in the document: their listeners run nested in the update, before the block is disposed. With `restoreFocus` (React DOM), an element blurred by a move is focused again after the DOM update, with `focus` and `focusin` run nested. With `schedule.commitEventsIgnored` these focus events reach only window and document listeners. A cancelled or removed target has no default action. A focused control that becomes disabled keeps focus until the focus fixup, which blurs it with `blur` and `focusout` as events of their own: natively a task after the frame that found it disabled, after the default-priority tasks queued before it (M6; Chromium's style update starts a 0 ms timer, which runs after animation frames; against a React render queued by the frame's scroll events its order is not stable); the runtime also blurs a focused element that lost its box (hidden by CSS), which the interpreter, having no style, does not model.
- **Scroll events:** a scroller whose offset changed (by script or by the user) has a pending `scroll` event. The rendering step after the task dispatches them in order, once per scroller however often it moved. An element's `scroll` event does not bubble. The viewport's event targets the document and reaches the document's listeners, then the window's. A layout (a frame's, or one forced by a layout read) clamps a scroll offset that a content change left past the end of its range, so reads see the clamped offset at once; the frame after the change queues that scroller's `scroll` event once its layout is done, and the rendering step of the frame after dispatches it (Chromium 153). Probes run two frames (rendering step, then layout) after every action, as the browser harness waits for two animation frames; windowed apps run the rendering step and the layout before painting. A probe's pointer action requires a target fully visible in its scroll containers and the viewport: Playwright would scroll it into view first (`DOM.scrollIntoViewIfNeeded`, Chromium's center-if-needed alignment), which probes do not model. Like layout reads, programs with `scroll` listeners are checked against Chromium only.
- **ResizeObservers** (M6): `resize.new(callback)` creates an observer record (`"class": true`, one field `callback` of type `fn([array<Entry>, record], void)`, the record itself as the second parameter; an `Entry` record is `target` (element), `contentRect` (a record of `x, y, width, height, top, right, bottom, left`), `borderBoxSize`, `contentBoxSize` and `devicePixelContentBoxSize` (arrays of records of `inlineSize` and `blockSize`), in this order). `resize.observe(o, e, box)` (a literal `content-box`, `border-box` or `device-pixel-content-box`) observes `e` (again: the observation is replaced), `resize.unobserve(o, e)` and `resize.disconnect(o)` stop. After each frame's layout (before paint; probes after the two frames of each step and of the mount) the native runtime delivers every observation whose size differs from the one last reported (none at first, so every new observation is reported, at 0×0 too): observations deeper in the tree than the previous round's shallowest target, observers in creation order, each observer's callback a task (with its microtask checkpoint) receiving its entries and itself, then a layout, until nothing is due; what remains is the loop error Chromium reports (written to stderr). Sizes are in layout units (1/64 px); the device-pixel size is snapped at the box's position; an element without boxes reports zeros. The interpreter has no layout: `resize.observe` throws `RunicLayoutError` there, and the differential reports such programs incomplete.
- **IntersectionObservers** (M6 overlays): `intersection.new(callback, rootMargin, thresholds)` creates an observer record (`"class": true`, one field `callback` of type `fn([array<Entry>, record], void)`; an `Entry` record is `boundingClientRect` and `intersectionRect` (`DOMRect` records), `intersectionRatio`, `isIntersecting`, `rootBounds` (a nullable `DOMRect` record), `target` and `time`, in this order). Its root is the document's viewport; `rootMargin` is one to four pixel or percentage lengths (a `SyntaxError` otherwise) and the thresholds lie in 0..=1 (a `RangeError` otherwise), sorted, `[0]` when none. `intersection.observe(o, e)` (again: nothing), `intersection.unobserve(o, e)` and `intersection.disconnect(o)` (which also drops the entries queued for it). After each frame's layout, after the ResizeObserver deliveries, the native runtime updates every observation, observers in creation order and their targets in observation order: the target's bounding box clipped by the ancestors of its containing block chain that clip overflow (their padding boxes) and by the root rectangle (the viewport grown by the margins), edge-inclusive; the ratio is the intersection's area over the target's (1 or 0 for an empty target, by whether it intersects); an entry is queued where the index of the first threshold above the ratio, or whether it intersects, changed (every new observation is reported). One host task, after the frame, calls each observer with queued entries, in creation order, each callback with its microtask checkpoint. Targets under a transformed ancestor or a `clip-path` are reported unsupported. The interpreter has no layout: `intersection.observe` throws `RunicLayoutError` there.
- **floating-ui** (M6 overlays, `@floating-ui/dom` 1.7.4 over `@floating-ui/core` 1.7.3): `floating.compute(reference, floating, middleware, placement, strategy)` → `promise<position>` is `computePosition`, run by `runic_js::floating` over the native layout's platform (`runic_runtime::floating`, Chromium's offset parents, clipping ancestors and rounding); each `await` of the package is a microtask. The middleware, their options, the middleware data and the results are records of fixed shapes (`runic_ir::floating`: a middleware is `name, kind, options, fn`, `kind` 0 for a custom middleware whose `fn` takes the state record and returns `x, y, data`, 1 to 6 for offset, shift, flip, size, arrow and hide; options are one record of all their fields, undefined where absent; `middlewareData` holds the six built-in entries, then one per custom middleware name). `floating.overflow-ancestors(e)` → `array<element>` is `getOverflowAncestors`' elements (the window and visual viewport that end its list are not elements). The interpreter has no layout: both throw `RunicLayoutError` there.
- **Media query lists** (type `media-query`, compared by identity): `media.query(q)` (`matchMedia(q)`, a literal query of the supported features) creates one. `media-query.matches` evaluates the query when read. `media-query.listen/unlisten(list, f)` add or remove a `change` listener, identified by its function value; adding it again does nothing. When the viewport or the user preferences change, the rendering step does three things in order: it dispatches the window's `resize` event (when the size changed); it runs the scroll steps; it fires `change` at each list whose state differs from when it was created or last notified, oldest list first, each listener a callback of its own. The event has `type` `change` and `event.matches`. `resize` listeners belong to the window. Probes change the environment with the actions `resize` (`width`, `height`) and `emulate` (`colorScheme`, `reducedMotion`, `contrast`); the browser harness uses Playwright's `setViewportSize` and `emulateMedia`.

## Validation limits

The validator caps a program at 4,096 template nodes, 1,024 cells per component, 1,024 handlers, 4,096 functions, expression and statement depth 96, 2^20 expressions and 4 MiB of CSS. Each limit has a diagnostic. These are resource limits, not semantic assumptions. Two semantic checks reject what the backend cannot reproduce: in-place mutation of `readonly` cells (`E_READONLY`), and template reads of values that change without making anything dirty (`E_REACTIVITY`: written `none` cells, identity-tracked references mutated in place, maps and sets mutated inside proxied state, mutated globals, RegExps whose `lastIndex` changes: exec, test, replace or match with a global or sticky RegExp, or setting `lastIndex`, unless the cell or global always holds a literal without `g` and `y`; Dates changed in place by a setter; host services, M5; `raw` class fields mutated in place and plain fields of class instances written after construction where templates read those fields, directly or through the functions they call or create, or hand the instance to a built-in, M6), which the frameworks would show only when neighbouring state re-renders; derived values must not use host services either. Writing reactive class fields (or the deep state they hold) from a template expression or a derived value, directly or through called functions, is `E_REACTIVITY` unless the code built the instance itself (Svelte throws `state_unsafe_mutation`), and derived class fields must not change values they did not create. Diagnostics carry the source location of the statement, cell, handler or element they concern, falling back to the enclosing function or element.

## Snapshots

The interpreter's and probe's state snapshots contain the DOM, the root instance's `cells`, and `instances`: every other live instance in tree order as `{ "component": name, "cells": [...] }` (imperatively mounted instances after the root's, in mount order). Content in the body after the container (imperative mounts, M6) appears as `portals`, a list of nodes, omitted when empty; the browser harness reports the same (leaving out the page's scripts and whitespace), and the runtime's own select popup is not part of it. Whitespace-only text directly in the body is left out on both sides (the browser cannot tell the page's from a portal's: Svelte keeps a space between a block and a component in a portalled snippet). Derived class fields appear as `null` (their caches are not state). Element handles appear as `"element"`, event objects as `"event"`, RegExps as their `toString()`, Dates as their ISO string (or `"Invalid Date"`).

Effects outside the DOM appear under `host` (M5), as in the browser harness's snapshots, each field omitted at its default and `host` omitted when all are: `console` (the lines since the previous step, `{ "level": "log" | "info" | "warn" | "error" | "debug", "text": … }`), `clipboard` (default `""`), `href` (the location without the origin, default `"/"`), `historyLength` (default 1) and `title` (M6, `document.title`, default empty). Texts holding a lone surrogate appear as `{ "units": [UTF-16 code units] }`. The probe and interpreter take the case environment as `--url` (start location, default `/`), `--clipboard` (default empty) and `--seed` (default 1), besides `--storage`; `back` and `forward` actions traverse the session history as the user does.

## Correctness

`runic_ir::interp` executes a program against an abstract DOM. `conformance/differential.mjs` runs generated code and the interpreter on seeded random event traces and compares DOM and cells after every step. The conformance harness tests both against the original frameworks in Chromium.
