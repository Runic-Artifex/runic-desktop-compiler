# Compatibility contract v9

The input that is implemented and verified as of milestone M5. This is a living document: milestones update it in place, and git history and the `m<N>` tags record earlier versions (v8 is at tag `m4`, v7 at `m3`, v6 at `m2`, v5 at `m1`; v1–v4 are in `history/`). Roadmap items are not part of the contract until a milestone verifies them.

The TypeScript frontends (`frontend/`) lower every framework through one shared language layer to [IR schema 4](IR.md). Ordinary JavaScript/TypeScript code follows the JavaScript value model. M3 added component instances, props, lists, slots, element refs, checkboxes and `keydown` ([design](design/M3-COMPONENTS.md)); M4 added the event loop, effects, timers, promises and `async`/`await`, and `localStorage` ([design](design/M4-EFFECTS.md)); M5 added the DOM event model, forms, layout reads and scrolling, media queries, host services ([design](design/M5-PLATFORM.md)) and inline SVG icons. Native applications execute no JavaScript engine.

## Collection

`runic.json` selects a local entry, title, optional `framework` (`react`, the default, `vue` or `svelte`) and optional `renderer` (`cpu`, the default, or `gpu`). Optional `alias` maps import prefixes to directories inside the app, resolved as Vite's `resolve.alias` (`"alias": { "$lib": "src/lib" }`, as SvelteKit configures `$lib`; the app's own Vite and SvelteKit configs are never run). All apps use an empty `div#root` and one module script. Vite collects original sources, ordered local CSS and WOFF2 assets; inline HTML scripts are rejected. Imports of types only (`import type`, lists of `type` names) load nothing.

Checked identities are React/React DOM 19.3.0, Vue/compiler-sfc 3.5.43 or 3.5.24, and Svelte/compiler 5.57.1 or 5.49.2. Runtime and compiler versions must match; other versions fail with `E_FRONTEND_VERSION`. Vite 8.3.2, TypeScript 5.9.3, plugin-vue 6.0.9 and the Svelte Vite plugin 7.3.1 are pinned tools.

CSS may use any selectors and properties that Blitz's style engine supports; Blitz/Stylo renders them and conformance checks the result. At-rules other than `@font-face`, `@media`, `@layer`, `@property`, `@supports` and `@keyframes` are rejected (`@starting-style`, `@container`, …). Transitions and keyframe animations (`transition*`, `animation*`, M6, [design](design/M6-LIBRARIES.md#animations), case `animations`) run on Stylo's engine at the runtime's timeline; rejected (`E_CSS_PROPERTY`): `text-transform` other than `none`, `uppercase` and `lowercase` (Blitz transforms case only); `animation-fill-mode` `forwards` and `both` (Stylo drops a finished animation's fill when its element is next restyled), also where a `var()` can reach them through a value the stylesheet gives the custom property, `transition-behavior: allow-discrete`, and scroll-driven animations. Animation and transition events and `element.getAnimations()` are rejected (`E_EVENT`, `E_CALL`). The compiler parses every stylesheet with Stylo and Blitz's preferences: a rule or declaration Stylo drops is rejected with its location (`E_CSS`, `E_CSS_PROPERTY`), except drops verified equivalent in Chromium (vendor pseudo-classes and pseudo-elements, `forced-colors`/`prefers-contrast`/`prefers-reduced-motion` media features, desktop-irrelevant vendor properties, and `resize`, whose grip Blitz never draws). `filter` and `backdrop-filter` (M6, [research](research/M6-CPU-RENDERER.md), cases `filters`, `backdrop-filters`) take lists of the CSS filter functions (`blur`, `brightness`, `contrast`, `drop-shadow`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia`), drawn by both renderers (the forked CPU and GPU renderers, with the same semantics) and animatable; rejected (`E_CSS_PROPERTY`, also through `var()`): `url()` filter references and a `drop-shadow()` that may take `currentColor` (Blitz draws it black). A filtered element with an outline, an outer box shadow or content overflowing its border box, and a backdrop-filtered element with rounded corners, an ancestor that is a Backdrop Root (opacity, filter, clip-path, mask, mix-blend-mode) or also a `filter`, stop a probe with `E_FILTER` (an app reports it once): Blitz draws them differently ([gaps](BLITZ-GAPS.md)). Gradients are drawn as in Chromium (cases `gradients` and `blitz-gradients`: angle gradients on the background tile, colour stop fix-up, both fixed in the Blitz fork). Rejected as well are the SVG-only properties (`fill*`, `stroke*`, `marker*`, `paint-order`, `d`, `cx`, `r`, `x`, … `E_CSS_PROPERTY`): Blitz renders inline SVG from its attributes and would ignore them. `:target` selectors are rejected (`E_CSS`): Blitz never matches them. With `"tailwind": true` in runic.json, Tailwind CSS 4.3.3's Vite plugin generates the stylesheet, and its output is what these checks apply to. Resources must be bounded local WOFF2 files (`format("woff2")` or `format("woff2-variations")`); native builds require one embedded font.

## Language

Every adapter lowers ordinary code through the shared layer. TypeScript's checker supplies types; in untyped JavaScript the frontend infers IR types from the lowered values and specialises untyped helper functions per call-site argument types.

**Values** ([value model](design/M2-VALUES.md)): numbers with exact double semantics; UTF-16 strings; booleans; `null`/`undefined` and nullable types (`T | null | undefined`); string/number/boolean literal unions; objects with a fixed shape (records); arrays; `Map`/`Set`; functions and closures. Class instances (below). Other unions, `any`/`unknown` that cannot be inferred, symbols, bigint and heterogeneous tuples are rejected with `E_TYPE_UNSUPPORTED`/`E_TYPE_UNION`.

**Statements and expressions:** `const`/`let`, assignment and compound assignment to locals, cells, fields and array elements; `if`, `switch`, `while`, `do`/`for`/`for-of` with labelled `break`/`continue`; functions, arrow functions and closures (captured variables are shared by reference); `return`, `throw`, `try`/`catch`/`finally`; template literals; object/array destructuring and spread; optional chaining and `??`; all arithmetic, bitwise, comparison, logical and `typeof` operators; `Number`/`String`/`Boolean` conversions.

**Built-ins:** `Math`, `Number`, string and array methods, `Array.from`/`isArray`, `Object.keys/values/entries/assign`, `JSON.stringify`/`JSON.parse` into a declared type, `Map`/`Set` and `structuredClone`, as listed in [M2-VALUES](design/M2-VALUES.md). `RegExp` with ECMAScript semantics (literal and constructed patterns, flags `dgimsuy`; `exec`, `test`, `match`, `matchAll`, `replace`, `replaceAll`, `search`, `split`; `v` and the static members are rejected). `Date` (construction, `Date.now/UTC/parse` as V8 parses, all getters and setters in local and UTC time, the string and ISO forms) in the case's or system's time zone. `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.Collator`, `toLocale*String` and `localeCompare` for en-US, en-GB, de-DE, fr-FR and ja-JP (and en, de, fr) with the option combinations pinned by Chromium vectors; other locales, options, `Intl.PluralRules` and `Intl.DisplayNames` are rejected (`E_INTL`). Identifiers resolve by symbol, so a local `Math` shadows the global one. Unknown globals and methods are rejected (`E_UNRESOLVED`, `E_MEMBER`, `E_BUILTIN`).

**Time and async:** `setTimeout`/`setInterval`/`requestAnimationFrame` and their `clear`/`cancel` functions, `queueMicrotask`, `Date.now()` and `performance.now()`. `Promise<T>` with `new Promise`, `Promise.resolve/reject/all` and `then`/`catch`/`finally`, in ECMAScript's microtask order (adopting a returned promise costs two ticks). `async` functions and arrows, including event handlers: `await` as a statement, in `const x = await e`, `x = await e`, `x op= await e` and `return await e`, inside `if`, loops, `for-of` over arrays and `try`/`catch`. Rejected: `await` nested in other expressions or conditions, `finally` around an `await`, `for await`, generators, and closures capturing a loop variable across an `await` (`E_ASYNC`). Rejection reasons are Error records.

**Host services:** `localStorage.getItem/setItem/removeItem/clear` (native apps keep it in `$XDG_DATA_HOME/runic/<title>/localStorage.json`; `key()`, `length` and the `storage` event are rejected); `console.log/info/warn/error/debug` with primitive arguments (stderr natively; format strings rejected); `navigator.clipboard.writeText/readText` (the OS clipboard natively); `history.pushState/replaceState` with a null state, `back`/`forward`/`go(n)`, `history.length`, `location.pathname/search/hash` and assigning `location.hash`, with `popstate` and `hashchange` on the window; `Math.random` and `crypto.randomUUID`. The document element (`dataset`, `classList`, `style.setProperty/removeProperty`, `lang`, `dir`) and `matchMedia(q)` / `window.matchMedia(q)`: `matches` and `change` listeners for `prefers-color-scheme`, `prefers-contrast`, `prefers-reduced-motion`, width, height and orientation. Templates and derived values must not use host services (`E_REACTIVITY`).

**Reactivity checks** (all frameworks): a template must not read a value that changes without the framework noticing, which the frameworks would show only when neighbouring state re-renders: a non-reactive variable that is written, a reference tracked by identity but mutated in place, a `Map`/`Set` mutated inside Svelte state, a mutated module object, a RegExp whose `lastIndex` changes or a Date changed by a setter (`E_REACTIVITY`). React state and props must not be mutated in place (`E_READONLY`).

**Classes** (M6 stage A, [design](design/M6-LIBRARIES.md#library-code-steps-3-to-6), case `classes`): class declarations at the top level of local modules and of Svelte and Vue component scripts (React components use module-level classes), in TypeScript or in JavaScript whose fields TypeScript can type (annotations, JSDoc, initialisers). Instance fields with and without initialisers, TypeScript parameter properties, fields the constructor creates by assignment, `#private` fields and methods, methods, getters and setters (compound assignments call both), static methods and static fields (module classes only; constants), `new C(…)`, `this` in methods, accessors, constructors, field initialisers and the arrow functions inside them, and `x instanceof C` (decided by the static type of `x`). A method is a value only when bound: `this.m = this.m.bind(this)` at the start of the constructor makes `m` a field holding a bound function, `obj.m.bind(x)` creates one, and arrow function fields keep their instance; `f.bind(x)` of a function value makes a new function (`x`, which it ignores, is `this`, `null`, `undefined` or a variable). Methods dispatch on the class of the receiver (statically where its type names one class; see inheritance below). An instance is built as JavaScript builds it: field initialisers in order, the constructor's leading `this.f = …` assignments, then the rest of the constructor; before the instance exists, `this` may only be read as an earlier field, inside an arrow function stored whole in a field, or bound. Svelte `$state` holds instances as they are (no proxy), so mutating one that the template reads is `E_REACTIVITY`; Vue refs proxy them as Vue does. Rejected (`E_CLASS`): generic and anonymous classes, class expressions, decorators, `accessor` and `declare` fields, computed and quoted member names, overloads, static blocks and accessors, unbound method references, other uses of `this` before the instance exists, `return` in constructors, fields not set before the constructor otherwise uses `this` (unless optional), use before the declaration, `JSON.stringify`, `structuredClone`, `Object.keys/values/entries/assign`, spreads and string conversion of instances, object literals typed as a class, `instanceof` on values of unknown type (caught exceptions), assigning static fields, static fields of component-script classes, partial application with `bind`, and Vue refs of classes whose constructor keeps the raw `this` in closures (arrow function fields, bound methods), whose writes Vue's proxy would not see.

**Reactive class fields** (M6 stage B, [design](design/M6-LIBRARIES.md#reactive-class-fields-stage-b), case `reactive-classes`): in Svelte component scripts and `.svelte.ts`/`.svelte.js` modules (where Svelte compiles runes; components import them with the full name, `./todos.svelte.ts`), a field initialised with `$state(v)`, `$state.raw(v)`, `$derived(e)` or `$derived.by(f)`, public or `#private`, or a field the constructor assigns one of them as a leading `this.f = …` statement. They behave as Svelte 5.57.1's signals: reading one is a dependency of the running `$effect` or derived value (unless that computation created the instance), and the template updates after writes. A write notifies when the new value is not `===` the old one (`-0` over `0` changes nothing and keeps `0`; `NaN` over `NaN` notifies); `$state` stores proxies of plain objects and arrays (deep state, as component `$state`), `$state.raw` and class instances are stored as they are. Derived fields are computed from the instance when first read, cached until what they read changes, and keep their value when a recomputation gives an `===` one, so effects reading them re-run only when it changed. Instances can live in component constants, state, other instances' fields and module constants. Rejected: assigning a derived field (Svelte 5.25+ overrides), `$derived` in the constructor reading the constructor's parameters or locals, reactive fields assigned after the constructor otherwise uses `this`, runes in plain `.ts`/`.js` modules and in React and Vue code (`E_CLASS`); writing reactive state from a template expression or a derived value, directly or through the functions they call, unless that code created the instance (Svelte throws `state_unsafe_mutation`), derived fields that change values they did not create or use host services, template reads of `$state.raw` values mutated in place and of plain fields written after construction (`E_REACTIVITY`); reading a derived field of a component-script class in another component.

**Inheritance and class references** (M6, [design](design/M6-LIBRARIES.md#inheritance-and-class-unions), case `class-hierarchy` in Svelte, React and Vue): single inheritance (`class B extends A`) between classes compiled from source, declared in the same module scope or component script. An instance has its base classes' fields first. Construction follows JavaScript: the statements before each `super(…)` (which must not use `this`) and its arguments from the class up to the root, then from the root down each class's parameter properties, field initialisers and the rest of its constructor; a class without a constructor passes its arguments on. Methods, getters, setters, static methods and static fields are inherited and can be overridden; `super.m(…)`, `super.x` (a getter) and `super.x = v` (a setter) call the base class's member; `#private` names belong to the class declaring them (a subclass may declare its own of the same name). Abstract classes, abstract methods and abstract properties (implemented by the subclasses' methods and fields); reactive fields (`$state`, `$derived`) in base classes and subclasses. A value TypeScript types as a class that has subclasses, or as a union of classes, keeps its instance's class: a member its classes declare differently (overrides, abstract members, a field each class of a union declares) is chosen by that class; `instanceof`, discriminant checks (`x.kind === 'single'`) and `as` assertions narrow it, and an assertion TypeScript cannot check (`as unknown as C`) throws a `TypeError` where the instance is of another class (JavaScript would continue with the wrong object). Every class of the program's sources is known, so a class's subclasses are all its subclasses there. Rejected (`E_CLASS`): extending library classes (`Error`, `MediaQuery`; mapping packs will provide them), mixins and other base expressions, generic base classes, `super(…)` other than as one statement at the top level of a constructor, `this` before `super(…)`, `super.x` of a field (JavaScript reads the prototype) or of an abstract member, redeclaring an inherited field (except without an initialiser, assigned at the top of the constructor before it otherwise uses `this`: bits-ui's `opts` of narrower options types, which then share one record with the types constructors pass on to the base; a field only some of them have is read through a type that has it, a `TypeError` if the program broke its types), extending a class of another module scope or component script, a base constructor that uses `this` beyond its leading field assignments when a subclass declares fields (JavaScript would run that code before the subclass's fields exist), assigning through a union a field its classes declare separately, binding a method that subclasses override through the base type, and arrays, maps, sets and functions of a subclass type used as ones of the base type (they keep their identity).

**Object keys** are observable (`Object.keys`, `JSON.stringify`), so a record keeps the key order of the literal that creates it; a spread contributes its source's keys in their order. A literal whose properties are in a different order than its declared type is rejected (`E_OBJECT`).

**Modules:** components can import named bindings from local `.js`/`.ts` modules, with aliases, export lists and named re-exports, and import other components (`.svelte`, `.vue`, function components). Modules initialise once, dependencies first. Module functions become shared functions; constants become program globals, evaluated once in order (object constants keep their identity). Module objects may be mutated (they are not reactive). Barrels (M6, [design](design/M6-LIBRARIES.md#library-modules-step-3), case `shadcn-basics`): `export { default as X } from './x.svelte'`, `import Root from …; export { Root, Root as Button }`, `export *` and `export * as N`, chained through any number of modules, and names a module re-exports from a package (`export { cn } from "cn"`), which keep the package's [pack](#packages). Namespace imports (`import * as Card from …`) name components as tags (`<Card.Root>`, Svelte) and may be re-exported; using a namespace as a value is rejected (`E_IMPORT`). `let` exports, top-level statements, default imports of plain modules, cycles, `export *` of a package and npm dependencies without a mapping pack are rejected (see [Packages](#packages)).

**Library code (M6):** objects whose TypeScript type has only a string index signature (and constant keys of its value type) are dictionaries (maps), read and written by key, also with computed keys; reading a key that names a member of `Object.prototype` (`toString`, …) or writing `__proto__` throws `RunicUnsupportedError`. A record read with a computed key of its field names (`{ horizontal: …, vertical: … }[orientation]`). Unions of plain object types are one record (key sets untracked: key-observing built-ins reject it). `Object.is`. Tests the IR types decide in untyped package code (`Array.isArray(x)`, `typeof x === "…"` of a local) keep their one branch; callbacks of array methods in untyped code take the element type; parameters typed `unknown` are specialised per call site; an untyped `let x;` takes the type of the values assigned to it. Methods bound into their fields later in a constructor (`this.m = this.m.bind(this)` after other statements) are bound when the instance is built, when nothing before reads them other than by calling them.

**Outside M5:** generators, getters and setters in object literals, `in`, `instanceof` other than of classes and `HTMLElement`, rest parameters, logical assignment, string literals containing lone surrogates, typed arrays, `ResizeObserver` (M6, with the libraries that use it) and npm dependencies other than the [mapping packs](#packages) (M6).

## React

The entry calls `createRoot(document.getElementById('root')).render(<App />)` for a local function component. Every function component is a component with instances: a rendered `<Child/>` gets its own state, created and destroyed with its region (a conditional branch, a list item), so state resets on remount. A component body holds `useState` declarations (non-lazy initialisers), const render values, nested functions and one returned JSX tree; expression-bodied arrow components are accepted. Reads see the render snapshot of the last commit, and closures created in a handler or effect keep the snapshot they were created with (stale closures). Setters with values or updater functions queue in order; discrete events (click, input, change, keydown) render in a microtask, other updates (timers, promises, effects) in a later task.

- **Props:** destructured or through a `props` parameter, typed by TypeScript or, in JavaScript, by the first call site. Callbacks are function props. `children` and other `ReactNode` props rendered as `{children}`, and render props `(x: T) => ReactNode` called as `{row(x)}`, are slots evaluated in the parent.
- **Lists:** `items.map(item => <Row key={…}/>)`, keyed or (without a key) by index, with React's forward-placement reorder; React DOM's focus restore after a commit is reproduced. A `key` elsewhere remounts its element when it changes.
- **JSX:** the native tag allow-list (with `textarea`, `label`, `select`, `option` and inline SVG, below), string and expression attributes (entities decoded), `className`, inline `style` objects (keys written inline, set through the CSSOM as React DOM does), `&&`/`?:` conditionals, fragments, rest props and spread attributes (`{...rest}`, listeners included) and refs passed as props.
- **Events:** event objects (`type`, keys and modifiers, pointer coordinates and buttons, `target`/`currentTarget`, `preventDefault`, `stopPropagation`) for click, double click, context menu, key, pointer, mouse and focus events (`onFocus`/`onBlur` from `focusin`/`focusout`, with `relatedTarget`); continuous events only where React's later render is unobservable; window and document listeners. Controlled text inputs, text areas (`value` with `onChange`), checkboxes, radio buttons (`checked` with `onChange`, exclusive named groups) and selects (`value` with `onChange`), restored after every dispatch as React DOM does. `onWheel` and `onScroll` are rejected.
- **Refs:** `useRef<HTMLInputElement | null>(null)` attached with `ref={r}` to one element of the same component; `r.current` reads the live element (`focus()`, `blur()`, null checks). `useRef` of numbers, strings and booleans is a mutable box that never re-renders. Callback refs, refs passed to components, one ref on several elements, refs in list items or slot content, ref reads during render and refs holding objects are rejected.
- **Effects:** `useEffect` and `useLayoutEffect` with no dependency array, `[]` or a literal array of values; their functions and cleanups read the render that created them. Layout effects run after the DOM update children first; all cleanups of a phase run before its effects; passive effects' state writes render in a later task; unmount cleanups run parent first, layout before DOM removal and passive after.
- Rejected: effects outside the component body's top level or in custom hooks (`E_HOOK`), non-literal or spread dependency arrays and object or function dependencies other than state and props, async effect functions, microtasks queued in layout effects, `useInsertionEffect`, `useMemo`, `useCallback`, lazy initialisers, conditional or list regions whose unmount cleanups React would order by element position, nested prop destructuring, style strings and computed style keys, `select multiple`/`defaultValue`, controlled controls without `onChange`, `focus()` outside discrete event handlers where focus listeners exist, recursive components.

## Vue

The entry calls `createApp(App).mount('#root')` on a local SFC with `<script setup>` (JS or TS). Setup supports `ref`, `computed`, functions, const values and local module imports; `ref` reads see earlier writes immediately and nested mutation is tracked. `computed` values are cached and recompute when what they read changed. Templates support the tag allow-list, static attributes, `:attr` bindings, `:class` (objects, arrays, strings, normalised and merged with a static class) and `:style` (objects, arrays, strings, applied as `patchStyle` does), interpolation and `v-if`/`v-else-if`/`v-else`. Fallthrough attributes and `v-bind="$attrs"`/object spreads are applied as Vue merges them. Vue marks `#root` with `data-v-app`.

- **Components:** child SFCs are instances. `defineProps<T>()` (destructured or as an object, optionally with `withDefaults`), `defineEmits<T>()` (as `on<Event>` callbacks) and `defineModel<T>()` with the parent's `v-model`.
- **Lists:** `v-for` over arrays with `:key`, keyed or by index, with Vue's longest-increasing-subsequence reorder.
- **Slots:** `<slot>` outlets (default, named, scoped, with fallback), typed by `defineSlots<T>()` or inferred; `<template #name>`, `v-slot` and default content in the parent, with destructured slot props.
- **Events and forms:** event objects for click, double click, context menu, key, pointer, mouse and focus events (`@focus`, `@blur`, `@focusin`, `@focusout` with `relatedTarget`), with `withModifiers`/`withKeys` modifiers; several listeners of one event run in order. `v-model` and `:value` on text inputs and text areas (re-applied at every re-render where they differ, as Vue patches them), `:checked`/`v-model` on checkboxes, `v-model` on selects and radio buttons with literal values. `@scroll`, `.once`, `.capture` and `.passive` are rejected.
- **Refs:** `ref="name"` on an element (or a component that forwards it) bound to a `ref()`/`shallowRef()` of that name or to `useTemplateRef<T>('name')`; the ref holds the element while it is mounted and `null` after removal. Refs read during rendering, writes to template refs, `:ref`, refs in `v-for` or slot content and refs on components, slots or `<template>` are rejected.
- **Watchers and lifecycle:** `watchEffect` (with `onCleanup`/`onWatcherCleanup`) and `watch` of refs, computeds, getters or arrays of them (`immediate`; the callback receives the new and old values) run before the component updates; `onBeforeMount`, `onMounted` (synchronously within `mount()`), `onBeforeUnmount` (DOM attached, parent first) and `onUnmounted` (after removal, children first). `nextTick()`/`nextTick(fn)` resolve when the pending flush ends. Each listener ends with a microtask checkpoint, as Vue attaches listeners to elements.
- Rejected: `deep`/`once`/`flush: 'post' | 'sync'` watchers, `onUpdated`/`onBeforeUpdate`, watching props or reactive objects, watchers whose writes another watcher of the component reads (Vue's queue order), regions whose unmount work Vue would run before later siblings are created, other directive modifiers, `v-model` modifiers and `v-model` on other input types, text controls whose re-renders Runic cannot match (object or function props, listener fallthrough, slot outlets, side-effecting template expressions), `:checked` on radio buttons, `v-show`, dynamic slot names, `$slots`, slot content that may render nothing where the child has a fallback.

## Svelte

The entry calls `mount(App, {target: document.getElementById('root')})` (or `querySelector('#root')`) on a local component in runes mode. Scripts support `$state`, `$state.raw`, `$derived`, `$derived.by`, functions, `let`/`const` values and module imports. Reads see earlier writes immediately; derived values are cached and recompute when what they read changed. Markup supports the tag allow-list, attributes with expressions (an empty `class` is omitted; nullable numbers and booleans are absent when nullish, otherwise their string, as `set_attribute` writes them), interpolation and `{#if}`/`{:else if}`/`{:else}`.

- **`<script module>`** (M6): its statements are a module of their own, initialised once in module order (constants, functions, classes, `tv()` definitions of the tailwind-variants pack, imports); the instance script and the template see its names, and other modules import its exports (`import Root, { buttonVariants } from './button.svelte'`). Components a program never instantiates still provide their module scripts.
- **Component tags** resolve through imports, barrels and namespace imports: `<Button>`, `<Card.Root>`.
- **`<svelte:element this={tag}>`** (M6) with a tag from a finite set of HTML elements of the allow-list (literals, conditionals, literal-union values, props whose sites pass them): one element per tag, recreated with its content when the tag changes; a nullish tag renders nothing.
- **Links** (M6): `<a href>` is focusable and followed by a click or Enter, as a fragment navigation (`popstate`, then `hashchange` when the fragment changed; following the same link again replaces the history entry). `href` values must be a finite set of fragments (`#name`) that name no element and are not the document top (`#`, `#top`); other links (other documents, the top, a fragment naming an element: scrolling to and focusing it) are rejected (`E_TEMPLATE`), as are `:target` selectors (`E_CSS`, Blitz never matches them).

- **Deep state:** `$state` stores proxies of plain objects and arrays, with Svelte's identity: storing a raw object gives a new proxy, and only writes through the proxy are reactive ([ownership](design/M3-COMPONENTS.md#svelte-deep-state-ownership)).
- **Components:** child components are instances; `$props()` with defaults, `$bindable` and rest props (`...rest`, forwarded with `{...rest}` spread attributes, listeners included), `bind:prop`, callback props, `bind:this` on components and on elements into a `$bindable` prop (`ref = $bindable(null)`). Rest props typed by svelte/elements' attribute interfaces (`WithElementRef<HTMLButtonAttributes>`) are attribute bags as before.
- **Lists:** `{#each}` with index, key, destructured items and `{:else}`, with Svelte's keyed reconcile; `{#key}` remounts its content.
- **Snippets:** `children`, named snippets and `{@render}` with arguments.
- **Events and bindings:** event attributes for click, double click, context menu, key, pointer, mouse, wheel, focus and `scroll` events with event objects; `<svelte:window>`/`<svelte:document>` and `window`/`document.addEventListener`. `class:` and `style:` directives (composed as `to_class`/`to_style`). `bind:value` on text inputs, text areas and selects, `checked`/`bind:checked` on checkboxes, `bind:group` on radio buttons with literal values, `bind:this` element refs, labels.
- **Effects:** `$effect` and `$effect.pre` re-run when the state, derived values or proxied properties they read change; `onMount` and `onDestroy`; `tick()`. Cleanups read the state as it was before the flush, and teardowns run after the DOM is removed. M6: `$effect`/`$effect.pre` also inside functions that run while an instance is created (class constructors, runed's `watch`): a pre effect runs at once, as Svelte runs it; elsewhere they throw `RunicEffectError`.
- **Library features** (M6, as bits-ui uses them): `$props.id()` (`c1`, `c2`, … in creation order); `untrack(fn)`; `on(element, 'beforematch', handler)` from `svelte/events` (Blitz never fires it); contexts through runed's `Context` (set while an instance is created, read up the instances that render it); props whose passed `undefined` takes the default; snippets passed on through rest props and tested for presence. Top-level statements of component scripts other than declarations (`State.create(…)` called for its effect, `watch.pre(…)`, `if`) run while the instance is created, in order with the declarations. `$state.snapshot(v)`. `SvelteMap` from `svelte/reactivity` (`get`, `has`, `set`, `delete`, `clear`, `size`; no initial entries or iteration): its reads depend on the whole map, where Svelte's depend on one key, so it may be read only in `$derived` values and derived class fields (effects would run where Svelte's do not: `E_REACTIVITY`). Props typed wider than the value model (svelte/elements' `value?: any`) take the types their sites pass, also through spreads and rest props passed on; a required prop given through a wrapper's rest props that every site of the wrapper passes. Snippets and children may take fewer parameters than they are rendered with. A bare attribute passes `true` to a component. camelCase props in bags (lowercased where a spread sets them on an element, as `setAttribute` does). A spread's `value` is assigned to the element's property (an attribute only where the property reflects it: `button`, `option`, `data`; reported unsupported on inputs and the like) and an input's `checked` to its live state, as Svelte's `set_attributes` does. `bind:value` on a text input bound to a nullable string. Props typed by a discriminated union (bits-ui's `type: "single" | "multiple"`) take the member's types when every site passes one discriminant literal, also through a wrapper's rest props. `bind:prop` of a variable of the present type to an optional prop that its component only sets to present values (followed through the component's own `bind:`s; otherwise `E_TEMPLATE`); a type assertion on the bound variable (`bind:value={value as never}`). `setContext`/`getContext` from `svelte` with string literal keys in `<script module>` functions: one context per key program-wide, typed by what the program sets; a read where no parent set it gives `undefined`, or throws `RunicUnsupportedError` where its type cannot hold it (`getContext<Required<T>>`). Objects written with getters (`{ get variant() { … } }`): their type's objects hold a getter per property, called at each read (read-only; every literal of that type uses getters).
- **Spreads** (M6): `{...bag}` onto elements and components takes attribute bags: rest props, `mergeProps` results, bits-ui's `props` objects, class fields typed `Record<string, unknown>` whose derived value is an object literal, and `child` snippet arguments. Onto an element, booleans of names without a boolean property (`data-*`, `aria-*`, …) become `"true"`/`"false"`, a `style` string is set through `cssText` when it changes, functions under other names are not attributes, and attachments (`attachRef`) run with the post effects of the instance rendering the element; a style object and `hidden="until-found"` are unsupported (the native runtime reports them, the interpreter throws). Onto a component, entries reach its declared props (a later entry overriding an explicit attribute; a callback of a compatible type adapted, another kind of value throwing `TypeError`) and the rest its rest props; `bind:` after a spread that may hold the name is rejected.
- Rejected: `$effect.root`, `$effect.tracking`, `$inspect`, async effect functions, other `svelte` imports (and `setContext`/`getContext` in instance scripts or with other keys) and `svelte/events` events other than `beforematch`, runes and mutable state in `<script module>`, component styles, legacy `on:` directives, actions, function bindings, rest props read by name in script, top-level statements other than effects and lifecycle calls, `experimental.async`.

## SvelteKit

M6, phase 1 of the [design](design/M6-SVELTEKIT.md): single-page SvelteKit apps with universal loads, rendered by Kit's client router ported to the compiled language (`frontend/adapters/kit/`, Kit 2.70.1 `client.js`) over the M5 history. Cases `kit-hash` (hash router), `kit-routes` and `kit-routes-missing` (path router) compare the native app with the app's real Kit build (adapter-static, `fallback`) served to Chromium.

- **Recognition.** `runic.json` is `{ "framework": "svelte", "kit": true, "title": … }` (no `entry` or `alias`: Kit gives both). `@sveltejs/kit` must be **2.70.1**, the files whose code builds the manifest byte-identical to the published package (SHA-256, `compiler/adapters/kit-pins.mjs`); other versions fail with `E_FRONTEND_VERSION` (Kit 3, and its `vite.config` configuration, is not yet supported). The app's `vite.config` and `svelte.config.js` are never run: `svelte.config.js` is read as literals, accepting `kit.router.type` (`hash` or `pathname`), `kit.router.resolution` `client`, `kit.alias` (with `$lib` → `src/lib`), `kit.output.bundleStrategy` `single` or `inline`, `kit.version.pollInterval` 0, `compilerOptions.runes` `true`, and ignoring the build-only `adapter`, `prerender`, `appDir`, `outDir`, `typescript`, `csp`, `csrf`, `env`, `inlineStyleThreshold` and `serviceWorker`; anything else, `preprocess` and `extensions` are `E_KIT_CONFIG`.
- **`src/app.html`**: `<html>` attributes become the document's, `<body>` attributes the body's; the body holds one element whose only content is `%sveltekit.body%`, and that element (its attributes kept) is the container instead of `div#root`. The head may hold `<meta charset>`, `<meta name="viewport">` and `%sveltekit.head%`. Scripts, links, styles, titles, event attributes and placeholders in attributes are `E_KIT_HTML`; `data-sveltekit-preload-data`/`-preload-code` other than `off`/`false` (in app.html or on elements) are `E_KIT_PRELOAD`.
- **Routes.** The app's own Kit builds the manifest (`create_manifest_data`): route ids, groups, layout chains with `@` resets, rest and optional parameters, matchers from `src/params` (ordinary compiled functions), Kit's sort order, Kit's default layout and error page. A generated root component nests the layouts through `children` with `data` and `params`; a level whose component is unchanged keeps its instance and gets new props.
- **Loads.** `+page.ts`/`+layout.ts` export `load` (declared function or `const load = (…) satisfies PageLoad`; a `: PageLoad` annotation is `E_KIT_LOAD`) and the page options `ssr` and `prerender = false`; others are `E_KIT_LOAD`. Loads get `params`, `url`, `route` and `parent()`; Kit's dependency tracking re-runs a load only when the params, url parts, route or parent data it read changed. `error(status, message)` renders the nearest `+error.svelte` (Kit's `load_nearest_error_page`), an unknown route the root error page with 404; `redirect(status, location)` navigates within the app. `handleError` from `src/hooks.client.ts` gives the error object (`{ event, status, message }` in; no `error`, since unexpected errors are values Kit logs and the compiled program does not inspect). Data merges with parent data as Kit merges it.
- **Navigation.** Link clicks (absolute and relative `href`, fragments of the current page, `data-sveltekit-noscroll`, `-keepfocus` and `-replacestate` on the link, an ancestor, the container or `<body>`), `goto(url, { replaceState, noScroll, keepFocus })` returning a promise, back and forward, `beforeNavigate` with `cancel()` (links, `goto`, traversals; a cancelled traversal goes back), `afterNavigate`, scrolling to the top or to the fragment's element (which also becomes the sequential focus starting point), Kit's focus reset, the `#svelte-announcer` live region, and `<svelte:head><title>` setting `document.title` (one `<title>` of text and expressions; the window title stays the `runic.json` title). History entries carry Kit's indices as their state. `beforeNavigate`/`afterNavigate` are called as top-level statements of a component script (registered when the instance mounts, removed when it is destroyed); elsewhere `E_KIT_LIFECYCLE`.
- **Modules.** `$app/state` (`page.url`, `page.params`, `page.route.id`, `page.status`, `page.error`), `$app/navigation` (`goto`, `beforeNavigate`, `afterNavigate`), `$app/environment` (`browser` `true`, `dev` and `building` `false`), `@sveltejs/kit` (`error`, `redirect`, types), `./$types` (generated `PageProps`, `PageData`, `PageLoad`, `LayoutProps`, …). Route components declare `data`, `params` and `children` by destructuring `$props()`.
- **Runtime reports** (`RunicUnsupportedError`, as for other unsupported values): navigations Kit performs by loading another document (external links, `data-sveltekit-reload`, unknown paths through links or `goto` in path mode, redirects to other origins), redirect loops, errors without a `handleError` hook (Kit's default logs a stack trace), a hash edited without router state.
- **Rejected:** server loads, `+server` endpoints, form actions (`E_KIT_SERVER`); `hooks.server`, universal hooks and service workers (`E_KIT_HOOKS`); `$app/stores`, `$app/forms`, `$app/paths`, `$app/server`, `$env/*`, `$service-worker` (`E_KIT_IMPORT`, at the import); `page.data`, `page.form`, `page.state`, `navigating`, `updated`, `onNavigate`, `invalidate*`, `preload*` and shallow routing (`pushState`/`replaceState` from `$app/navigation`), which the modules do not export; a `form` prop or rest props in route components (`E_KIT_COMPONENT`); a route module without a component (`E_KIT_ROUTES`); `catch` clauses in route modules and in modules that reach `@sveltejs/kit` (`E_KIT_CATCH`: `error()` and `redirect()` throw the router's errors); document `click` and window `popstate`/`hashchange` listeners (`E_KIT_LISTENER`: the router owns them); `autofocus` (`E_KIT_ATTRIBUTE`); `{@html}` and `<iframe>` as in all Svelte code.
- **Known deviations.** Data objects of different route nodes are compared as different (Kit compares their identity after a `parent()` merge, which only matters for objects shared between loads); a reload does not restore Kit's per-entry scroll positions (Kit keeps them in `sessionStorage`); errors thrown while rendering are not routed to `+error.svelte`; route modules initialise with the program, not when their route first loads. The differential is incomplete for Kit apps: the router reads the window's scroll position at every navigation.

## Inline SVG

Icons written inline in templates, as lucide draws them, in all three frameworks ([IR](IR.md#template), case `icons`):

- **Elements:** `svg`, `g`, `path`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `rect`, created in the SVG namespace; `{#if}`/`v-if`/`?:` and lists inside an `<svg>`. An `<svg>` needs a `viewBox`; it may stand in text, flex rows and buttons, sized by `width`/`height` or by CSS.
- **Attributes:** on `<svg>` `xmlns` (the SVG namespace only), `width`, `height`, `viewBox`, `class`, `id`, `role` (ARIA, no rendering effect; M6); on every element the paint attributes `fill`, `fill-opacity`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-opacity`, and `class`, `aria-*`, `data-*`; `opacity` and `transform` on groups and shapes; each shape's geometry. Values are static or bound strings and numbers; class toggles (`class:`, `:class`) work. `currentColor` follows the CSS `color` of the element holding the attribute. Colours in other spaces (`oklch()`, as the shadcn themes are) are converted to sRGB for it.
- **React** maps props as react-dom 19.3's `setProp` does: `className` → `class`; `viewBox`, `width`, `height` keep their names; `fillOpacity`, `fillRule`, `strokeDasharray`, `strokeDashoffset`, `strokeLinecap`, `strokeLinejoin`, `strokeMiterlimit`, `strokeOpacity`, `strokeWidth` → their hyphenated names (`getAttributeAlias`); lowercase, `aria-*` and `data-*` names as written; a boolean `aria-*`/`data-*` value is the string `"true"`/`"false"`. Other camelCase props (`clipRule`, `xlinkHref`, `xmlnsXlink`, `preserveAspectRatio`, …) and props with rules of their own (`focusable`, `style`, …) are rejected (`E_JSX`).
- **Rejected** (`E_SVG`): other SVG elements (`text`, `use`, `defs`, `clipPath`, gradients, …), nested `<svg>`, HTML elements, components, slots or text inside an `<svg>`, listeners, spreads, refs and inline styles on SVG elements, `id`, `style` and `color` on SVG children, attributes outside the list. Blitz renders inline SVG from attributes, so author CSS reaches SVG children only through `color`, and `currentColor` inherited by a child resolves with the color of the element that holds it, not the child's ([gaps](BLITZ-GAPS.md)).
- **Size.** Only programs with an `<svg>` link Blitz's SVG support (usvg, 1.6 MiB in a release build): codegen enables the runtime's `svg` feature for them.

## Native runtime and controls

The Rust backend validates every program and generates an application crate linked against `crates/runic-runtime`. The runtime builds the DOM directly through Blitz's mutator API under `<div id="root">`, keeps node handles, and updates only bindings whose cells changed (or all bindings with `--no-opt`). Conditional content and component instances are mounted and removed as subtrees; keyed lists move existing nodes with the framework's reorder strategy. It supplies the browser behaviour the pinned Blitz lacks or does differently ([gaps](BLITZ-GAPS.md)):

- **Events.** Chromium's sequences on Linux: pointer and mouse boundary events, `click`/`dblclick` by click count, `contextmenu` on press, `wheel`, key events with Playwright's modifier order; listeners run target first then bubbling, then document and window listeners, each with its microtask checkpoint; cancelled events have no default action, and neither has a target its listeners removed. Disabled controls get pointer events only.
- **Focus.** Focus moves on mousedown (to the nearest focusable element, nowhere for other content); Tab and Shift+Tab follow `tabindex` order (positive values first); `focus()`/`blur()` run their listeners nested. Every move dispatches `blur`, `focusout`, `focus`, `focusin` with `relatedTarget`. Removing the focused element, or a keyed move detaching it, dispatches `blur` and `focusout` at once while it is still in the document; a focused control that becomes disabled (natively also one that loses its box) is blurred by the rendering step's focus fixup. After a move-induced blur, Tab resumes after the moved element, not from Chromium's live range at the detach position (case `reorder-navigation`, a known gap).
- **Controls.** Checkboxes and radio buttons (groups by name in a tree, arrow keys, Tab entering a group at its checked button; checking one, by user or script, unchecks the group); text areas and labels; selects drawn by the runtime (closed control at Chromium's metrics, keyboard on the closed control, a popup drawn into the page with Chromium's keyboard and pointer model). Script-set values update the live control only when they differ, so echoes preserve selection and composition; read-only and disabled edits are blocked; `maxlength` (UTF-16 units) and control characters are stopped before mutation; Alt with navigation or editing keys does nothing in text controls, as on Linux Chromium.
- **Layout and scrolling.** `getBoundingClientRect`, `offset*`, `client*`, `scroll*` read the native layout with Blink's pixel snapping; `scrollTop`/`scrollLeft`, `scrollTo`, `scrollBy`, `scrollIntoView` (every scroll container, whole pixels) and the window equivalents scroll at once. A rendering step after each task runs the window's `resize` event, `scroll` events (one per moved scroller), media query list `change` events, then the focus fixup.
- **Inline styles and the document element** go through the CSSOM (`runic-css` over Stylo): serialisation, `setProperty` and each framework's update model, and (M6) script access to an element's inline style properties (`node.style.transitionDuration`).
- **Library DOM APIs** (M6): `isConnected`, `hasAttribute`, `getAttribute` (`element.id`), `closest(tag)`, `querySelectorAll`/`querySelector` with a subset of selectors (type, `#id`, `.class`, `[attr]`, `[attr=value]`, `:not()`, descendant and child combinators; others reported unsupported), `x instanceof HTMLElement` (false for SVG elements), `getComputedStyle(e).getPropertyValue("direction")` (computed; other properties rejected; the interpreter reports it as layout), `event.detail` (the click count of mouse button events; 0 for keyboard and simulated clicks); `requestSubmit()` is reported unsupported (no form can be rendered); `new Image()` throws `RunicUnsupportedError`; `getAnimations()` returns an empty list when the element's computed style declares no animation and no transition of a positive duration, and is reported unsupported otherwise (Blitz has no animation objects); `MutationObserver` may be created and disconnected, observing is reported unsupported; `beforematch` is never fired. An element without layout boxes (`display: none`, or inside such an element) has an empty rectangle at the origin, in `getBoundingClientRect` and in probe geometry, as in Chromium.
- **Event loop.** Input events and timers are tasks, each followed by its microtask checkpoint; state writes queue the framework's flush job; default-priority tasks (React) run after the current task; host replies (clipboard, history traversals) are tasks after the one that asked. Timers use the system clock natively and a virtual clock in probes.
- **Animations.** Every style resolution runs CSS transitions and animations at the document timeline's time: real time natively (from the shell's first access to the document, where blitz-shell starts its animation clock; the shell redraws while animations run), the virtual clock in probes, whose `wait` resolves styles at every 16 ms frame so that animations started by timers begin at the frame. Text in anonymous blocks (direct text of flex and grid containers, including default `inline-flex` buttons) keeps the `color` it had when its boxes were built, with or without a transition ([gaps](BLITZ-GAPS.md)).
- **Rendering.** The canvas is painted white beneath the document. Form controls use Chromium's default font size and radio and checkbox metrics; `svg` elements clip their drawing (`overflow: hidden`, as in Chromium's UA sheet). The CPU (vello_cpu) and GPU (vello) renderers are selected per project. Both draw filters and backdrop filters (forks, [research](research/M6-CPU-RENDERER.md#the-gpu-renderer)); the GPU renderer draws windows with area anti-aliasing (as the CPU renderer and Skia; anyrender's default for windows is 16x MSAA), and its fork samples gradients and box shadows at pixel centres. Pixel conformance is pinned to the CPU renderer; `conformance/run.mjs --renderer gpu` runs the same gates on GPU builds, drawn on Mesa's software Vulkan driver (lavapipe) from the locked shell: the representative cases, `filters`, `backdrop-filters` and `gradients` pass it.

## Verification

`conformance/run.mjs` drives the original framework in headless Chromium and the native app's probe build with the same input: clicks, double clicks, context menus, hovers and wheel turns (at an element's centre or a given position in it), key presses and typing, focus, option choices, viewport resizes and emulated preferences, history traversals, reloads and virtual-time waits. It compares DOM semantics (tags, attributes, text, live values, selections, focus), host effects (console lines, clipboard text, location, history length), geometry within 2 px and, with `--pixels`, screenshots within a mean absolute error of 3/255, over the whole viewport and over each element a case names in `pixelRegions`. Chromium's document timeline is stopped and every CSS animation is sought to the virtual time since the harness first saw it, at the points where the probe resolves styles (Playwright's fake clock does not move the timeline). A case sets its environment: time zone, locale, start URL, clipboard text, random seed (the harness replaces Chromium's `Math.random`/`crypto.randomUUID` by the probe's seeded generator), `localStorage`, and the fake clock for programs that read the time. `conformance/differential.mjs` compares generated code with the reference interpreter on seeded random traces; programs that read layout or listen for scroll events are reported incomplete there and checked against Chromium only. Comparisons observe committed output after natural paint and focus settling and never force blur. The Svelte reference is compiled for production. `conformance/interp-vs-browser.mjs` compares the interpreter with the framework without native builds. [M5 results](../conformance/results/m5.md) list the cases, results and known deviations.

OS keyboard delivery, IME, Wayland resize and accessibility are not certified (internal events do not prove them). The OS clipboard and native console output were checked once by hand under X11, not by conformance. Multiple windows are outside verified support. Builds are atomic and run `--offline` against the workspace `Cargo.lock`. No performance improvement is claimed beyond the measured startup and size figures in the results.
