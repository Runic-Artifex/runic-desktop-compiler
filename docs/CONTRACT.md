## Collection

The shared IR and Svelte element lists contain 80 tags (with `img`, below); React and Vue accept 73.
All three accept `form`, `fieldset`, `legend`, `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`,
`td`, `colgroup` and `col`. React and Vue still lack `a`, `dl`, `dt`, `dd`,
`figure` and `figcaption`. Blitz owns table formatting; adapters lower structure
and attributes (React maps `colSpan`/`rowSpan`), with no framework-specific backend
path. Verified fixtures cover captions, column sizing, row/group boxes, spans,
alignment, collapsed borders, responsive scrollers and cell/row events. An automatic
table distributes its width over length, percentage and automatic columns as Chromium
does (Blitz fork, case `table-width`); colspan distribution does not yet follow Blink.
The complete CSS table model and full quirks behavior remain separate gaps.

**Fieldsets** (case `fieldset`, fixture `fieldset-svelte`, `tests/fieldset.test.mjs`, Blitz fork; [results](../conformance/results/fieldset.md)): `fieldset` and `legend` in all three adapters, laid out and painted as Chromium 153 does. The rendered legend (the first `legend` child that is neither floated nor absolutely positioned, also after other content) leaves the fieldset's content: it is shrink-to-fit at the content box's inline start (auto margins align it), its block-start margin ignored, centred over a thicker block-start border, and the content (block, flex or grid, with its gap) starts below the larger of the border and the legend's margin box. A definite height keeps its border box; a content-sized fieldset is at least as wide as its legend. The border runs through the legend's centre and is cut out behind it (snapped to device pixels), and the background and shadows start at the border. A second legend is ordinary content. The UA border is Chromium's `2px groove rgb(239, 239, 239)`. `disabled` on a `fieldset` is rejected where it is written or where a spread or rest props may carry it (`E_TEMPLATE` in Svelte and Vue, `E_JSX` in React, `E_IR` in the validator; the runtime reports one reaching a fieldset through a bag as unsupported): a disabled fieldset disables its descendant controls, which the runtime does not model. Legends with an inline `display`, inline content on both sides of the legend, `display: inline` fieldsets and scrolling fieldsets render differently ([gaps](gaps/PLATFORM.md)).

`runic.json` selects a local entry, title, optional `framework` (`react`, the default, `vue` or `svelte`) and optional `renderer` (`cpu`, the default, or `gpu`). Optional `alias` maps import prefixes to directories inside the app, resolved as Vite's `resolve.alias` (`"alias": { "$lib": "src/lib" }`, as SvelteKit configures `$lib`; the app's own Vite and SvelteKit configs are never run). All apps use an empty `div#root` and one module script; `index.html`'s `<html>` and `<body>` attributes (`lang`, `class`, `data-*`) become the document element's and the body's (M6; shadcn-svelte's style class is on `<body>`, where portalled content inherits it). Vite collects original sources (in a stable order, whatever order its concurrent transforms finish in: from the entry, each module before its static imports in source order and its glob entries in key order, depth first, then any other module by path; `tests/module-order.test.mjs`), ordered local CSS and WOFF2 assets (also those of a package stylesheet the app's stylesheet imports and Tailwind CSS inlines, such as `@fontsource-variable/geist/index.css`: each recorded from the one file inside the app Vite emitted it from, at most 1 MiB); inline HTML scripts are rejected. Imports of types only (`import type`, lists of `type` names) load nothing.

**Pinned images** (M6 steps 2, 4 and 5, [design](design/M6-IMAGES.md), `compiler/images.mjs`; the Svelte adapter reports the URLs of `<img src>` and every adapter those of `new Image().src`, below; React and Vue `<img>` report none yet and stay rejected). A lowered program may list the image URLs it can load; the builder pins each before validation:

- **`runic images <app>`** (`node compiler/cli.mjs images <app>`), the only networked step, never part of a build: it lowers the app without pinning, fetches each distinct http(s) URL once (redirects followed, 30 s timeout, aborted past 4 MiB), takes the type from the bytes (PNG, JPEG, WebP, GIF, SVG; a Content-Type naming another type fails, `application/octet-stream` or none is accepted) and writes `images/<sha256>.<ext>` and `runic.images.json` (`{ "format": 1, "images": [{ url, sha256, bytes, mime } | { url, status }] }`, sorted by URL, 2-space JSON) atomically. Both are committed with the app. A final non-2xx response is pinned as its HTTP status; a network error without a status, an oversized or empty body, an unsupported type or more than 32 MiB together fail the command, which then writes nothing. Pinned files the new record no longer names are removed; any other file in `images/` fails the command before it fetches. Without remote URLs it removes the record. The output is identical for identical responses.
- **Builds** read only the record and the files (`E_ASSET`, naming the command that fixes it): a remote URL without an entry (at the URL's source), entries for URLs the program does not load (at the entry), a missing file, a file whose size or SHA-256 differs from the record, a file whose bytes are not the recorded type, and files in `images/` the record does not name. The record and the files feed the source hash. Root-relative URLs (`/logo.png`, percent-decoded) name files of `public/` (Vite) or `static/` (SvelteKit) and need no record; the real path must stay inside the app. One that names no file there is `E_ASSET` unless the record pins it as a missing file, `{ "url": "/x.png", "status": 404 }` (what a static server answers; only 404, never bytes, and `E_ASSET` at the URL's source if the file exists); the build gives it that status, and `runic images` keeps such entries while the program loads the URL. Other URL forms (`data:`, relative, protocol-relative, other schemes) and root-relative URLs with a query, fragment, empty, `.` or `..` segment are `E_ASSET`. Image assets follow the fonts in `assets` (one per file) and `images` is sorted by URL; the backend reads their bytes from the app directory, checks size and SHA-256 again and embeds them as the app's `IMAGES` table.
- **`<img>` in Svelte** (M6 steps 4 and 5, case `images`, fixture `images-svelte`, `tests/images.test.mjs`): `src`, `alt`, `width`, `height`, `decoding` and other plain attributes, classes and `bind:this`, and `onload`/`onerror` handlers. `src` must have a finite set of string values known at build time: literals, a template of literal parts, or an expression whose value domain the language layer bounds (a conditional of literals, a variable of a literal union type); each value is reported with the attribute's source location and pinned as above. An open `src` (`{name}` of a `string`, a template with an expression) is `E_ASSET` at the attribute, as is one that may be a non-string; `null`/`undefined` values set no source. Spread attributes (M6, bits-ui's Avatar.Image: `<img {...mergedProps} {src} />`) are accepted where `src` is determined: a `src` attribute after every spread that may hold `src`, or the values the bags give `src` (frontend/bags.ts: object literals, rest props and the props passed to them, class members through their implementation), each spread's from the last, a spread that may lack `src` leaving it to the attribute or spreads before it; each value is reported with the spread's location, and an open one is `E_ASSET` at the spread. A spread that may give a rejected name below (`loading`, `srcset`, `sizes`, `crossorigin`) a value other than `undefined` or `null` (`false` too: Svelte sets it as the text `"false"`) is `E_TEMPLATE` at the spread; the runtime reports one unsupported should it arrive anyway. A `src` value passed on through component props (and through `boxWith` getters, method parameters and runed `watch` getters, frontend/packs/choice.ts) is followed to its literals; an open one is `E_ASSET` at the expression where it is open, naming the `<img>` or image object it reaches. Rejected at the attribute (`E_TEMPLATE`): `loading` (lazy loading changes when `load` fires), `srcset` and `sizes` (also a single candidate: the runtime loads `src` only), `crossorigin`, bindings other than `bind:this` (`bind:naturalWidth`, `bind:naturalHeight`); `<picture>` is outside the element list; `onload`/`onerror` on other elements is `E_EVENT`. The validator repeats these rules for IR from any frontend (`E_IR`; `load` and `error` listeners only as `<img>` attributes, never through `element.listen`, `document`/`window` listeners or bags). At run time, the document's base URL is `http://runic.invalid/` (root-relative sources resolve against it, as against Chromium's `http` origin, and the reserved name cannot collide with a pinned host); Blitz's requests are served from the `IMAGES` table only, matched after the same URL normalisation (`HTTPS://A.example:443/x` is `https://a.example/x`): a pinned image's bytes are decoded (PNG, JPEG, WebP and GIF, the `image` decoders runic-runtime enables; SVG through usvg, which the validator admits only in programs drawing inline SVG, the condition that links the runtime's `svg` feature; SVG images are not yet compared with Chromium), a pinned HTTP status fails the load, `data:` URLs decode as before, and any other URL is reported unsupported (`E_ASSET`, once) and never loads: no socket is opened. `load` and `error` are dispatched as Chromium does: non-bubbling, not cancelable, each as its own task (listeners, then the microtask checkpoint) in the order Blitz finished the loads, after the task that started them and before queued timers and other host tasks; one whose element's `src` changed since the load finished is dropped (Chromium cancels the stale load). Sizing follows CSS: `width`/`height` attributes as presentational hints, the intrinsic size otherwise, and `object-fit`.
- **`new Image()`** (M6, any frontend's script, lowered in `frontend/language.ts`; cases `bits-avatar` and `images`, `tests/images.test.mjs`): a host object, never in the document (IR type `image`, [IR](IR.md#types-and-values)). `new Image()` without arguments; assigning `src` with the same build-time rule as `<img src>` (each value reported at the assignment and pinned; an open value is `E_ASSET` where it is open), reading `src` (the URL resolved against the base URL, as Chromium reads it); `onload` and `onerror` (assigned functions or `null`, read back), `addEventListener`/`removeEventListener` of `load` and `error` with a function of no parameters (no options; other kinds `E_EVENT`). Setting `src` starts a load from the pinned table: its outcome (`load` for a decodable pinned image, `error` for a pinned HTTP status, an empty `src`, or bytes that do not decode) is dispatched as a task after decoding to the handler and the listeners in registration order (a handler keeps the position of its first assignment), then the microtask checkpoint. Each host-task round runs the queued image-object outcomes in the order their `src` was set, then the `<img>` events, before timers; setting `src` again before the outcome ran abandons it (as Chromium cancels the earlier load). An unpinned URL is reported unsupported (`E_ASSET`, once) and dispatches nothing; an SVG image is reported unsupported. `crossOrigin` and `referrerPolicy` are recorded and read back as Chromium 153 reflects them (`crossOrigin` `anonymous` or `use-credentials`, `anonymous` for any other string, `null` when unset; `referrerPolicy` one of the policy keywords or `""`); with no network and no canvas they change nothing else. Rejected (`E_MEMBER`, `E_CALL`, `E_ASSIGN`): `complete`, `naturalWidth`, `naturalHeight`, `decode()` and other members, constructor arguments, compound assignments. Ordering measured against Chromium 153 and where it differs: [gaps](gaps/PLATFORM.md#images-and-fonts-p7). The interpreter keeps an image object's state but loads nothing (reading `src` is `RunicUnsupportedError`); the differential reports programs setting `src` as incomplete.

Checked identities are React/React DOM 19.3.0, Vue/compiler-sfc 3.5.43 or 3.5.24, and Svelte/compiler 5.57.1 or 5.49.2. Runtime and compiler versions must match; other versions fail with `E_FRONTEND_VERSION`. Vite 8.3.2, TypeScript 5.9.3, plugin-vue 6.0.9 and the Svelte Vite plugin 7.3.1 are pinned tools.

CSS may use the selectors and properties accepted by the compiler and supported by Blitz's style engine; Blitz/Stylo renders them and conformance checks the result. `position: sticky` (CSS slice 1, Blitz and Parley forks, case `sticky`, [results](../conformance/results/sticky.md)) is laid out, painted and hit-tested as Chromium 153 does while its scroll containers and the document scroll: in nested scroll containers, in flex and grid items, on table row groups, rows and cells (their row group, row and column backgrounds move with them), with any of `top`, `right`, `bottom`, `left` (lengths, percentages of the scrollport without its padding, negative values), pushed by the end of its containing block, under transformed ancestors. A sticky ordinary inline box with an inset is reported at run time (Blitz keeps it in flow). At-rules other than `@font-face`, `@media`, `@layer`, `@property`, `@supports`, `@keyframes`, `@container` and `@charset "UTF-8"` (stylesheets are read as UTF-8) are rejected (`@starting-style`, …). Media queries on user preferences (Stylo and Blitz forks, case `media-preferences`) are evaluated as Chromium 153 does: `forced-colors` is `none` (Chromium on Linux never forces colors); `prefers-reduced-motion` and `prefers-contrast` have no preference, as in the harness's Chromium, and probes follow the emulated preference. Chromium on Linux takes these two from the desktop (GTK's animation setting; a high-contrast GTK theme), which a native app cannot read, so natively a rule under such a query is reported once it matches an element, and so is `matchMedia` of one. Vendor declarations Stylo drops are not reported where Chromium drops them too (every `-moz-`, `-o-` and `-ms-` property) or where a later declaration of their rule, at least as important, sets the property they name (Bootstrap's `-o-object-fit` before `object-fit`, `position: -webkit-sticky` before `position: sticky`). `text-shadow` other than `none` is reported where its rule matches an element (Blitz paints no text shadows) and rejected in keyframes. So are `columns`, `column-count` and `column-width` other than `auto`, in stylesheets and inline styles: Blitz lays out no multi-column layout. Container queries (M6, Blitz and Stylo forks, cases `blitz-container-queries` and `bits-dialog`) are size queries on `container-type: size | inline-size` containers (the `container` shorthand and named containers included), evaluated against the container's content box in the last layout: when a container's size changes, its descendants are restyled and laid out again in the same frame; a container has layout containment and an intrinsic inline size as if empty. Style and scroll-state queries and `container-type: scroll-state` are rejected (`E_CSS`, `E_CSS_PROPERTY`). Container units (`cqw`, `cqi`, …) are not supported: Stylo drops declarations using them, which the app reports once they apply (below). Transitions and keyframe animations (`transition*`, `animation*`, M6, [design](design/M6-LIBRARIES.md#animations), case `animations`) run on Stylo's engine at the runtime's timeline; `text-transform` takes `none`, `uppercase`, `lowercase` and `capitalize` (M6, Blitz fork, case `capitalize`), laid out as Chromium 153 does: `capitalize` titlecases the first letter of each word as Blink segments words, across inline elements, and leaves the other letters unchanged; shaping uses the transformed text, while the DOM and copied text keep the source text (differences: [gaps](BLITZ-GAPS.md)); rejected (`E_CSS_PROPERTY`): `full-width` and `full-size-kana` (Blitz transforms case only); `text-wrap-style` (and the `text-wrap` shorthand) takes `auto`, `stable`, `balance` and `pretty` (M6, Stylo, Parley and Blitz forks, cases `text-wrap-balance` and `text-wrap-pretty`), laid out as Chromium 153 does: `balance` balances the lines of a block container's first paragraph of at most six lines (Blink's score line breaker, else the bisection of the width), `pretty` rebreaks the last four lines of each paragraph whose greedy last line is a single word shorter than a third of the width (Blink's score line breaker, keeping the line count; the block container's value counts for both, not an inline's), `stable` breaks greedily as `auto` does; `balance` and `pretty` are reported where they reach a text area, whose text Blitz breaks greedily (reported, also inherited from a matched element; on `::placeholder` rejected, `E_CSS_PROPERTY`) (differences: [gaps](BLITZ-GAPS.md)); `field-sizing` takes `fixed` and `content` (M6, Stylo and Blitz forks, case `field-sizing`): with `content`, text areas and text, email, tel and url inputs are sized by their text as Chromium 153 does, or by their placeholder while that is shown (`rows`, `cols` and `size` ignored, min and max sizes clamping, a text area wrapping at the width it gets, at least the 1px caret), and grow and shrink as the text changes; `content` is reported where a rule with it (also through `var()` or `inherit`) matches a select or a search, number, password or file input, which Blitz does not size as Chromium does (differences: [gaps](BLITZ-GAPS.md)); `-webkit-line-clamp` with `display: -webkit-box` (or `-webkit-inline-box`) and `-webkit-box-orient: vertical` (Tailwind's `line-clamp-N`; M6, Stylo and Blitz forks, case `line-clamp`) is laid out as Chromium 153's legacy line clamp: the box is a `flow-root` (an `inline-block`) that counts the lines of its formatting context through in-flow blocks, and if anything follows the clamp line, that line ends in an ellipsis and the box and the blocks past the clamp point end after it (their own border and padding below; a fixed block size kept), later content clipped by `overflow` and kept in the scrollable overflow; text changes and resizes clamp again. Reported at run time where they occur (an app reports them once): a `-webkit-box` without vertical orientation and a clamp count (a legacy flexible box in Chromium), a clamp root that is a button, a right-to-left, bidirectional or not start-aligned clamp line, an atomic inline after the ellipsis, an ellipsis in a block without text of its own, a shortened block whose end margin collapses with its content's or with a percentage block size, and out-of-flow boxes past the clamp point; `-moz-box-orient`, which Stylo applies and Chromium ignores, is reported where its rule matches; the standard `line-clamp` is dropped (reported) (differences: [gaps](BLITZ-GAPS.md)); `animation-fill-mode` `forwards` and `both` (the pinned Stylo fork repairs finished-fill lifetime, but compiler and runtime acceptance guards remain), also where a `var()` can reach them through a value the stylesheet gives the custom property, `transition-behavior: allow-discrete`, and scroll-driven animations. Animation and transition events are rejected (`E_EVENT`); `element.getAnimations()` is a library DOM API (below). The compiler parses every stylesheet with Stylo and Blitz's preferences: a rule or declaration Stylo drops is rejected with its location (`E_CSS`, `E_CSS_PROPERTY`), except drops verified equivalent in Chromium (vendor pseudo-classes and pseudo-elements, `forced-colors`/`prefers-contrast`/`prefers-reduced-motion` media features, desktop-irrelevant vendor properties, `-webkit-font-smoothing: antialiased` and `-moz-osx-font-smoothing: grayscale`, which ask for the grayscale antialiasing both renderers always draw (other smoothing values stay reported; [M6-CSS](research/M6-CSS.md#properties)), and `resize`, whose grip Blitz never draws). A dropped declaration in a style rule whose selectors have no pseudo-element is not rejected: the app reports it as unsupported, with its location, once the rule's selector matches an element, so a library variant the page never uses costs nothing (`tests/collect.test.mjs`). Nor where it never applies (M6, bits-ui's Select): an element that a later rule of the same block, of at least the rule's specificity (Stylo's), setting the property also matches is not reported; and scroll margins only once such an element is scrolled into view (the runtime's focus never scrolls, and Blitz has no scroll snapping); scroll paddings (M6, bits-ui's Command list, `scroll-py-1`) only once a target inside such an element is scrolled into view where the padding would move it: a target aligned to the nearest edge and already inside the scrollport less the padding scrolls in neither, where the compiler knows the padding as a length (pixels or rem, through `calc(… * n)` and custom properties the stylesheet declares once). `filter` and `backdrop-filter` (M6, [research](research/M6-CPU-RENDERER.md), cases `filters`, `backdrop-filters`) take lists of the CSS filter functions (`blur`, `brightness`, `contrast`, `drop-shadow`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia`), drawn by both renderers (the forked CPU and GPU renderers, with the same semantics) and animatable; rejected (`E_CSS_PROPERTY`, also through `var()`): `url()` filter references. A `drop-shadow()` without a colour takes the element's `color`; opacity and filters apply to an element's outline, outer box shadows and overflowing content, and a backdrop is clipped to the rounded border box (Blitz fork, case `blitz-filter-layers`). A backdrop-filtered element with an ancestor that is a Backdrop Root (opacity, filter, clip-path, mask, mix-blend-mode) or also a `filter` stops a probe with `E_FILTER` (an app reports it once): Blitz draws them differently ([gaps](BLITZ-GAPS.md)). `mix-blend-mode` (all 16 values other than `normal`, `plus-lighter` included) and `background-blend-mode` (Blitz fork, case `blend`) are composited as in Chromium 153 by both renderers: a blended element is a stacking context and blends with what its nearest stacking context (isolation, opacity, a transform, z-index, filter, …; not an `overflow` clip) painted behind it (at the top level, the canvas and its background); on the root element it is ignored. A blended element that is a non-atomic inline box, SVG content, also backdrop-filtered, or below an ancestor that only Chromium makes a stacking context (`will-change`, `contain`, `container-type`, `backdrop-filter`, `perspective`, `transform-style: preserve-3d`) stops a probe with `E_BLEND` (an app reports it once) ([gaps](gaps/PLATFORM.md#css-and-rendering-p4)). Gradients are drawn as in Chromium (cases `gradients` and `blitz-gradients`: angle gradients on the background tile, colour stop fix-up, both fixed in the Blitz fork). The SVG painting properties `fill`, `stroke` and their `fill-*`/`stroke-*` longhands apply to inline SVG (Blitz fork, case `blitz-svg-css`), except paint servers (`url()`, also through `var()`); the other SVG-only properties (`marker*`, `paint-order`, `d`, `cx`, `r`, `x`, … ) are rejected (`E_CSS_PROPERTY`): Blitz would ignore them. `:target` selectors are rejected (`E_CSS`): Blitz never matches them; so are selectors giving an SVG child element (`path:hover`, `g:active rect`) a `:hover` or `:active` state, which Blitz never matches on SVG children (a class selector that lands on one cannot be found and still differs, [gaps](BLITZ-GAPS.md)). With `"tailwind": true` in runic.json, Tailwind CSS 4.3.3's Vite plugin generates the stylesheet, and its output is what these checks apply to. Resources must be bounded local WOFF2 files (`format("woff2")` or `format("woff2-variations")`); native builds require one embedded font. The IR (schema 5) lists them among its top-level `assets` and an `images` table of the pinned image URLs, which only the Svelte adapter's `<img>` fills so far (Pinned images above, [design](design/M6-IMAGES.md)).

**Inline styles** (CSS slice 1b, `runic_css::inline`, `tests/inline-styles.test.mjs`): `style` attributes, Svelte `style:` directives, React and Vue style objects, style spreads and script writes (`style.cssText`, `element.style[name]`) get the declaration checks stylesheets get, for the one element they style. A literal declaration a stylesheet would be rejected for (fill modes `forwards`/`both`, scroll-driven animations, `allow-discrete`, filter functions the renderers do not draw, images in `content`, `text-transform: full-width`/`full-size-kana`, SVG paint servers and SVG-only properties) is `E_CSS_PROPERTY` at the element. One a stylesheet would report where its rule applies (a declaration Stylo drops and Chromium 153 parses, unless verified equivalent or overridden later in the same style; `-moz-box-orient`; `text-shadow`; `text-wrap: balance`/`pretty` on a text area; `field-sizing: content` on the controls Blitz does not size so), and every declaration known only at run time, is reported unsupported when the style is set (the runtime and the interpreter alike). A drop is equivalent, in stylesheets too, where Chromium 153 is shown to drop the declaration as well: a property it does not parse (`crates/runic-css/src/chromium-properties.txt`), or a value of one identifier it accepts neither as a keyword of the property nor as a custom ident (`crates/runic-css/src/chromium-keywords.txt`; bits-ui's floating layer spreads `z-index: undefined`), both measured by `conformance/chromium-properties.mjs`; any other value Stylo drops is reported. Values through `var()` are checked as written.

**Rules no element can match** (D17, `tests/unmatched.test.mjs`; `crates/runic-ir/src/facts.rs`, `crates/runic-css/src/unmatched.rs`, `skipUnmatchedRules` in `compiler/collect.mjs`). A style rule the checks above reject (a rejected selector, a rejected or Stylo-dropped declaration in it) is not rejected when no element of the program can ever match the rule: it has no effect, so the compiler leaves every rule of that selector list out of the shipped stylesheet (Stylo never meets it), adds a style guard that reports the program unsupported should an element match the selectors without their pseudo-elements after all, and lists the rule in the build report (`skippedRules` in `build.json` and in the `analyze` command's summary: selector, location, the rejection and why no element can match). Rejections that belong to no style rule's selector stay immediate: at-rules, `@font-face` and `@property` descriptors, keyframes, the checks of authored component styles before scoping. The proof has two parts:

- **Element facts** (`runic_ir::facts`): an over-approximation of the tags, class tokens, attribute names and attribute values any element may carry at any time, from the lowered program of every component (reachable or not). A flow-insensitive abstract interpretation iterated to a fixpoint gives every location (cell, local, global, function result, record field and array element by type, attribute bag entry by name, context) the set of primitive values it may hold, or *any*: call results through function values, most built-ins, event payloads, handler parameters, parameters of functions called through values, arithmetic, and the fields of records the runtime creates are *any*; sets larger than 256 are *any*; a type the analysis cannot infer makes every fact open. The facts are read from template elements and slot content (static attributes, attribute and class expressions, class toggles, live properties), spreads and rest props (every bag entry name other than `on*`, with its values; a bag built-in the analysis does not model makes every name possible), `{@html}` fragments, `element.setAttribute` and the document element and body built-ins, and the elements the runtime and Blitz create: the document shell (`html`, `head`, `style`, `title`, `body`, the container `div` and the attributes `index.html` or `app.html` give them), the select popup, a file input's button and label, `checked`/`value` on inputs, `open` on `details` and `dialog`. An attribute or class written from *any* value makes that attribute's values, or all class tokens, *any*; a name written from *any* makes every attribute name and class possible. Only the inline `style` attribute's presence counts.
- **Selector decision** (`runic_css::unmatched`): the selector list parsed by Stylo is unmatchable when every complex selector contains, in some compound outside `:not()`, `:has()` and other pseudo-classes, a type, class, id or attribute selector no element can carry (compared ASCII case-insensitively; attribute operators against the known values); `:is()` and `:where()` count only when all their arguments are unmatchable; a pseudo-element counts through its originating compound; combinators and every other component add no proof, and a list Stylo does not parse is never proven. Both parts err towards "may match": a rule that might match is checked and rejected as before.

## Language

Every adapter lowers ordinary code through the shared layer. TypeScript's checker supplies types; in untyped JavaScript the frontend infers IR types from the lowered values and specialises untyped helper functions per call-site argument types.

**Values** ([value model](design/M2-VALUES.md)): numbers with exact double semantics; UTF-16 strings; booleans; `null`/`undefined` and nullable types (`T | null | undefined`); string/number/boolean literal unions (a primitive intersected with empty object types, `string & {}`, is that primitive, also as a union member: svelte/elements' `HTMLInputTypeAttribute`; a branded or other non-empty intersection is not one); objects with a fixed shape (records); arrays; `Map`/`Set`; functions and closures. Class instances (below). Other unions, `any`/`unknown` that cannot be inferred, symbols (except module-level `Symbol(…)` constants used only as Svelte context keys, which have no runtime value: Svelte, below), bigint and tuples with optional or rest elements are rejected with `E_TYPE_UNSUPPORTED`/`E_TYPE_UNION`. M6 overlays: a tuple of items of different types (a `Map`'s entries) is read by literal index and destructuring; its length, iteration, spreads, string conversion, `JSON.stringify` and `Object.keys/values/entries` are rejected (JavaScript treats it as an array).

**Statements and expressions:** `const`/`let`, assignment and compound assignment to locals, cells, fields and array elements; `if`, `switch`, `while`, `do`/`for`/`for-of` with labelled `break`/`continue`; functions, arrow functions and closures (captured variables are shared by reference); `return`, `throw`, `try`/`catch`/`finally`; template literals; object/array destructuring and spread; optional chaining and `??`; all arithmetic, bitwise, comparison, logical and `typeof` operators; `Number`/`String`/`Boolean` conversions.

**Parameters with defaults** (`function f(x: number, y = x + 1)`; case `default-parameters` in Svelte and React, `tests/default-parameters.test.mjs`): a caller may leave such a parameter out or pass undefined, so its type in the function's IR parameter list and in function types is nullable (`maybe<T>`, as TypeScript types it for callers), and the body binds its name to a local of TypeScript's type inside the function holding the argument or, where it is undefined (not null), the default. Defaults are evaluated when the call runs, left to right (destructured parameters in their place), and may read the parameters before them; one reading its own or a later parameter is rejected (`E_FUNCTION`; JavaScript throws a ReferenceError), as is a function in a default that refers to a later parameter (which JavaScript allows). This holds for direct calls, function values (a function value where a function type taking fewer arguments is expected, or passing values where its parameters may be undefined, is called with undefined for the parameters left out: `const g: (x: number) => string = f`, also as a module constant or a component constant), callbacks given to packs (runed's `watch` passes undefined as the first previous value), methods, constructors and `super(…)` (arguments first, then the defaults), and untyped JavaScript specialised per call site (a left-out argument whose default TypeScript types is passed undefined). A function expression whose context's function type always passes the parameter a value that is not undefined (`[…].map((v, i = 0) => …)`) keeps its type: its default never applies. A method called through a receiver TypeScript types `any` (untyped JavaScript specialised per call site) is passed undefined for the parameters it leaves out that may be undefined.

**Arrays of several types joined at once** (`tests/array-join.test.mjs`): an array literal of numbers, strings and booleans (nullable ones too) of several types that is joined where it is written (`[count, label, done].join(' ')`) is joined as JavaScript joins it: the elements in order, then the separator (`,` where it is left out or undefined), each element converted by ToString, null and undefined as the empty string. Such a literal used otherwise is rejected at its element (`E_ARRAY`: an IR array holds one type); a separator that is not a string, and elements of other types, are rejected (`E_CALL`).

**Built-ins:** `Math`, `Number`, string and array methods, `Array.from`/`isArray`, `Object.keys/values/entries/assign`, `JSON.stringify`/`JSON.parse` into a declared type, `Map`/`Set` and `structuredClone`, as listed in [M2-VALUES](design/M2-VALUES.md). `RegExp` with ECMAScript semantics (literal and constructed patterns, flags `dgimsuy`; `exec`, `test`, `match`, `matchAll`, `replace`, `replaceAll`, `search`, `split`; `v` and the static members are rejected). `Date` (construction, `Date.now/UTC/parse` as V8 parses, all getters and setters in local and UTC time, the string and ISO forms) in the case's or system's time zone. `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.Collator`, `toLocale*String` and `localeCompare` for en-US, en-GB, de-DE, fr-FR and ja-JP (and en, de, fr) with the option combinations pinned by Chromium vectors; other locales and options are rejected (`E_INTL`). M6 (case `plural-names` in Svelte, React and Vue): `Intl.PluralRules` `select(n)` and `resolvedOptions().pluralCategories` (and `.type`), cardinal and ordinal (`type`), for every locale Chromium has plural rules for (its own ICU data: a tag without rules of its own takes the default locale's, as Chromium does); `Intl.DisplayNames` `of(code)` for the types `region`, `script`, `currency` and `language` (dialect names such as "American English", or `languageDisplay: "standard"`), `fallback` `code` or `none`, in the display locales en-US, en-GB, de-DE, fr-FR, ja-JP, en, de, fr and ja. Language tags are a language with an optional script and region, canonicalized as V8 does (`iw` is Hebrew); a malformed tag throws a `RangeError` as in Chromium. Their locales may be computed at run time (and their options chosen by a condition, `ordinal ? { type: "ordinal" } : undefined`) where the object is constructed at its use (`new Intl.PluralRules(locale).select(n)`); constants need literal locales. Rejected (`E_INTL`): digit and rounding options of plural rules, `selectRange`, `resolvedOptions()` members other than those, other display name types and styles, unverified literal display locales; at run time, an unverified display locale, variants and extensions (`en-u-nu-arab`) and regions that alias several regions (`SU`) are reported unsupported (`RunicUnsupportedError`, which a probe or the interpreter does not let a program catch silently). Identifiers resolve by symbol, so a local `Math` shadows the global one. Unknown globals and methods are rejected (`E_UNRESOLVED`, `E_MEMBER`, `E_BUILTIN`).

**Time and async:** `setTimeout`/`setInterval`/`requestAnimationFrame` and their `clear`/`cancel` functions, `queueMicrotask`, `Date.now()` and `performance.now()`. `Promise<T>` with `new Promise`, `Promise.resolve/reject/all` and `then`/`catch`/`finally`, in ECMAScript's microtask order (adopting a returned promise costs two ticks). `async` functions and arrows, including event handlers: `await` as a statement, in `const x = await e`, `x = await e` (and `this.field = await e`, M6), `x op= await e` and `return await e`, inside `if`, loops, `for-of` over arrays and `try`/`catch`. Rejected: `await` nested in other expressions or conditions, `finally` around an `await`, `for await`, generators, and closures capturing a loop variable across an `await` (`E_ASYNC`). Rejection reasons are Error records. Unhandled rejections (M6, cases `rejections` and `rejections-timer` in Svelte, React and Vue) are reported as Chromium reports them: a console error line `Uncaught (in promise) Name: message` (`Name` alone for an empty message) in a task after the microtask checkpoint that left the promise without a handler, for each promise still without one then, in rejection order; the program cannot observe it. A handler added after the report (Chromium revokes it) is reported unsupported. Vue catches a promise a listener returns and logs it with `console.error` (its production `callWithAsyncErrorHandling`), so it is not reported unhandled.

**Host services:** `localStorage.getItem/setItem/removeItem/clear` (native apps keep it in `$XDG_DATA_HOME/runic/<title>/localStorage.json`; `key()`, `length` and the `storage` event are rejected); `console.log/info/warn/error/debug` with primitive arguments (stderr natively; format strings rejected); `navigator.clipboard.writeText/readText` (the OS clipboard natively); `history.pushState/replaceState` with a null state, `back`/`forward`/`go(n)`, `history.length`, `location.pathname/search/hash` and assigning `location.hash`, with `popstate` and `hashchange` on the window; `Math.random` and `crypto.randomUUID`. The document element (`dataset`, `classList`, `style.setProperty/removeProperty`, `lang`, `dir`), `document.body` and `document.querySelector` of the literal selectors `body` and `#id` (M6), and `matchMedia(q)` / `window.matchMedia(q)`: `matches` and `change` listeners for `prefers-color-scheme`, `prefers-contrast`, `prefers-reduced-motion`, width, height and orientation. Templates and derived values must not use host services (`E_REACTIVITY`).

**Reactivity checks** (all frameworks): a template must not read a value that changes without the framework noticing, which the frameworks would show only when neighbouring state re-renders: a non-reactive variable that is written, a reference tracked by identity but mutated in place, a `Map`/`Set` mutated inside Svelte state, a mutated module object, a RegExp whose `lastIndex` changes or a Date changed by a setter (`E_REACTIVITY`). React state and props must not be mutated in place (`E_READONLY`).

**Classes** (M6 stage A, [design](design/M6-LIBRARIES.md#library-code-steps-3-to-6), case `classes`): class declarations at the top level of local modules and of Svelte and Vue component scripts (React components use module-level classes), in TypeScript or in JavaScript whose fields TypeScript can type (annotations, JSDoc, initialisers). Instance fields with and without initialisers, TypeScript parameter properties, fields the constructor creates by assignment, `#private` fields and methods, methods, getters and setters (compound assignments call both), static methods and static fields (module classes only; constants), `new C(…)`, `this` in methods, accessors, constructors, field initialisers and the arrow functions inside them, and `x instanceof C` (decided by the static type of `x`: by the class a class reference's instance carries, subclasses included, false for null and undefined; also where TypeScript types `x` `any` or `unknown`, an untyped helper's parameter specialised per call site, by its IR type, which then must be a class instance or a primitive, which no class has: bits-ui's `isCalendarDateTime(dateValue)` given the `@internationalized/date` pack's `DateValue`, `tests/untyped-instanceof.test.mjs`; there a test the IR type decides keeps its one branch). A method is a value only when bound: `this.m = this.m.bind(this)` at the start of the constructor makes `m` a field holding a bound function, `obj.m.bind(x)` creates one, and arrow function fields keep their instance; `f.bind(x)` of a function value makes a new function (`x`, which it ignores, is `this`, `null`, `undefined` or a variable). Methods dispatch on the class of the receiver (statically where its type names one class; see inheritance below). An instance is built as JavaScript builds it: field initialisers in order, the constructor's leading `this.f = …` assignments, then the rest of the constructor; before the instance exists, `this` may only be read as an earlier field, inside an arrow function stored whole in a field, or bound. Svelte `$state` holds instances as they are (no proxy), so mutating one that the template reads is `E_REACTIVITY`; Vue refs proxy them as Vue does. **Generic classes** (M6 overlays, bits-ui's `TimeoutFn<T>`; `tests/generic-classes.test.mjs`) take the one instantiation of the program: the type arguments of every `new C(…)` and `C<…>` must map to the same IR types, and the type parameters stand for them in the class (parameter types are TypeScript's instantiated signatures, so `...args: Parameters<T> | []` is resolved; inside the class `Parameters<T>` of a type parameter bound to a function type is its parameters, and calling a value of type `T` takes its IR function type). A type parameter no member mentions (`TooltipTether<Payload = never>`) is left unbound. Rejected: a second instantiation (`E_CLASS`, at its site; compiling per instantiation is not implemented), an instantiation with a type parameter, and a generic class never instantiated with type arguments. Rejected (`E_CLASS`): anonymous classes, class expressions, decorators, `accessor` and `declare` fields, computed and quoted member names, overloads, static blocks and accessors, unbound method references, other uses of `this` before the instance exists, `return` in constructors, fields not set before the constructor otherwise uses `this` (unless optional), use before the declaration, `JSON.stringify`, `structuredClone`, `Object.keys/values/entries/assign`, spreads and string conversion of instances, object literals typed as a class, `instanceof` on values of unknown type whose IR type is no class instance or primitive (caught exceptions, dynamic values), assigning static fields, static fields of component-script classes, partial application with `bind`, and Vue refs of classes whose constructor keeps the raw `this` in closures (arrow function fields, bound methods), whose writes Vue's proxy would not see.

**Reactive class fields** (M6 stage B, [design](design/M6-LIBRARIES.md#reactive-class-fields-stage-b), case `reactive-classes`): in Svelte component scripts and `.svelte.ts`/`.svelte.js` modules (where Svelte compiles runes; components import them with the full name, `./todos.svelte.ts`), a field initialised with `$state(v)`, `$state.raw(v)`, `$derived(e)` or `$derived.by(f)`, public or `#private`, or a field the constructor assigns one of them as a leading `this.f = …` statement. They behave as Svelte 5.57.1's signals: reading one is a dependency of the running `$effect` or derived value (unless that computation created the instance), and the template updates after writes. A write notifies when the new value is not `===` the old one (`-0` over `0` changes nothing and keeps `0`; `NaN` over `NaN` notifies); `$state` stores proxies of plain objects and arrays (deep state, as component `$state`), `$state.raw` and class instances are stored as they are. Derived fields are computed from the instance when first read, cached until what they read changes, and keep their value when a recomputation gives an `===` one, so effects reading them re-run only when it changed. Instances can live in component constants, state, other instances' fields and module constants. Rejected: assigning a derived field (Svelte 5.25+ overrides), `$derived` in the constructor reading the constructor's parameters or locals, reactive fields assigned after the constructor otherwise uses `this`, runes in plain `.ts`/`.js` modules and in React and Vue code (`E_CLASS`); writing reactive state from a template expression or a derived value, directly or through the functions they call, unless that code created the instance (Svelte throws `state_unsafe_mutation`), derived fields that change values they did not create or use host services, template reads of `$state.raw` values mutated in place and of plain fields written after construction (`E_REACTIVITY`); reading a derived field of a component-script class in another component.

**Inheritance and class references** (M6, [design](design/M6-LIBRARIES.md#inheritance-and-class-unions), case `class-hierarchy` in Svelte, React and Vue): single inheritance (`class B extends A`) between classes compiled from source, declared in the same module scope or component script. An instance has its base classes' fields first. Construction follows JavaScript: the statements before each `super(…)` (which must not use `this`) and its arguments from the class up to the root, then from the root down each class's parameter properties, field initialisers and the rest of its constructor; a class without a constructor passes its arguments on. Methods, getters, setters, static methods and static fields are inherited and can be overridden; `super.m(…)`, `super.x` (a getter) and `super.x = v` (a setter) call the base class's member; `#private` names belong to the class declaring them (a subclass may declare its own of the same name). Abstract classes, abstract methods and abstract properties (implemented by the subclasses' methods and fields); reactive fields (`$state`, `$derived`) in base classes and subclasses. A value TypeScript types as a class that has subclasses, or as a union of classes, keeps its instance's class: a member its classes declare differently (overrides, abstract members, a field each class of a union declares) is chosen by that class; `instanceof`, discriminant checks (`x.kind === 'single'`) and `as` assertions narrow it, and an assertion TypeScript cannot check (`as unknown as C`) throws a `TypeError` where the instance is of another class (JavaScript would continue with the wrong object). Every class of the program's sources is known, so a class's subclasses are all its subclasses there. Rejected (`E_CLASS`): extending library classes (`Error`, `MediaQuery`; mapping packs will provide them), mixins and other base expressions, generic base classes, `super(…)` other than as one statement at the top level of a constructor, `this` before `super(…)`, `super.x` of a field (JavaScript reads the prototype) or of an abstract member, redeclaring an inherited field (except without an initialiser, assigned at the top of the constructor before it otherwise uses `this`: bits-ui's `opts` of narrower options types, which then share one record with the types constructors pass on to the base; a field only some of them have is read through a type that has it, a `TypeError` if the program broke its types; and except a plain data field declared again with an initialiser of a type the base field takes, where no rune initialises either and no class of the chain has an accessor or method of the name: bits-ui's SliderMultiRootState `getAllThumbs`, assigned in its place among the subclass's field initialisers, as JavaScript's [[Define]] of the existing own data property sets it; rejected where a base constructor's code after it uses `this` may read it before it is set, below), extending a class of another module scope or component script, a base constructor that uses `this` beyond its leading field assignments when a subclass declares fields (JavaScript would run that code before the subclass's fields exist; covered where nothing can tell: every field the subclasses declare, and every base field they declare again, is a literal, `$derived`, a whole arrow function or `$state` of a literal, whose creation has no effect and reads nothing, and that code reaches the instance only through base fields no subclass declares again, also inside the arrow functions those fields hold, which a callee may call at once, or in `$effect`s; bits-ui's SliderSingleRootState and SliderMultiRootState, whose base constructor ends with `new SvelteResizeObserver(() => this.opts.ref.current, this.#handleLayoutChange)`; the fields then exist from the start), assigning through a union a field its classes declare separately, binding a method that subclasses override through the base type, and arrays, maps, sets and functions of a subclass type used as ones of the base type (they keep their identity).

**Object keys** are observable (`Object.keys`, `JSON.stringify`), so a record keeps the key order of the literal that creates it; a spread contributes its source's keys in their order. A literal whose properties are in a different order than its declared type is rejected (`E_OBJECT`). The objects of an array literal that list their keys in different orders (shadcn-svelte's combobox `countries`) share one record whose key order is not tracked, built by name: `JSON.stringify` of a value holding it, and `Object.keys`/`values`/`entries`/`assign` of it or of an object spread from it, are rejected (`E_OBJECT`), checked again with the finished program. A subclass field declared again with an object of the base field's shape is built in the base field's key order; one whose objects differ from the base field's in key order or in being implemented with getters is rejected (`E_OBJECT` at a literal, `E_CLASS` otherwise). `null!` is null where the IR type there holds null: `$state<HTMLButtonElement>(null!)` (the combobox examples' trigger refs, set by `bind:this` or `bind:ref`) or a variable of an element type; reads through it throw a `TypeError` while it is null (`tests/ir-errors-null-refs.test.mjs`). Elsewhere it is `E_TYPE_UNSUPPORTED`.

**Modules:** components can import named bindings from local `.js`/`.ts` modules, with aliases, export lists and named re-exports, and import other components (`.svelte`, `.vue`, function components). Modules initialise once, dependencies first. The constants of package modules (packages compiled from source and pack ports), which are created when code first reaches them, are initialised before every program constant whose initialiser reaches them, directly or through the functions it calls, as JavaScript evaluates a package before the modules importing it (`export const d = new CalendarDate(…)` reads the `@internationalized/date` port's month tables; `tests/package-global-order.test.mjs`, case `default-parameters`). Module functions become shared functions; constants become program globals, evaluated once in order (object constants keep their identity). Module objects may be mutated (they are not reactive). Barrels (M6, [design](design/M6-LIBRARIES.md#library-modules-step-3), case `shadcn-basics`): `export { default as X } from './x.svelte'`, `import Root from …; export { Root, Root as Button }`, `export *` and `export * as N`, chained through any number of modules, and names a module re-exports from a package (`export { cn } from "cn"`), which keep the package's [pack](#packages). Namespace imports (`import * as Card from …`) name components as tags (`<Card.Root>`, Svelte) and may be re-exported; using a namespace as a value is rejected (`E_IMPORT`). Top-level statements (other than [module state](#language)), default imports of plain modules, cycles, `export *` of a package and npm dependencies without a mapping pack are rejected (see [Packages](#packages)).

**Library code (M6):** objects whose TypeScript type has only a string index signature (and constant keys of its value type) are dictionaries (maps), read and written by key, also with computed keys; reading a key that names a member of `Object.prototype` (`toString`, …) or writing `__proto__` throws `RunicUnsupportedError`. A record read with a computed key of its field names (`{ horizontal: …, vertical: … }[orientation]`). Unions of plain object types are one record (key sets untracked: key-observing built-ins reject it). `Object.is`. Tests the IR types decide in untyped package code (`Array.isArray(x)`, `typeof x === "…"` of a local) keep their one branch; callbacks of array methods in untyped code take the element type; parameters typed `unknown` are specialised per call site; an untyped `let x;` takes the type of the values assigned to it. Methods bound into their fields later in a constructor (`this.m = this.m.bind(this)` after other statements) are bound when the instance is built, when nothing before reads them other than by calling them.

**Module state** (M6 overlays, `tests/module-state.test.mjs`; bits-ui's scroll lock and keyboard tracking): a `let` at the top level of a local or package module is state that lives as long as the program, initialised in order with the module's constants, read and written by its functions (also through `export let`, a live binding). Except a component prop whose value calls code that advances module state (bits-ui's id counter `globalThis.bitsIdCounter` through `useId()`, shadcn-svelte's CommandGroup ``value ?? heading ?? `----${useId()}` ``; case `id-counter`, `tests/memo-props.test.mjs`): Svelte 5.49.2 memoizes such a prop in a derived value that the child's `$.prop` computes once, where it declares the prop, and never again when it read no signal; the frontend models it as a derived function of the parent instance (`frontend/memo-props.ts`) where that is provably the same point in the counter's order: the value reads no state and writes only primitive fields of plain module records, the component sits at the top level of its parent's template (not in `{#if}`, `{#each}`, `{#key}` or a snippet), the child declares the prop with a default or `$bindable` and nothing it runs before that declaration names the counter, the counter never escapes as a value, and the program has `$state` proxies or reactive class fields (so a derived value does not track the plain record). **Build-time conditions** (M6): a condition whose value is known at build time (literals, constants of packs such as esm-env's `DEV`, module constants of packages compiled from source evaluated at build time, `typeof` of the host's globals, which are objects natively, and `!`, `===`, `!==`, `==`, `!=`, `&&`, `||`, `??` over them) decides `if`, `?:`, `&&` and `||` at build time: the branch never taken is not lowered (it never runs), so code only a development build runs is not rejected. In package modules: recursive functions are typed from their calls outside themselves (and a called function giving one of their arguments from its calls), an empty object passed says nothing about a parameter's type, a module's own runed `Context` takes the type of what it sets, and the calls of a method through its declaration file's class count for its implementation (`this.root.setState("search", …)`). `structuredClone` (and `$state.snapshot` in package code) copies maps and sets in plain data. Subclass fields of literals or `$derived` values exist from the start where the base constructor, after using `this`, reaches only fields of the classes above them (or does so in effects). A bare `return;` in a function that returns values returns undefined. **Values typed `any` in the Calendar, InputOTP, Sonner and Checkbox examples** (M6; `tests/untyped-sites.test.mjs`): the host declarations (`frontend/dom.d.ts`) give @types/node's `NodeJS.Timeout`, which bits-ui's declaration files write for what `setTimeout` returns, as `number`, what the browser's timers return; and lib.dom's autofill tokens (`AutoFill` and its parts, TypeScript 5.9.3's declarations unchanged), by which svelte/elements types `autocomplete` (strings). **Language of the Slider and PinInput** (M6; `tests/slider-pin-input.test.mjs`, `crates/runic-js/tests/number.rs`):

Other array-like objects, a this argument and other mapping functions are rejected (`E_BUILTIN`).

- A package function returning, as its last statement, a `const` object literal it then fills (`getThumbStyles`' `const style = { position: "absolute" }`) types the literal by the declared result.

**Dynamic values** (M6 spike, opt-in with `runic.json` `"dynamicValues": true`, Svelte only; [design and results](design/M6-DYNAMIC-VALUES.md), adopted as an opt-in: D16 amended). A value a static rule types keeps that type (a union of object types as a merged record or narrowed by the values reaching it, a literal of computed keys from a finite set of names as an attribute bag, host globals, a DOM method's declared result where TypeScript says `any`), so the example census lowers a superset of the examples it lowers without the opt-in ([results](../conformance/results/shadcn-svelte-census-dynamic.md): 264 against 261). Static values are boxed with their type (keeping identity) where they meet dynamic ones; a dynamic value reaching a static type is checked and throws `RunicUnsupportedError` when it does not fit, never coerced. A dynamic object reaches a record type as a copy only where the validator proves the copy unobservable (`E_DYN_COPY`); a dynamic value in state changed in place is rejected (`E_REACTIVITY`); a dynamic class value must be a string. Methods called on dynamic receivers are implemented in `runic-js` for a subset and not verified by a case ([gap register](gaps/LANGUAGE.md#dynamic-values-opt-in-spike)). Verified by `tests/dynamic-values.test.mjs` (also: a program the static rules type lowers to the same IR with the opt-in), cases `dyn-values` and `bits-pagination`, and the differential (fixtures `dyn-values-svelte` and `dyn-mismatch-svelte`, the latter differential only: there the browser carries on with the mistyped value).

**Outside M5:** generators, getters and setters in object literals (except objects of a declared type whose properties are getters or constants), `in`, `instanceof` other than of classes, `HTMLElement`, `Element`, `Node` and `Date` (decided by the IR type: values of the `date` type are the Date objects, so a test of another value folds at build time and keeps its one branch, bits-ui's `getDaysInMonth(date)`; of a dynamic value it is rejected), rest parameters other than a callback's or of a tuple type, logical assignment, string literals containing lone surrogates, typed arrays and npm dependencies other than the [mapping packs](#packages) (M6).

## React

The entry calls `createRoot(document.getElementById('root')).render(<App />)` for a local function component. Every function component is a component with instances: a rendered `<Child/>` gets its own state, created and destroyed with its region (a conditional branch, a list item), so state resets on remount. A component body holds `useState` declarations (non-lazy initialisers), const render values, nested functions and one returned JSX tree; expression-bodied arrow components are accepted. Reads see the render snapshot of the last commit, and closures created in a handler or effect keep the snapshot they were created with (stale closures). Setters with values or updater functions queue in order; discrete events (click, input, change, keydown) render in a microtask, other updates (timers, promises, effects) in a later task.

- **Props:** destructured or through a `props` parameter, typed by TypeScript or, in JavaScript, by the first call site. Callbacks are function props. `children` and other `ReactNode` props rendered as `{children}`, and render props `(x: T) => ReactNode` called as `{row(x)}`, are slots evaluated in the parent.
- **Lists:** `items.map(item => <Row key={…}/>)`, keyed or (without a key) by index, with React's forward-placement reorder; React DOM's focus restore after a commit is reproduced. A `key` elsewhere remounts its element when it changes.
- **JSX:** the native tag allow-list (with `textarea`, `label`, `select`, `option` and inline SVG, below), string and expression attributes (entities decoded), `className`, inline `style` objects (keys written inline, set through the CSSOM as React DOM does), `&&`/`?:` conditionals, fragments, rest props and spread attributes (`{...rest}`, listeners included) and refs passed as props.
- **Events:** event objects (`type`, keys and modifiers, pointer coordinates and buttons, `target`/`currentTarget`, `preventDefault`, `stopPropagation`) for submit (`onSubmit`, common FormEvent operations), click, double click, context menu, key, pointer, mouse and focus events (`onFocus`/`onBlur` from `focusin`/`focusout`, with `relatedTarget`); continuous events (pointer and mouse moves, enters and leaves) only where React's later render is unobservable; `onScroll` (M6, React's continuous lane, cases `scroll-lane` and `virtual-list` with the React virtualized list): its updates render in a default-priority task after the frame (after the listener's microtasks and the frame's ResizeObserver notifications), and a discrete update before that task renders them with its own, as React does; timers posted by a scroll listener are rejected (Chromium runs them before that render); window and document listeners. Controlled text inputs, text areas (`value` with `onChange`), checkboxes, radio buttons (`checked` with `onChange`, exclusive named groups) and selects (`value` with `onChange`), restored after every dispatch as React DOM does. `onWheel` is rejected.
- **Refs:** `useRef<HTMLInputElement | null>(null)` attached with `ref={r}` to one element of the same component; `r.current` reads the live element (`focus()`, `blur()`, null checks). `useRef` of numbers, strings and booleans is a mutable box that never re-renders. Callback refs, refs passed to components, one ref on several elements, refs in list items or slot content, ref reads during render and refs holding objects are rejected.
- **Effects:** `useEffect` and `useLayoutEffect` with no dependency array, `[]` or a literal array of values; their functions and cleanups read the render that created them. Layout effects run after the DOM update children first; all cleanups of a phase run before its effects; passive effects' state writes render in a later task; unmount cleanups run parent first, layout before DOM removal and passive after.
- Rejected: effects outside the component body's top level or in custom hooks (`E_HOOK`), non-literal or spread dependency arrays and object or function dependencies other than state and props, async effect functions, microtasks queued in layout effects, `useInsertionEffect`, `useMemo`, `useCallback`, lazy initialisers, conditional or list regions whose unmount cleanups React would order by element position, nested prop destructuring, style strings and computed style keys, `select multiple`/`defaultValue`, controlled controls without `onChange`, `focus()` outside discrete event handlers where focus listeners exist, recursive components.

## Vue

The entry calls `createApp(App).mount('#root')` on a local SFC with `<script setup>` (JS or TS). Setup supports `ref`, `computed`, functions, const values and local module imports; `ref` reads see earlier writes immediately and nested mutation is tracked, also read through a constant or object holding the ref's contents (case `alias-vue`) and written through a constant, a function parameter or a function result whose every source is the ref's contents (case `alias-writes-vue`); a raw object a ref holds, changed through another reference, is rejected (`E_REACTIVITY`: Vue tracks writes through the ref's proxy only; case `raw-target-vue` in Chromium). `computed` values are cached and recompute when what they read changed. Templates support the tag allow-list, static attributes, `:attr` bindings, `:class` (objects, arrays, strings, normalised and merged with a static class) and `:style` (objects, arrays, strings, applied as `patchStyle` does), interpolation and `v-if`/`v-else-if`/`v-else`. Fallthrough attributes and `v-bind="$attrs"`/object spreads are applied as Vue merges them. Vue marks `#root` with `data-v-app`.

- **Components:** child SFCs are instances. `defineProps<T>()` (destructured or as an object, optionally with `withDefaults`), `defineEmits<T>()` (as `on<Event>` callbacks) and `defineModel<T>()` with the parent's `v-model`.
- **Lists:** `v-for` over arrays with `:key`, keyed or by index, with Vue's longest-increasing-subsequence reorder.
- **Slots:** `<slot>` outlets (default, named, scoped, with fallback), typed by `defineSlots<T>()` or inferred; `<template #name>`, `v-slot` and default content in the parent, with destructured slot props.
- **Events and forms:** event objects for submit (`@submit`), click, double click, context menu, key, pointer, mouse and focus events (`@focus`, `@blur`, `@focusin`, `@focusout` with `relatedTarget`), with `withModifiers`/`withKeys` modifiers; several listeners of one event run in order. `v-model` and `:value` on text inputs and text areas (re-applied at every re-render where they differ, as Vue patches them), `:checked`/`v-model` on checkboxes, `v-model` on selects and radio buttons with literal values. `@scroll` is a native listener on the element (as Vue adds it); `.once`, `.capture` and `.passive` are rejected.
- **Refs:** `ref="name"` on an element (or a component that forwards it) bound to a `ref()`/`shallowRef()` of that name or to `useTemplateRef<T>('name')`; the ref holds the element while it is mounted and `null` after removal. Refs read during rendering, writes to template refs, `:ref`, refs in `v-for` or slot content and refs on components, slots or `<template>` are rejected.
- **Watchers and lifecycle:** `watchEffect` (with `onCleanup`/`onWatcherCleanup`) and `watch` of refs, computeds, getters or arrays of them (`immediate`; the callback receives the new and old values) run before the component updates; `onBeforeMount`, `onMounted` (synchronously within `mount()`), `onBeforeUnmount` (DOM attached, parent first) and `onUnmounted` (after removal, children first). `nextTick()`/`nextTick(fn)` resolve when the pending flush ends. Each listener ends with a microtask checkpoint, as Vue attaches listeners to elements.
- Rejected: `deep`/`once`/`flush: 'post' | 'sync'` watchers, `onUpdated`/`onBeforeUpdate`, watching props or reactive objects, watchers whose writes another watcher of the component reads (Vue's queue order), regions whose unmount work Vue would run before later siblings are created, other directive modifiers, `v-model` modifiers and `v-model` on other input types, text controls whose re-renders Runic cannot match (object or function props, listener fallthrough, slot outlets, side-effecting template expressions), `:checked` on radio buttons, `v-show`, dynamic slot names, `$slots`, slot content that may render nothing where the child has a fallback.

## Svelte

The entry calls `mount(App, {target: document.getElementById('root')})` (or `querySelector('#root')`) on a local component in runes mode. App files are compiled in runes mode; files of packages in the mode Svelte infers from them, as the site's build does (the `sv create` rule). A package's legacy-mode component (one without runes: bits-ui's hidden inputs, svelte-sonner's icons) is lowered as runes mode where the two modes mean the same for it: it compiles in runes mode without errors or the `slot_element_deprecated`, `event_directive_deprecated` and `non_reactive_update` warnings, and its instance script declares no `let`/`var` and exports nothing. Otherwise it is rejected at the feature (`E_SVELTE_LEGACY`; `export let`, `$$props`, `<slot>`, …), and lowers only through a pack. Scripts support `$state`, `$state.raw`, `$derived`, `$derived.by`, functions, `let`/`const` values and module imports. Reads see earlier writes immediately; derived values are cached and recompute when what they read changed. Markup supports the tag allow-list (M6: with `dl`, `dt`, `dd`, `figure` and `figcaption`; the inert `sup`, `sub`, `kbd`, `samp`, `mark`, `time`, `data`, `abbr`, `dfn`, `var`, `cite`, `del`, `ins`, `s`, `u`, `blockquote` and `address` in Svelte, React and Vue, case `text-elements`; and `form`, with bounded canceled physical/implicit submission and no-argument `requestSubmit()` as described below; reset and uncovered submission defaults retain explicit diagnostics; attribute names may hold underscores), attributes with expressions (an empty `class` is omitted; nullable numbers and booleans are absent when nullish, otherwise their string, as `set_attribute` writes them), interpolation and `{#if}`/`{:else if}`/`{:else}`.

- **`<script module>`** (M6): its statements are a module of their own, initialised once in module order (constants, functions, classes, `tv()` definitions of the tailwind-variants pack, imports); the instance script and the template see its names, and other modules import its exports (`import Root, { buttonVariants } from './button.svelte'`). Components a program never instantiates still provide their module scripts.
- **Component tags** resolve through imports, barrels and namespace imports: `<Button>`, `<Card.Root>`.
- **Component styles** (M6, bits-ui's Select viewport): a `<style>` whose rules are all `:global(…)` joins the stylesheet Vite emits and is checked with it. Scoped rules are rejected (`E_TEMPLATE`): lowering does not add Svelte's scoping class.
- **Component values** (M6, SvelteKit phase 2, case `kit-docs`): a component imported and named in an expression (`component={ButtonDemo}`), or the default export of a module an `import.meta.glob` loads, is a value of svelte's `Component` type: one object per component (`===` is identity, `typeof` is `"function"`; `String()`, `JSON.stringify` and key-observing built-ins reject it). A tag naming a variable (`<Markdown viewerData={…} />`) renders the component it holds: its candidates are the program's component values whose required props (destructured from `$props()` without a default, not optional in the props type) the tag passes; the tag becomes one copy per candidate behind an `if` chain on the value, so a new value destroys the old instance and creates the new one, as Svelte does. A nullish value renders nothing; another component, possible only through casts TypeScript cannot check, throws `TypeError`. A tag no component value fits is `E_TEMPLATE`. `{@const Component = component}` of a component value names such a tag (shadcn-svelte's ComponentPreview), also beside a type-only import of the same name: type-only imports name no value or component. Props a child neither declares nor collects in rest props are not evaluated (Svelte passes them as getters nothing reads).
- **`import.meta.glob`** (M6) in script modules, with literal patterns (from `/` or relative) and the options `eager`, `import` and `query: '?raw'` (with `eager` and `import: 'default'`: the files' text): Vite 8.3.2's table (its files, sorted, `node_modules` ignored), lazy loaders resolving after Vite's preload helper and Rollup's inlined dynamic import (two chained microtask steps) to the module's namespace object, built from the fields of the module type the call names (`import.meta.glob<{ default: Component }>(…)`, a local object type; required without `import`). Other options and globs in component scripts are `E_GLOB`.
- **`{@html value}`** (M6): HTML is parsed at build time, never at run time. A constant string (the markdown preprocessor's highlighted code) is its own fragment; any other string value may be one of a SvelteKit app's build-time data strings (server data, endpoint responses), each parsed into a fragment; the runtime shows the fragment whose string is the value (nullish and empty: nothing; another string: `RunicUnsupportedError`). Fragments hold static elements of the template allow-list without links, controls or SVG, with plain attributes (no event handlers); others are `E_TEMPLATE`. Svelte's `html()` parses as a `<template>` element's `innerHTML` does; the fragments are parse5's HTML fragment parsing.
- **Markdown and other preprocessed modules** (M6): see [SvelteKit](#sveltekit) generation. Module scripts may destructure a record into constants (`const { title } = metadata`, as mdsx writes them).
- **`<svelte:element this={tag}>`** (M6) with a tag from a finite set of HTML elements of the allow-list (literals, conditionals, literal-union values, props whose sites pass them): one element per tag, recreated with its content when the tag changes; a nullish tag renders nothing.
- **Links** (M6): `<a href>` is focusable and followed by a click or Enter, as a fragment navigation (`popstate`, then `hashchange` when the fragment changed; following the same link again replaces the history entry). `href` values must be a finite set of fragments (`#name`) that name no element, or the document top (`#`, and `#top` where no element has that id or, as an `<a>`, that name; case `link-spreads`): following the top scrolls the document element into view (block start, inline nearest, as Chromium's fragment anchor for the document does) and leaves focus where it is. An `href` may come through spread attributes (shadcn-svelte's breadcrumb link, `<a {...attrs}>` over a derived bag of its `href` prop and rest props; case `link-spreads`, `tests/modules.test.mjs`): each spread after the last `href` attribute, from the last, gives the values its bag holds for it (frontend/bags.ts, as for `<img src>`), checked as an explicit `href`'s; one that may not hold it leaves it to those before it. Other links (other documents, a fragment naming an element: scrolling to and focusing it) are rejected (`E_TEMPLATE`), an open value at the attribute or at the spread, as are `:target` selectors (`E_CSS`, Blitz never matches them).

- **Deep state:** `$state` stores proxies of plain objects and arrays, with Svelte's identity: storing a raw object gives a new proxy, and only writes through the proxy are reactive ([ownership](design/M3-COMPONENTS.md#svelte-deep-state-ownership)). Proxies never write the raw object (a reset to it, defaults: case `proxy-target`) and take a property from it at its first access (case `proxy-lazy`); a raw object reached again through a cycle is a new proxy (case `ownership-cycles`). An array changed in place other than through its proxy after it was stored is reported unsupported at run time. Props carry the parent's proxies. Reads through a proxy are dependencies wherever it is held ([design](design/REACTIVITY-ALIASING.md), R1/R2): a `$state` object shared through a context and read through a constant, held by `$state.raw`, a class field, a Map or an array, or read by a function or a derived value, updates its readers when it is mutated through its owner (case `alias-reads`), and a write through such a value is a write through the proxy where every source of the value is deep state: constants never set, context values every `setContext` of which stores deep state, results and parameters of functions every return and call of which give it (case `alias-writes`; found 2026-10-13 by case `symbol-context`, whose first version rendered stale counts natively). A child mutating a prop in place where a site passes a raw object (a new object, a module constant, a variable that is not `$state`) or the prop's default object applies is rejected (`E_REACTIVITY`): Svelte passes props as they are and does not track the write (case `prop-raw` in Chromium).
- **Components:** child components are instances; `$props()` with defaults, `$bindable` and rest props (`...rest`, forwarded with `{...rest}` spread attributes, listeners included), `bind:prop`, callback props, `bind:this` on components and on elements into a `$bindable` prop (`ref = $bindable(null)`). Rest props typed by svelte/elements' attribute interfaces (`WithElementRef<HTMLButtonAttributes>`) are attribute bags as before.
- **Lists:** `{#each}` with index, key, destructured items, without an item binding (`{#each items, i}`, `{#each items}`; `tests/svelte-each.test.mjs`) and `{:else}`, with Svelte's keyed reconcile; `{#key}` remounts its content.
- **Snippets:** `children`, named snippets and `{@render}` with arguments.

A type assertion on the bound variable (`bind:value={value as never}`). `setContext`/`getContext` from `svelte` with string literal keys in `<script module>` functions: one context per key program-wide, typed by what the program sets; a read where no parent set it gives `undefined`, or throws `RunicUnsupportedError` where its type cannot hold it (`getContext<Required<T>>`); `hasContext` with such a key is whether the instance or a parent set it (`false` for a key the program never sets; rejected where the set values may be `undefined`, which `hasContext` tells apart from no value; `tests/bits.test.mjs`). Every reference to the constant in the program's sources, followed through imports and re-exports, must be the key argument of one of these calls (type positions such as `typeof K` aside); any other use (`===`, a Map key or computed property key, `description`, `toString`, `String(K)`, template interpolation, passing it on) needs a symbol value and is rejected at the reference (`E_TYPE_UNSUPPORTED`), as are `Symbol.for`, the well-known symbols, `Symbol(…)` evaluated in functions or instance scripts, non-literal descriptions and `let` symbols. Onto a component, entries reach its declared props (a later entry overriding an explicit attribute; a callback of a compatible type adapted, another kind of value throwing `TypeError`) and the rest its rest props, or are ignored by a component without rest props (Svelte passes them as getters nothing reads); `bind:` after a spread that may hold the name is rejected. A prop whose values must be known at build time (a `class` in `cn(…)`) takes the values the spread's bag holds for it (`tests/bag-values.test.mjs`): object literals, `$derived` values, rest props through their component's sites, snippet parameters through the render sites, and `mergeProps` where one of its bags holds the name (a later bag's class through `clsx`, `hidden` and `disabled` false deleted), with an earlier attribute's value where the bag lacks the name. A conditional bag whose test is known at build time, or tests (truthiness, `== null`/`!= null`) a value that only holds null or undefined (a prop no site passes: `color != null ? { color } : {}`), holds what that branch holds. A number in a style object is printed as its string, as `mergeProps` prints styles. A bag key computed from a finite set of names (bits-ui's `[this.root.getBitsAttr("trigger")]`, the names over the dialog's variants: calls of build-time constants' functions, methods and arrow function fields returning one expression, inlined) is evaluated at run time and gives the entry of the name it is; a name outside the set throws `TypeError`. A prop typed wider than the value model that no site passes, written only by `bind:value` of inputs whose type the props decide is not `number` or `range` (shadcn's Input), is a nullable string. One that no site passes and that has no default, bound only by `bind:K={name}` on components it renders (at least one; shadcn-svelte's InputGroup.Input binding Input's `value`), takes the bound child props' type where they agree and it holds undefined (the child, lowered first, has decided it; binds in branches that cannot render are left out). An arrow function in a class field declared with more parameters is adapted to the declared type.

## SvelteKit

M6, phases 1 and 2 of the [design](design/M6-SVELTEKIT.md): single-page SvelteKit apps with universal loads, rendered by Kit's client router ported to the compiled language (`frontend/adapters/kit/`, Kit 2.70.1 `client.js`) over the M5 history; phase 2 adds build-time generators, server data and prerendered endpoints as build-time tables, markdown pages, `import.meta.glob`, component values and `{@html}` of build-time strings. Cases `kit-hash` (hash router), `kit-routes` and `kit-routes-missing` (path router), and `kit-docs` and `kit-docs-narrow` (the shadcn-svelte site's markdown pages for Toggle, Tabs and Separator through its velite and mdsx configurations, fixture `kit-docs-svelte`, with the compiler's checked package versions in place of the site's lockfile pins) compare the native app with the app's real Kit build (adapter-static) served to Chromium.

- **Recognition.** `runic.json` is `{ "framework": "svelte", "kit": true, "title": … }` (no `entry` or `alias`: Kit gives both). `@sveltejs/kit` must be **2.70.1**, the files whose code builds the manifest byte-identical to the published package (SHA-256, `compiler/adapters/kit-pins.mjs`); other versions fail with `E_FRONTEND_VERSION` (Kit 3, and its `vite.config` configuration, is not yet supported). The app's `vite.config` and `svelte.config.js` are never run: `svelte.config.js` is read as literals, accepting `kit.router.type` (`hash` or `pathname`), `kit.router.resolution` `client`, `kit.alias` (with `$lib` → `src/lib`), `kit.output.bundleStrategy` `single` or `inline`, `kit.version.pollInterval` 0, `compilerOptions.runes` `true`, and ignoring the build-only `adapter`, `prerender`, `appDir`, `outDir`, `typescript`, `csp`, `csrf`, `env`, `inlineStyleThreshold` and `serviceWorker`; anything else is `E_KIT_CONFIG`, as are `preprocess` and `extensions` unless a preprocess generation step covers them (below).
- **Generation** (`runic generate <app>`, `compiler/generate.mjs`): `runic.json` `generate` lists steps in order, each with its inputs (globs) and pinned tools (`name@version`, the package's files checked against the SHA-256 in `compiler/generate-pins.mjs`): a command (`node <app script>` or a bin of a pinned tool, with `outputs` directories) or a `preprocess` glob, whose files run through `svelte.config.js`'s `preprocess` list (the only place the compiler imports that file) into `.runic/generate/<step>/<file>.svelte`; `extensions` may then name the preprocessed extension (`.md`). Steps run with `TZ=UTC`, `LC_ALL=C` and `SOURCE_DATE_EPOCH=0`. For a SvelteKit app generation then evaluates the server code (below). `.runic/generate.json` records each step's declaration, tools and the SHA-256 of every input and output, and the server phase's sources and output. Builds never run a step: a missing record, a changed declaration, tool, input or output is `E_GENERATED` at `runic.json`. A preprocessed file is the component module of its recorded output (`content/components/toggle.md` → `toggle.md.svelte` beside it; diagnostics are located in that output).
- **Server data and endpoints** (generation, `compiler/adapters/kit-server.mjs`): for each prerendered page route (`prerender = true`, inner levels over outer, a universal module's option over its server module's), once per entry (`entries()` of the page's modules, or the route itself without parameters), the levels' server loads run in Node through the compiler's Vite (the app's aliases, never its `vite.config`) with Kit's request event (no cookies) and their reads (params, url, route, parent) recorded; the universal loads run as Kit's server rendering runs them (`browser` false) for the URLs they fetch; a same-origin fetch calls the matching endpoint's `GET` (which must be `prerender = true`), and endpoints' own `entries()` add URLs. Server data must be JSON values, one per combination of what the load read. Natively a server load's data is a table by those reads (each lookup new objects, as each response Kit parses), passed to the level's universal load as `data` and invalidated as Kit's `load_route` does; a load's `fetch(url)` is a response from the endpoints' table (`ok`, `status`, `text()`, and `await res.json()` parsed into the type the program declares for it), a host round trip after the first navigation. Server modules export `load`, `prerender`, `ssr` and `entries`.
- **`src/app.html`**: `<html>` attributes become the document's, `<body>` attributes the body's; the body holds one element whose only content is `%sveltekit.body%`, and that element (its attributes kept) is the container instead of `div#root`. The head may hold `<meta charset>`, `<meta name="viewport">` and `%sveltekit.head%`. Scripts, links, styles, titles, event attributes and placeholders in attributes are `E_KIT_HTML`; `data-sveltekit-preload-data`/`-preload-code` other than `off`/`false` (in app.html or on elements) are `E_KIT_PRELOAD`.
- **Routes.** The app's own Kit builds the manifest (`create_manifest_data`): route ids, groups, layout chains with `@` resets, rest and optional parameters, matchers from `src/params` (ordinary compiled functions), Kit's sort order, Kit's default layout and error page. A generated root component nests the layouts through `children` with `data` and `params`; a level whose component is unchanged keeps its instance and gets new props.
- **Loads.** `+page.ts`/`+layout.ts` export `load` (declared function or `const load = (…) satisfies PageLoad`; a `: PageLoad` annotation is `E_KIT_LOAD`) and the page options `ssr` and `prerender` (`true` or `false`: natively every route renders on the client; `true` makes generation evaluate it); others (`entries` included: put it in the server module) are `E_KIT_LOAD`. A level's `params` are strings where every route reaching the level has the parameter. Loads get `params`, `url`, `route` and `parent()`; Kit's dependency tracking re-runs a load only when the params, url parts, route or parent data it read changed. `error(status, message)` renders the nearest `+error.svelte` (Kit's `load_nearest_error_page`), an unknown route the root error page with 404; `redirect(status, location)` navigates within the app. `handleError` from `src/hooks.client.ts` gives the error object (`{ event, status, message }` in; no `error`, since unexpected errors are values Kit logs and the compiled program does not inspect). Data merges with parent data as Kit merges it.
- **Navigation.** Link clicks (absolute and relative `href`, fragments of the current page (a fragment naming an element is followed as Chromium follows it: popstate, the element scrolled into view with block start, focused if focusable and otherwise focus cleared and the element made the navigation starting point, then hashchange), `data-sveltekit-noscroll`, `-keepfocus` and `-replacestate` on the link, an ancestor, the container or `<body>`), `goto(url, { replaceState, noScroll, keepFocus })` returning a promise, back and forward, `beforeNavigate` with `cancel()` (links, `goto`, traversals; a cancelled traversal goes back), `afterNavigate`, scrolling to the top or to the fragment's element (which also becomes the sequential focus starting point), Kit's focus reset, the `#svelte-announcer` live region, and `<svelte:head><title>` setting `document.title` (one `<title>` of text and expressions; the window title stays the `runic.json` title). History entries carry Kit's indices as their state. `beforeNavigate`/`afterNavigate` are called as top-level statements of a component script (registered when the instance mounts, removed when it is destroyed); elsewhere `E_KIT_LIFECYCLE`.
- **Modules.** `$app/state` (`page.url`, `page.params`, `page.route.id`, `page.status`, `page.error`), `$app/navigation` (`goto`, `beforeNavigate`, `afterNavigate`), `$app/environment` (`browser` `true`, `dev` and `building` `false`), `@sveltejs/kit` (`error`, `redirect`, types), `./$types` (generated `PageProps`, `PageData`, `PageLoad`, `LayoutProps`, …). Route components declare `data`, `params` and `children` by destructuring `$props()`.
- **Runtime reports** (`RunicUnsupportedError`, as for other unsupported values): navigations Kit performs by loading another document (external links, `data-sveltekit-reload`, unknown paths through links or `goto` in path mode, redirects to other origins), redirect loops, errors without a `handleError` hook (Kit's default logs a stack trace), a hash edited without router state.
- **Rejected:** server loads of routes that are not prerendered (or have parameters but no `entries()`), endpoints no load fetches and that list no entries, endpoints fetched but not prerendered, form actions, server data that is not JSON or not deterministic (`E_KIT_SERVER`); fetches of other origins, other methods or non-endpoint URLs at generation (`E_KIT_FETCH`); at run time, server data of an entry generation did not evaluate and fetches of other URLs (`RunicUnsupportedError`); `hooks.server`, universal hooks and service workers (`E_KIT_HOOKS`); `$app/stores`, `$app/forms`, `$app/paths`, `$app/server`, `$env/*`, `$service-worker` (`E_KIT_IMPORT`, at the import); `page.data`, `page.form`, `page.state`, `navigating`, `updated`, `onNavigate`, `invalidate*`, `preload*` and shallow routing (`pushState`/`replaceState` from `$app/navigation`), which the modules do not export; a `form` prop or rest props in route components (`E_KIT_COMPONENT`); a route module without a component (`E_KIT_ROUTES`); `catch` clauses in route modules and in modules that reach `@sveltejs/kit` (`E_KIT_CATCH`: `error()` and `redirect()` throw the router's errors); document `click` and window `popstate`/`hashchange` listeners (`E_KIT_LISTENER`: the router owns them); `autofocus` (`E_KIT_ATTRIBUTE`); `<iframe>` as in all Svelte code.
- **Known deviations.** Data objects of different route nodes are compared as different (Kit compares their identity after a `parent()` merge, which only matters for objects shared between loads); a reload does not restore Kit's per-entry scroll positions (Kit keeps them in `sessionStorage`); errors thrown while rendering are not routed to `+error.svelte`; route modules initialise with the program, not when their route first loads; server-rendered pages are not modelled: the native app renders the first page on the client as Kit's SPA mode does (`ssr = false`), where hydration would give `$props.id()` the server's `s1`, `s2`, … ids. The differential is incomplete for Kit apps: the router reads the window's scroll position at every navigation.

## Inline SVG

Icons written inline in templates, as lucide draws them, in all three frameworks ([IR](IR.md#template), case `icons`):

- **Elements:** `svg`, `g`, `path`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `rect`, created in the SVG namespace; `{#if}`/`v-if`/`?:` and lists inside an `<svg>`. An `<svg>` needs a `viewBox`; it may stand in text, flex rows and buttons, sized by `width`/`height` or by CSS.
- **Attributes:** on `<svg>` `xmlns` (the SVG namespace only), `width`, `height`, `viewBox`, `class`, `id`, `role` (ARIA, no rendering effect; M6); on every element the paint attributes `fill`, `fill-opacity`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-opacity`, and `class`, `aria-*`, `data-*`; `opacity` and `transform` on groups and shapes; each shape's geometry. Values are static or bound strings and numbers; class toggles (`class:`, `:class`) work. `currentColor` follows the CSS `color` of the element holding the attribute. Colours in other spaces (`oklch()`, as the shadcn themes are) are converted to sRGB for it.
- **React** maps props as react-dom 19.3's `setProp` does: `className` → `class`; `viewBox`, `width`, `height` keep their names; `fillOpacity`, `fillRule`, `strokeDasharray`, `strokeDashoffset`, `strokeLinecap`, `strokeLinejoin`, `strokeMiterlimit`, `strokeOpacity`, `strokeWidth` → their hyphenated names (`getAttributeAlias`); lowercase, `aria-*` and `data-*` names as written; a boolean `aria-*`/`data-*` value is the string `"true"`/`"false"`. Other camelCase props (`clipRule`, `xlinkHref`, `xmlnsXlink`, `preserveAspectRatio`, …) and props with rules of their own (`focusable`, `style`, …) are rejected (`E_JSX`).
- **Rejected** (`E_SVG`): other SVG elements (`text`, `use`, `defs`, `clipPath`, gradients, …), nested `<svg>`, HTML elements, components, slots or text inside an `<svg>`, listeners, spreads, refs and inline styles on SVG elements, `id`, `style` and `color` on SVG children, attributes outside the list. Stylesheet CSS reaches SVG content (Blitz fork): presentation attributes are overridden by any rule, `fill`/`stroke` and their longhands inherit, `currentColor` resolves with each element's own `color`, and `display: none`, `visibility`, `opacity` and transforms (about the user-space origin, as in Chromium) apply to children (case `blitz-svg-css`).
- **Size.** Only programs with an `<svg>` link Blitz's SVG support (usvg, 1.6 MiB in a release build): codegen enables the runtime's `svg` feature for them.

## Packages

npm packages are handled by mapping packs (D9, [design](design/M6-LIBRARIES.md#mapping-packs-d9)), one module per package version in `frontend/packs/`. A bare import resolves through the collector to a package directory; its `package.json` name and exact version select the pack. A package without a pack is rejected (`E_DEPENDENCY`), another version of a packed package too (`E_PACK_VERSION`), and so is every use the pack does not cover (`E_PACK`), each at its source location. A program lists the packs it used in `meta.mappings`. Packs are validated against the real package (vectors under `conformance/packs/`, case `packs`).

## Native runtime and controls

The Rust backend validates every program and generates an application crate linked against `crates/runic-runtime`. The runtime builds the DOM directly through Blitz's mutator API under `<div id="root">`, keeps node handles, and updates only bindings whose cells changed (or all bindings with `--no-opt`). Conditional content and component instances are mounted and removed as subtrees; keyed lists move existing nodes with the framework's reorder strategy. It supplies the browser behaviour the pinned Blitz lacks or does differently ([gaps](BLITZ-GAPS.md)):

- **Events.** Chromium's sequences on Linux: pointer and mouse boundary events (with the bubbling `pointerover`/`pointerout`/`mouseover`/`mouseout`, M6, case `hover-events` in Svelte, React and Vue; React programs may not combine `onMouseEnter`/`onMouseLeave` with `onMouseOver`/`onMouseOut`, nor the pointer pair, as React dispatches enter and leave from the out event), `click`/`dblclick` by click count, `contextmenu` on press, `wheel`, key events with Playwright's modifier order; capture and bubble follow the event path; task/microtask boundaries follow the framework schedule, while physical document/window callbacks retain their own checkpoints; submit selection checks current registrations and propagation at each target/phase entry; cancelled events have no default action, and neither has a target its listeners removed. Disabled controls get pointer events only.
  Boundary events use normalized element targets; bubbling changes `currentTarget`
  without changing `target`. `relatedTarget` is the opposite endpoint or null,
  exposed as `HTMLElement | null` for `MouseEvent` and inherited by `PointerEvent`,
  including typed window/document and rest-prop maps. Repeated movement within the
  same element emits no new over/out transition. Verified unpressed mouse hover
  carries pointer `button: -1`, mouse `button: 0` and `buttons: 0`. Boundary events
  retain the current held-button mask and the changed button when caused by a
  button transition. Pointer boundary sequences precede mouse
  sequences. React's same-family restriction applies across the program, forwarded
  listeners included; existing continuous-render constraints remain.
- **Focus.** Focus moves on mousedown (to the nearest focusable element, nowhere for other content); Tab and Shift+Tab follow `tabindex` order (positive values first); `focus()`/`blur()` run their listeners nested. Every move dispatches `blur`, `focusout`, `focus`, `focusin` with `relatedTarget`. Removing the focused element, or a keyed move detaching it, dispatches `blur` and `focusout` at once while it is still in the document; a focused control that becomes disabled (natively also one that loses its box) is blurred by the focus fixup (a task after the frame, M6). After a move-induced blur, Tab resumes after the moved element, not from Chromium's live range at the detach position (case `reorder-navigation`, a known gap).
- **Controls.** Checkboxes and radio buttons (groups by name in a tree, arrow keys, Tab entering a group at its checked button; checking one, by user or script, unchecks the group); text areas and labels; selects drawn by the runtime (closed control at Chromium's metrics, keyboard on the closed control, a popup drawn into the page with Chromium's keyboard and pointer model). Script-set values update the live control only when they differ, so echoes preserve selection and composition; read-only and disabled edits are blocked; `maxlength` (UTF-16 units) and control characters are stopped before mutation; Alt with navigation or editing keys does nothing in text controls, as on Linux Chromium.
- **Bounded form submission** (M6, [design](design/M6-FORM-SUBMISSION.md), [acceptance](../conformance/results/form-submit.md)). React, Vue and Svelte support bubbling, cancelable `submit` with common Event operations through physical submit-control activation, implicit Enter in text/search/tel/password inputs (missing or invalid type normalizes to text), and no-argument `requestSubmit()`. Script-added bubbling `submit` listeners use a literal event name with no options. React programs combining any native element submit registration with a synthetic submit handler (including handlers forwarded through rest props) are rejected with E_EVENT because React delegates to its root after native element listeners. This is a conservative program-wide overlap rejection, without proving elements disjoint. Element-only React submit registrations, removal-only element calls, and native window/document submit listeners remain admitted. Native submit listeners support `instanceof SubmitEvent` and `instanceof Event`; React synthetic `onSubmit` handlers expose common operations and continue to reject DOM-event `instanceof` and `nativeEvent`.
  Live explicit/ancestor ownership and associated controls use document order; an invalid explicit owner never falls back. The first default submit button remains decisive when disabled, and disabled/readonly input states count in the broader implicit blocker set. Default-button activation retains its simulated click with detail 0, and cancellation blocks submission. Validation bypass uses only form `novalidate` or the actual initiating submitter's `formnovalidate`; a no-argument request never borrows the default button's flag.
  Requests run synchronously with no inserted task/microtask checkpoint, suppress same-form reentry, permit another form's request, and restore the caller's update priority. Physical submits preserve event-versus-listener checkpoints. Submission-specific authored cases cover phase-local registration selection, removed/readded callbacks, later-phase additions, and propagation stops. Each submit target/phase checks the propagation flag: stopPropagation permits remaining callbacks in that invocation, stopImmediatePropagation suppresses them too, and suppressed callbacks start no task/checkpoint. Canceled completion still releases the same-form guard; this does not certify generic mutable DOM listener behavior. A known disconnected form dispatches no submit and retains the disconnected-form warning; retained descendant named shadows are diagnosed before that no-op.
  Reset, FormData/data serialization, navigation/dialog completion, argumented requests, `SubmitEvent.submitter`, constructing SubmitEvent, custom validity, validation UI, intrinsic/constraint validity the shared helper cannot prove, command-invoker Auto behavior, non-form requests, requestSubmit named-property shadows, and nested/parser-specific forms remain rejected or explicitly unsupported. Constraint/user-validity CSS observables remain rejected even with validation bypass, before framework scoping changes selector text or source positions; Vue external component styles retain their actual stylesheet location. The stops fixture exercises admitted window/document capture and ancestor bubble listeners; no new element capture API is admitted or certified here. This is the canceled-submission domain verified by authored cases, not a general browser forms implementation.
- **Layout and scrolling.** `getBoundingClientRect`, `offset*`, `client*`, `scroll*` read the native layout with Blink's pixel snapping; `scrollTop`/`scrollLeft`, `scrollTo`, `scrollBy`, `scrollIntoView` (every scroll container, whole pixels) and the window equivalents scroll at once. A rendering step after each task runs the window's `resize` event, `scroll` events (one per moved scroller), media query list `change` events, then the focus fixup.
- **Inline styles and the document element** go through the CSSOM (`runic-css` over Stylo): serialisation, `setProperty` and each framework's update model, and (M6) script access to an element's inline style properties (`node.style.transitionDuration`).
- **Library DOM APIs** (M6): `isConnected`, `hasAttribute`, `getAttribute` (`element.id`), `closest(tag)`, `querySelectorAll`/`querySelector` with a subset of selectors (type, `#id`, `.class`, `[attr]`, `[attr=value]`, `:not()`, descendant and child combinators; others reported unsupported), `x instanceof HTMLElement` (false for SVG elements), `getComputedStyle(e).getPropertyValue("direction")` (computed; other properties rejected; the interpreter reports it as layout), `event.detail` (the click count of mouse button events; 0 for keyboard and simulated clicks); no-argument `requestSubmit()` runs bounded canceled submission synchronously from a live form without a default-button click; non-form receivers, named shadows and uncovered defaults retain diagnostics; `new Image()` (Pinned images above); `element.getAnimations()` (no options) returns the element's running CSS animations and transitions as Animation objects (transitions first, then animations in `animation-name` order; none for an element that is not rendered), one object per animation while it runs, with `finished` (fulfilled with the animation at the frame it ends, before that frame renders; rejected with an `AbortError` when a style change, the element's removal or `display: none` cancels it, at the style resolution that cancels it), `playState` (`running`, also while delayed, `paused`, `finished`, `idle` once cancelled; reading it brings styles up to date) and `pending` (until a frame has seen the animation); other members are rejected (`E_MEMBER`), and an element whose `animation-fill-mode` is `forwards` or `both` (possible only through inline styles) is reported unsupported; the interpreter reports programs reading them as layout; `MutationObserver` observes child lists (case `overlay-host`); observing attributes is reported unsupported; `beforematch` is never fired. M6 (bits-ui's Command): `CSS.escape`; `nextElementSibling`/`previousElementSibling` (a sibling outside the program's elements is reported unsupported) and `matches(selector)` of the selector subset; `parent.appendChild(child)` of a child of `parent`, which moves it to the end (another node, or one holding focus, is reported unsupported; once script reordered an element's children, the framework inserting into it is reported unsupported, as the frameworks place blocks by anchors the runtime does not keep); `setAttribute(name, value)` (the framework writing an attribute script set is covered where it writes the value the element has, as the frameworks skip writes of values they set before; a different value is reported unsupported); bits-ui's `getFirstNonCommentChild(el)`, whose result is an element, or a text node where the program only tests it for truth and reads its data attributes (none). The interpreter reports programs moving nodes or writing attributes as needing the native DOM. An element without layout boxes (`display: none`, or inside such an element) has an empty rectangle at the origin, in `getBoundingClientRect` and in probe geometry, as in Chromium.
- **Script DOM** (M6, [design](design/M6-SCRIPT-DOM.md), slice 1: bits-ui's announcer; case `script-dom-announcer`, fixture `script-dom-announcer-svelte`, `tests/script-dom.test.mjs`). The document and the window are values (node handles of the IR's `element` type): a `Document | null` is a nullable handle, `doc === document` compares identity, and a member of a value TypeScript types as the document (or the window) is that object's member. `document.createElement(tag)` makes an element script owns, for a literal tag (or a union of literal tags) of the static elements (those `{@html}` fragments hold, the inert text-level and table elements; others are `E_CALL`), the name lowercased; `document.querySelector` takes any selector of the subset. Nodes script created move under the DOM standard's pre-insertion validity (`HierarchyRequestError` for an ancestor into its descendant or into a text node, `NotFoundError` for a reference child of another parent; a WebIDL `TypeError` for the window) with `appendChild`, `insertBefore` (a null reference appends), `replaceChildren(...nodes)` and `remove()` (nothing without a parent; a removed node keeps its subtree for script that holds it), within child lists script owns: those of nodes script created, of an element the template renders without children (not a control, void, table-section or SVG element: no framework inserts into it), and of the body before the container (`body.firstChild` is the container or a node script placed before it). `textContent =` (one text node, none for the empty string; null is empty) and `innerText =` (text nodes with a `<br>` for each CR LF, LF or CR) replace such a child list; `childElementCount` counts element children of any element; `firstChild` is read where script owns the child list. `className`, `id`, `role` and the ARIA reflection properties (`ariaLive` → `aria-live`, …; null removes the attribute) and `removeAttribute` write attributes, checked against the framework's later writes as `setAttribute` is; `style.cssText =` sets the style attribute to the CSSOM serialization of the declarations (a declaration the style engine does not parse is reported unsupported, as Chromium may keep it). Reported unsupported at run time: script inserting into, removing from or replacing the child list of an element the framework renders children into, moving or removing a node the framework renders (except the reordering above), `firstChild` of such an element or of a SvelteKit app's body, moving or removing a subtree that holds focus, and using a script node inside a subtree the framework removed (the runtime frees it). Reading `innerText` is `E_MEMBER` (it depends on rendering). Snapshots gain `preceding`, the body's content before the container (the browser harness, the native probe and the interpreter). The interpreter models the nodes script creates and the child lists it owns (the differential is complete for the fixture); script changes of the framework's own nodes stay `RunicLayoutError` there. A document member read on a node value the program does not know to be the document (an untyped package parameter: bits-ui's `initAnnouncer(doc)`) checks at run time that it is: `createElement` on another node throws JavaScript's `TypeError`, `body` of another node (undefined) is reported unsupported. For bits-ui's announcer, package code is typed by two more rules: a function a declared package function returns as a member of an object literal (`return { announce }`) takes the declared member's type (its defaulted parameters are then nullable, as the declaration's optional ones are), and a local arrow function returned as such a member and called only through it (`getLog`) takes, per untyped parameter, the one type its calls pass; svelte-toolbelt's `srOnlyStylesString` is in its pack (checked against the package).
- **Script DOM, slice 2** (node breadth; case `script-dom-nodes`, fixture `script-dom-nodes-svelte`, `tests/script-dom.test.mjs`). `document.createTextNode`, `createComment` and `createDocumentFragment` make nodes script owns; inserting a fragment moves its children and leaves it empty. `nodeType`, `nodeName` (`tagName`; uppercase for HTML elements), `nodeValue` and `data` (null for elements; writes to text and comment nodes script created, nothing for elements), `textContent` of comments and fragments (comments left out of an element's). Node-level traversal (`firstChild`, `lastChild`, `nextSibling`, `previousSibling`, `childNodes`) is exact in child lists script owns and at the body before the container (past the container, and in child lists the framework renders children into, it is reported unsupported); `parentNode` (the document for the html element; a top-level element's, the container, is reported), `parentElement` (none under a fragment), and element-level `children`, `firstElementChild`, `lastElementChild` of every element. `childNodes` and `children` are live lists: they are read where used (`.length`, an index, undefined past the end, `Array.from(list)`); kept in a variable or iterated they are `E_MEMBER`. `append`, `prepend`, `before`, `after` and `replaceWith` take nodes and strings (text nodes), with the DOM standard's viable-sibling rules; `removeChild` and `replaceChild` (`NotFoundError` for another parent's child). `cloneNode(deep)` of nodes script created and of rendered elements (attributes and, when deep, children; no listeners or bindings; controls and images are reported, their cloning steps copy state): the clone is script's. `classList` `add`, `remove`, `toggle(token, force)`, `contains` and `replace` follow the DOM standard's DOMTokenList steps (the attribute serialized as an ordered set, untouched where the update steps do not run; `SyntaxError` and `InvalidCharacterError` for empty and whitespace tokens), `className` reads, and `dataset` writes (`data-` names by the HTML standard's mapping) on every element, checked against the framework's later writes as `setAttribute` is. `instanceof Node`, `Text`, `Comment`, `CharacterData` and `DocumentFragment` test the node kind (`instanceof Element` and `HTMLElement` are false for text, comment and fragment nodes). The interpreter models all of it, including script attribute writes on rendered elements (kept until the framework writes a changed value; one that differs from script's stops the run as unsupported, as natively).
- **Event loop.** Input events and timers are tasks, each followed by its microtask checkpoint; state writes queue the framework's flush job; default-priority tasks (React's scheduler, M6 rejection reports) run after the current task, and those queued inside a frame (its rendering step's events, ResizeObserver callbacks) after the frame's layout (M6); a discrete event's update renders pending default-priority updates with it (React's sync lane); host replies (clipboard, history traversals) are tasks after the one that asked. The focus fixup blurs a focused element that became disabled or lost its box in a task after the frame, after the default-priority tasks queued before it (Chromium's style update starts a 0 ms timer; its order against a React render queued by the same frame's scroll events is not stable in Chromium). Timers use the system clock natively and a virtual clock in probes.
- **Animations.** Every style resolution runs CSS transitions and animations at the document timeline's time: real time natively (from the shell's first access to the document, where blitz-shell starts its animation clock; the shell redraws while animations run), the virtual clock in probes, whose `wait` resolves styles at every 16 ms frame so that animations started by timers begin at the frame. Each frame has an animation step (the probe's frames and wait frames, the window's redraws before they render): animations the app holds that ended settle their `finished` promises there, as a task. A style change that cancels an animation shows the element's unanimated style in the same resolution, and cubic-bezier easings are solved to Chromium's precision (both through the [Stylo fork](BLITZ-GAPS.md#fixed-in-the-stylo-fork)). Text in anonymous blocks (direct text of flex and grid containers, including default `inline-flex` buttons) follows its container's restyles, colour transitions included (a Blitz fork patch; case `blitz-anonymous-restyle`).
- **Imperative mounts and ResizeObserver** (M6). Mounted instances render in the body after the container, each before an anchor of its own, and update after the root in each flush pass. After each frame's layout the ResizeObserver notifications due are delivered (each observer's callback a task), with a layout after each round.
- **Rendering.** The canvas is painted white beneath the document. Form controls use Chromium's default font size, `line-height: normal` and radio and checkbox metrics, and buttons Chromium's button layout and baselines; grid containers take their baseline from their first item (Blitz fork); an `@font-face` face is used only for the characters its `unicode-range` covers, faces of a family with the same weight, style and width are tried last-defined first (rule order within a stylesheet, stylesheets in the order Blitz processes them), and a text control sizes itself from the first face whose range includes a space (Blitz and Parley forks, case `font-subsets`, [BLITZ-GAPS](BLITZ-GAPS.md)); `svg` elements clip their drawing (`overflow: hidden`, as in Chromium's UA sheet). The CPU (vello_cpu) and GPU (vello) renderers are selected per project. Both draw filters and backdrop filters (forks, [research](research/M6-CPU-RENDERER.md#the-gpu-renderer)); the GPU renderer draws windows with area anti-aliasing (as the CPU renderer and Skia; anyrender's default for windows is 16x MSAA), and its fork samples gradients and box shadows at pixel centres. Pixel conformance is pinned to the CPU renderer; `conformance/run.mjs --renderer gpu` runs the same gates on GPU builds, drawn on Mesa's software Vulkan driver (lavapipe) from the locked shell: the representative cases, `filters`, `backdrop-filters` and `gradients` pass it.

## Verification

Differential pointer traces record the native probe's actual pre-action hit and
replay its element-only path in the reference interpreter, with live tag/id
assertions on the interpreter's existing render. Native dispatch still uses Blitz
hit testing. Original and replay actions remain evidence; expected snapshots and
comparisons are unchanged. Each complete trace compares the initial state and
every generated action; unavailable endpoints, hidden-target stops and matching
render-error termination are incomplete. The consolidation checks 60 complete
traces and 1,560 comparisons in each optimization mode. This delegates endpoint
selection for event-semantic comparison; browser/native cases and direct pointer
oracles independently check native hit correctness.

`conformance/run.mjs` drives the original framework in headless Chromium and the native app's probe build with the same input: clicks, double clicks, context menus, hovers and wheel turns (at an element's centre or a given position in it), key presses and typing, focus, option choices, viewport resizes and emulated preferences, history traversals, reloads and virtual-time waits. It compares DOM semantics (tags, attributes, text, live values, selections, focus), host effects (console lines, with Chromium's reports of unhandled promise rejections since M6, while other uncaught exceptions fail the run; clipboard text, location, history length), geometry within 2 px and, with `--pixels`, screenshots within a mean absolute error of 3/255, over the whole viewport and over each element a case names in `pixelRegions`. Chromium's document timeline is stopped and every CSS animation is sought to the virtual time since the harness first saw it, at the points where the probe resolves styles (Playwright's fake clock does not move the timeline). A case sets its environment: time zone, locale, start URL, clipboard text, random seed (the harness replaces Chromium's `Math.random`/`crypto.randomUUID` by the probe's seeded generator), `localStorage`, and the fake clock for programs that read the time. `conformance/differential.mjs` compares generated code with the reference interpreter on seeded random traces; programs that read layout or listen for scroll events are reported incomplete there and checked against Chromium only. A failed native probe (non-zero exit or panic) fails its trace and the run continues; a fixture whose generated inputs are missing is reported incomplete with the `generate` command to run first. Content mounted in the body after the container is compared as `portals` (M6). The probe runs two frames after the mount before its first snapshot, as the browser waits for two animation frames. Comparisons observe committed output after natural paint and focus settling and never force blur. The Svelte reference is compiled for production. `conformance/interp-vs-browser.mjs` compares the interpreter with the framework without native builds. [M5 results](../conformance/results/m5.md) list the cases, results and known deviations.

OS keyboard delivery, IME, Wayland resize and accessibility are not certified (internal events do not prove them). The OS clipboard and native console output were checked once by hand under X11, not by conformance. Multiple windows are outside verified support. Builds are atomic and run `--offline` against the workspace `Cargo.lock`. No performance improvement is claimed beyond the measured startup and size figures in the results.
