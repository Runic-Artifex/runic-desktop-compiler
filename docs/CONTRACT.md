# Compatibility contract v9

The input that is implemented and verified as of milestone M5 and the M6 work since (M6 is in progress). What is not covered is in the [gap register](GAPS.md). This is a living document: milestones update it in place, and git history and the `m<N>` tags record earlier versions (v8 is at tag `m4`, v7 at `m3`, v6 at `m2`, v5 at `m1`; v1–v4 are in `history/`). Roadmap items are not part of the contract until a milestone verifies them.

**Isolated parity branch:** this worktree accepts table structure in all three
adapters to exercise compiled fixtures and uses patched Blitz/Stylo/Vello/Parley through
local paths. The shipping contract below still describes the integrated pins.
Compiled table semantics, geometry and local pixels pass 96 CPU and 32 selected
GPU states. Broader control hit/layout/paint failures, reproducible dependency pins
and remaining input/platform gates prevent promoting experimental acceptance to
that contract. See the [implementation record](../conformance/results/chromium-parity.md),
the [font/inline continuation](../conformance/results/chromium-font-inline.md),
the [focus continuation](../conformance/results/chromium-control-focus.md),
the [control-box continuation](../conformance/results/chromium-control-boxes.md),
the [text-metric continuation](../conformance/results/chromium-text-metrics.md),
and [targeted plan](research/CHROMIUM-PARITY.md).

The TypeScript frontends (`frontend/`) lower every framework through one shared language layer to [IR schema 4](IR.md). Ordinary JavaScript/TypeScript code follows the JavaScript value model. M3 added component instances, props, lists, slots, element refs, checkboxes and `keydown` ([design](design/M3-COMPONENTS.md)); M4 added the event loop, effects, timers, promises and `async`/`await`, and `localStorage` ([design](design/M4-EFFECTS.md)); M5 added the DOM event model, forms, layout reads and scrolling, media queries, host services ([design](design/M5-PLATFORM.md)) and inline SVG icons. Native applications execute no JavaScript engine.

## Collection

`runic.json` selects a local entry, title, optional `framework` (`react`, the default, `vue` or `svelte`) and optional `renderer` (`cpu`, the default, or `gpu`). Optional `alias` maps import prefixes to directories inside the app, resolved as Vite's `resolve.alias` (`"alias": { "$lib": "src/lib" }`, as SvelteKit configures `$lib`; the app's own Vite and SvelteKit configs are never run). All apps use an empty `div#root` and one module script; `index.html`'s `<html>` and `<body>` attributes (`lang`, `class`, `data-*`) become the document element's and the body's (M6; shadcn-svelte's style class is on `<body>`, where portalled content inherits it). Vite collects original sources, ordered local CSS and WOFF2 assets; inline HTML scripts are rejected. Imports of types only (`import type`, lists of `type` names) load nothing.

Checked identities are React/React DOM 19.3.0, Vue/compiler-sfc 3.5.43 or 3.5.24, and Svelte/compiler 5.57.1 or 5.49.2. Runtime and compiler versions must match; other versions fail with `E_FRONTEND_VERSION`. Vite 8.3.2, TypeScript 5.9.3, plugin-vue 6.0.9 and the Svelte Vite plugin 7.3.1 are pinned tools.

CSS may use any selectors and properties that Blitz's style engine supports; Blitz/Stylo renders them and conformance checks the result. `position: sticky` is rejected (`E_CSS_PROPERTY`, also through `var()`): Blitz lays sticky boxes out as relative ones and never keeps them in view while scrolling ([gaps](BLITZ-GAPS.md)). At-rules other than `@font-face`, `@media`, `@layer`, `@property`, `@supports`, `@keyframes` and `@container` are rejected (`@starting-style`, …). Container queries (M6, Blitz and Stylo forks, cases `blitz-container-queries` and `bits-dialog`) are size queries on `container-type: size | inline-size` containers (the `container` shorthand and named containers included), evaluated against the container's content box in the last layout: when a container's size changes, its descendants are restyled and laid out again in the same frame; a container has layout containment and an intrinsic inline size as if empty. Style and scroll-state queries and `container-type: scroll-state` are rejected (`E_CSS`, `E_CSS_PROPERTY`). Container units (`cqw`, `cqi`, …) are not supported: Stylo drops declarations using them, which the app reports once they apply (below). Transitions and keyframe animations (`transition*`, `animation*`, M6, [design](design/M6-LIBRARIES.md#animations), case `animations`) run on Stylo's engine at the runtime's timeline; rejected (`E_CSS_PROPERTY`): `text-transform` other than `none`, `uppercase` and `lowercase` (Blitz transforms case only); `animation-fill-mode` `forwards` and `both` (Stylo drops a finished animation's fill when its element is next restyled), also where a `var()` can reach them through a value the stylesheet gives the custom property, `transition-behavior: allow-discrete`, and scroll-driven animations. Animation and transition events are rejected (`E_EVENT`); `element.getAnimations()` is a library DOM API (below). The compiler parses every stylesheet with Stylo and Blitz's preferences: a rule or declaration Stylo drops is rejected with its location (`E_CSS`, `E_CSS_PROPERTY`), except drops verified equivalent in Chromium (vendor pseudo-classes and pseudo-elements, `forced-colors`/`prefers-contrast`/`prefers-reduced-motion` media features, desktop-irrelevant vendor properties, and `resize`, whose grip Blitz never draws). A dropped declaration in a style rule whose selectors have no pseudo-element is not rejected: the app reports it as unsupported, with its location, once the rule's selector matches an element, so a library variant the page never uses (shadcn-svelte's `group-has-data-horizontal/field:text-balance`) costs nothing (`tests/collect.test.mjs`). Nor where it never applies (M6, bits-ui's Select): an element that a later rule of the same block, of at least the rule's specificity (Stylo's), setting the property also matches is not reported (Tailwind's `line-clamp-1` overridden by `flex` on shadcn-svelte's select value); `-webkit-line-clamp` and `-webkit-box-orient` count only where their rule's `display: -webkit-box` does (Chromium 153 applies them nowhere else); and scroll margins only once such an element is scrolled into view (the runtime's focus never scrolls, and Blitz has no scroll snapping); scroll paddings (M6, bits-ui's Command list, `scroll-py-1`) only once a target inside such an element is scrolled into view where the padding would move it: a target aligned to the nearest edge and already inside the scrollport less the padding scrolls in neither, where the compiler knows the padding as a length (pixels or rem, through `calc(… * n)` and custom properties the stylesheet declares once). `filter` and `backdrop-filter` (M6, [research](research/M6-CPU-RENDERER.md), cases `filters`, `backdrop-filters`) take lists of the CSS filter functions (`blur`, `brightness`, `contrast`, `drop-shadow`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia`), drawn by both renderers (the forked CPU and GPU renderers, with the same semantics) and animatable; rejected (`E_CSS_PROPERTY`, also through `var()`): `url()` filter references. A `drop-shadow()` without a colour takes the element's `color`; opacity and filters apply to an element's outline, outer box shadows and overflowing content, and a backdrop is clipped to the rounded border box (Blitz fork, case `blitz-filter-layers`). A backdrop-filtered element with an ancestor that is a Backdrop Root (opacity, filter, clip-path, mask, mix-blend-mode) or also a `filter` stops a probe with `E_FILTER` (an app reports it once): Blitz draws them differently ([gaps](BLITZ-GAPS.md)). Gradients are drawn as in Chromium (cases `gradients` and `blitz-gradients`: angle gradients on the background tile, colour stop fix-up, both fixed in the Blitz fork). The SVG painting properties `fill`, `stroke` and their `fill-*`/`stroke-*` longhands apply to inline SVG (Blitz fork, case `blitz-svg-css`), except paint servers (`url()`, also through `var()`); the other SVG-only properties (`marker*`, `paint-order`, `d`, `cx`, `r`, `x`, … ) are rejected (`E_CSS_PROPERTY`): Blitz would ignore them. `:target` selectors are rejected (`E_CSS`): Blitz never matches them; so are selectors giving an SVG child element (`path:hover`, `g:active rect`) a `:hover` or `:active` state, which Blitz never matches on SVG children (a class selector that lands on one cannot be found and still differs, [gaps](BLITZ-GAPS.md)). With `"tailwind": true` in runic.json, Tailwind CSS 4.3.3's Vite plugin generates the stylesheet, and its output is what these checks apply to. Resources must be bounded local WOFF2 files (`format("woff2")` or `format("woff2-variations")`); native builds require one embedded font.

## Language

Every adapter lowers ordinary code through the shared layer. TypeScript's checker supplies types; in untyped JavaScript the frontend infers IR types from the lowered values and specialises untyped helper functions per call-site argument types.

**Values** ([value model](design/M2-VALUES.md)): numbers with exact double semantics; UTF-16 strings; booleans; `null`/`undefined` and nullable types (`T | null | undefined`); string/number/boolean literal unions; objects with a fixed shape (records); arrays; `Map`/`Set`; functions and closures. Class instances (below). Other unions, `any`/`unknown` that cannot be inferred, symbols, bigint and tuples with optional or rest elements are rejected with `E_TYPE_UNSUPPORTED`/`E_TYPE_UNION`. M6 overlays: a tuple of items of different types (a `Map`'s entries) is read by literal index and destructuring; its length, iteration, spreads, string conversion, `JSON.stringify` and `Object.keys/values/entries` are rejected (JavaScript treats it as an array).

**Statements and expressions:** `const`/`let`, assignment and compound assignment to locals, cells, fields and array elements; `if`, `switch`, `while`, `do`/`for`/`for-of` with labelled `break`/`continue`; functions, arrow functions and closures (captured variables are shared by reference); `return`, `throw`, `try`/`catch`/`finally`; template literals; object/array destructuring and spread; optional chaining and `??`; all arithmetic, bitwise, comparison, logical and `typeof` operators; `Number`/`String`/`Boolean` conversions.

**Built-ins:** `Math`, `Number`, string and array methods, `Array.from`/`isArray`, `Object.keys/values/entries/assign`, `JSON.stringify`/`JSON.parse` into a declared type, `Map`/`Set` and `structuredClone`, as listed in [M2-VALUES](design/M2-VALUES.md). `RegExp` with ECMAScript semantics (literal and constructed patterns, flags `dgimsuy`; `exec`, `test`, `match`, `matchAll`, `replace`, `replaceAll`, `search`, `split`; `v` and the static members are rejected). `Date` (construction, `Date.now/UTC/parse` as V8 parses, all getters and setters in local and UTC time, the string and ISO forms) in the case's or system's time zone. `Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.Collator`, `toLocale*String` and `localeCompare` for en-US, en-GB, de-DE, fr-FR and ja-JP (and en, de, fr) with the option combinations pinned by Chromium vectors; other locales and options are rejected (`E_INTL`). M6 (case `plural-names` in Svelte, React and Vue): `Intl.PluralRules` `select(n)` and `resolvedOptions().pluralCategories` (and `.type`), cardinal and ordinal (`type`), for every locale Chromium has plural rules for (its own ICU data: a tag without rules of its own takes the default locale's, as Chromium does); `Intl.DisplayNames` `of(code)` for the types `region`, `script`, `currency` and `language` (dialect names such as "American English", or `languageDisplay: "standard"`), `fallback` `code` or `none`, in the display locales en-US, en-GB, de-DE, fr-FR, ja-JP, en, de, fr and ja. Language tags are a language with an optional script and region, canonicalized as V8 does (`iw` is Hebrew); a malformed tag throws a `RangeError` as in Chromium. Their locales may be computed at run time (and their options chosen by a condition, `ordinal ? { type: "ordinal" } : undefined`) where the object is constructed at its use (`new Intl.PluralRules(locale).select(n)`); constants need literal locales. Rejected (`E_INTL`): digit and rounding options of plural rules, `selectRange`, `resolvedOptions()` members other than those, other display name types and styles, unverified literal display locales; at run time, an unverified display locale, variants and extensions (`en-u-nu-arab`) and regions that alias several regions (`SU`) are reported unsupported (`RunicUnsupportedError`, which a probe or the interpreter does not let a program catch silently). Identifiers resolve by symbol, so a local `Math` shadows the global one. Unknown globals and methods are rejected (`E_UNRESOLVED`, `E_MEMBER`, `E_BUILTIN`).

**Time and async:** `setTimeout`/`setInterval`/`requestAnimationFrame` and their `clear`/`cancel` functions, `queueMicrotask`, `Date.now()` and `performance.now()`. `Promise<T>` with `new Promise`, `Promise.resolve/reject/all` and `then`/`catch`/`finally`, in ECMAScript's microtask order (adopting a returned promise costs two ticks). `async` functions and arrows, including event handlers: `await` as a statement, in `const x = await e`, `x = await e`, `x op= await e` and `return await e`, inside `if`, loops, `for-of` over arrays and `try`/`catch`. Rejected: `await` nested in other expressions or conditions, `finally` around an `await`, `for await`, generators, and closures capturing a loop variable across an `await` (`E_ASYNC`). Rejection reasons are Error records. Unhandled rejections (M6, cases `rejections` and `rejections-timer` in Svelte, React and Vue) are reported as Chromium reports them: a console error line `Uncaught (in promise) Name: message` (`Name` alone for an empty message) in a task after the microtask checkpoint that left the promise without a handler, for each promise still without one then, in rejection order; the program cannot observe it. A handler added after the report (Chromium revokes it) is reported unsupported. Vue catches a promise a listener returns and logs it with `console.error` (its production `callWithAsyncErrorHandling`), so it is not reported unhandled.

**Host services:** `localStorage.getItem/setItem/removeItem/clear` (native apps keep it in `$XDG_DATA_HOME/runic/<title>/localStorage.json`; `key()`, `length` and the `storage` event are rejected); `console.log/info/warn/error/debug` with primitive arguments (stderr natively; format strings rejected); `navigator.clipboard.writeText/readText` (the OS clipboard natively); `history.pushState/replaceState` with a null state, `back`/`forward`/`go(n)`, `history.length`, `location.pathname/search/hash` and assigning `location.hash`, with `popstate` and `hashchange` on the window; `Math.random` and `crypto.randomUUID`. The document element (`dataset`, `classList`, `style.setProperty/removeProperty`, `lang`, `dir`), `document.body` and `document.querySelector` of the literal selectors `body` and `#id` (M6), and `matchMedia(q)` / `window.matchMedia(q)`: `matches` and `change` listeners for `prefers-color-scheme`, `prefers-contrast`, `prefers-reduced-motion`, width, height and orientation. Templates and derived values must not use host services (`E_REACTIVITY`).

**Reactivity checks** (all frameworks): a template must not read a value that changes without the framework noticing, which the frameworks would show only when neighbouring state re-renders: a non-reactive variable that is written, a reference tracked by identity but mutated in place, a `Map`/`Set` mutated inside Svelte state, a mutated module object, a RegExp whose `lastIndex` changes or a Date changed by a setter (`E_REACTIVITY`). React state and props must not be mutated in place (`E_READONLY`).

**Classes** (M6 stage A, [design](design/M6-LIBRARIES.md#library-code-steps-3-to-6), case `classes`): class declarations at the top level of local modules and of Svelte and Vue component scripts (React components use module-level classes), in TypeScript or in JavaScript whose fields TypeScript can type (annotations, JSDoc, initialisers). Instance fields with and without initialisers, TypeScript parameter properties, fields the constructor creates by assignment, `#private` fields and methods, methods, getters and setters (compound assignments call both), static methods and static fields (module classes only; constants), `new C(…)`, `this` in methods, accessors, constructors, field initialisers and the arrow functions inside them, and `x instanceof C` (decided by the static type of `x`). A method is a value only when bound: `this.m = this.m.bind(this)` at the start of the constructor makes `m` a field holding a bound function, `obj.m.bind(x)` creates one, and arrow function fields keep their instance; `f.bind(x)` of a function value makes a new function (`x`, which it ignores, is `this`, `null`, `undefined` or a variable). Methods dispatch on the class of the receiver (statically where its type names one class; see inheritance below). An instance is built as JavaScript builds it: field initialisers in order, the constructor's leading `this.f = …` assignments, then the rest of the constructor; before the instance exists, `this` may only be read as an earlier field, inside an arrow function stored whole in a field, or bound. Svelte `$state` holds instances as they are (no proxy), so mutating one that the template reads is `E_REACTIVITY`; Vue refs proxy them as Vue does. **Generic classes** (M6 overlays, bits-ui's `TimeoutFn<T>`; `tests/generic-classes.test.mjs`) take the one instantiation of the program: the type arguments of every `new C(…)` and `C<…>` must map to the same IR types, and the type parameters stand for them in the class (parameter types are TypeScript's instantiated signatures, so `...args: Parameters<T> | []` is resolved; inside the class `Parameters<T>` of a type parameter bound to a function type is its parameters, and calling a value of type `T` takes its IR function type). A type parameter no member mentions (`TooltipTether<Payload = never>`) is left unbound. Rejected: a second instantiation (`E_CLASS`, at its site; compiling per instantiation is not implemented), an instantiation with a type parameter, and a generic class never instantiated with type arguments. Rejected (`E_CLASS`): anonymous classes, class expressions, decorators, `accessor` and `declare` fields, computed and quoted member names, overloads, static blocks and accessors, unbound method references, other uses of `this` before the instance exists, `return` in constructors, fields not set before the constructor otherwise uses `this` (unless optional), use before the declaration, `JSON.stringify`, `structuredClone`, `Object.keys/values/entries/assign`, spreads and string conversion of instances, object literals typed as a class, `instanceof` on values of unknown type (caught exceptions), assigning static fields, static fields of component-script classes, partial application with `bind`, and Vue refs of classes whose constructor keeps the raw `this` in closures (arrow function fields, bound methods), whose writes Vue's proxy would not see.

**Reactive class fields** (M6 stage B, [design](design/M6-LIBRARIES.md#reactive-class-fields-stage-b), case `reactive-classes`): in Svelte component scripts and `.svelte.ts`/`.svelte.js` modules (where Svelte compiles runes; components import them with the full name, `./todos.svelte.ts`), a field initialised with `$state(v)`, `$state.raw(v)`, `$derived(e)` or `$derived.by(f)`, public or `#private`, or a field the constructor assigns one of them as a leading `this.f = …` statement. They behave as Svelte 5.57.1's signals: reading one is a dependency of the running `$effect` or derived value (unless that computation created the instance), and the template updates after writes. A write notifies when the new value is not `===` the old one (`-0` over `0` changes nothing and keeps `0`; `NaN` over `NaN` notifies); `$state` stores proxies of plain objects and arrays (deep state, as component `$state`), `$state.raw` and class instances are stored as they are. Derived fields are computed from the instance when first read, cached until what they read changes, and keep their value when a recomputation gives an `===` one, so effects reading them re-run only when it changed. Instances can live in component constants, state, other instances' fields and module constants. Rejected: assigning a derived field (Svelte 5.25+ overrides), `$derived` in the constructor reading the constructor's parameters or locals, reactive fields assigned after the constructor otherwise uses `this`, runes in plain `.ts`/`.js` modules and in React and Vue code (`E_CLASS`); writing reactive state from a template expression or a derived value, directly or through the functions they call, unless that code created the instance (Svelte throws `state_unsafe_mutation`), derived fields that change values they did not create or use host services, template reads of `$state.raw` values mutated in place and of plain fields written after construction (`E_REACTIVITY`); reading a derived field of a component-script class in another component.

**Inheritance and class references** (M6, [design](design/M6-LIBRARIES.md#inheritance-and-class-unions), case `class-hierarchy` in Svelte, React and Vue): single inheritance (`class B extends A`) between classes compiled from source, declared in the same module scope or component script. An instance has its base classes' fields first. Construction follows JavaScript: the statements before each `super(…)` (which must not use `this`) and its arguments from the class up to the root, then from the root down each class's parameter properties, field initialisers and the rest of its constructor; a class without a constructor passes its arguments on. Methods, getters, setters, static methods and static fields are inherited and can be overridden; `super.m(…)`, `super.x` (a getter) and `super.x = v` (a setter) call the base class's member; `#private` names belong to the class declaring them (a subclass may declare its own of the same name). Abstract classes, abstract methods and abstract properties (implemented by the subclasses' methods and fields); reactive fields (`$state`, `$derived`) in base classes and subclasses. A value TypeScript types as a class that has subclasses, or as a union of classes, keeps its instance's class: a member its classes declare differently (overrides, abstract members, a field each class of a union declares) is chosen by that class; `instanceof`, discriminant checks (`x.kind === 'single'`) and `as` assertions narrow it, and an assertion TypeScript cannot check (`as unknown as C`) throws a `TypeError` where the instance is of another class (JavaScript would continue with the wrong object). Every class of the program's sources is known, so a class's subclasses are all its subclasses there. Rejected (`E_CLASS`): extending library classes (`Error`, `MediaQuery`; mapping packs will provide them), mixins and other base expressions, generic base classes, `super(…)` other than as one statement at the top level of a constructor, `this` before `super(…)`, `super.x` of a field (JavaScript reads the prototype) or of an abstract member, redeclaring an inherited field (except without an initialiser, assigned at the top of the constructor before it otherwise uses `this`: bits-ui's `opts` of narrower options types, which then share one record with the types constructors pass on to the base; a field only some of them have is read through a type that has it, a `TypeError` if the program broke its types), extending a class of another module scope or component script, a base constructor that uses `this` beyond its leading field assignments when a subclass declares fields (JavaScript would run that code before the subclass's fields exist), assigning through a union a field its classes declare separately, binding a method that subclasses override through the base type, and arrays, maps, sets and functions of a subclass type used as ones of the base type (they keep their identity).

**Object keys** are observable (`Object.keys`, `JSON.stringify`), so a record keeps the key order of the literal that creates it; a spread contributes its source's keys in their order. A literal whose properties are in a different order than its declared type is rejected (`E_OBJECT`).

**Modules:** components can import named bindings from local `.js`/`.ts` modules, with aliases, export lists and named re-exports, and import other components (`.svelte`, `.vue`, function components). Modules initialise once, dependencies first. Module functions become shared functions; constants become program globals, evaluated once in order (object constants keep their identity). Module objects may be mutated (they are not reactive). Barrels (M6, [design](design/M6-LIBRARIES.md#library-modules-step-3), case `shadcn-basics`): `export { default as X } from './x.svelte'`, `import Root from …; export { Root, Root as Button }`, `export *` and `export * as N`, chained through any number of modules, and names a module re-exports from a package (`export { cn } from "cn"`), which keep the package's [pack](#packages). Namespace imports (`import * as Card from …`) name components as tags (`<Card.Root>`, Svelte) and may be re-exported; using a namespace as a value is rejected (`E_IMPORT`). Top-level statements (other than [module state](#language)), default imports of plain modules, cycles, `export *` of a package and npm dependencies without a mapping pack are rejected (see [Packages](#packages)).

**Library code (M6):** objects whose TypeScript type has only a string index signature (and constant keys of its value type) are dictionaries (maps), read and written by key, also with computed keys; reading a key that names a member of `Object.prototype` (`toString`, …) or writing `__proto__` throws `RunicUnsupportedError`. A record read with a computed key of its field names (`{ horizontal: …, vertical: … }[orientation]`). Unions of plain object types are one record (key sets untracked: key-observing built-ins reject it). `Object.is`. Tests the IR types decide in untyped package code (`Array.isArray(x)`, `typeof x === "…"` of a local) keep their one branch; callbacks of array methods in untyped code take the element type; parameters typed `unknown` are specialised per call site; an untyped `let x;` takes the type of the values assigned to it. Methods bound into their fields later in a constructor (`this.m = this.m.bind(this)` after other statements) are bound when the instance is built, when nothing before reads them other than by calling them.

**Module state** (M6 overlays, `tests/module-state.test.mjs`; bits-ui's scroll lock and keyboard tracking): a `let` at the top level of a local or package module is state that lives as long as the program, initialised in order with the module's constants, read and written by its functions (also through `export let`, a live binding). In modules Svelte compiles runes in (`.svelte.ts`, `.svelte.js`), `let x = $state(v)` and `$state.raw(v)` are signals as Svelte's module state is: reads in effects, derived values and templates are dependencies, writes update them. A plain module variable that a template reads and code changes is `E_REACTIVITY` (Svelte would not update it). An untyped JavaScript variable takes the types of its initialiser and of the values the module assigns it (nullable where one is null or undefined; values of different types are `E_MODULE`). Rejected (`E_MODULE`): `var`, destructuring, other runes; `$state` in a component's module script (`E_RUNE`).

**Build-time conditions** (M6): a condition whose value is known at build time (literals, constants of packs such as esm-env's `DEV`, module constants of packages compiled from source evaluated at build time, `typeof` of the host's globals, which are objects natively, and `!`, `===`, `!==`, `==`, `!=`, `&&`, `||`, `??` over them) decides `if`, `?:`, `&&` and `||` at build time: the branch never taken is not lowered (it never runs), so code only a development build runs is not rejected. A closure created in its own variable's initialiser (`const o = new ResizeObserver(() => … o …)`, a function calling itself) shares the variable's binding. In a test (`if`, loops, `?:`, `!`), `a && b` and `a || b` combine their operands' truthiness, so the operands may have different types.

**ResizeObserver** (M6, case `resize-observer`): `new ResizeObserver(callback)` with `observe(target, { box })` (a literal `content-box`, `border-box` or `device-pixel-content-box`), `unobserve` and `disconnect`; the callback receives the entries (`target`, `contentRect`, `borderBoxSize`, `contentBoxSize`, `devicePixelContentBoxSize`) and the observer, after layout and before paint as Chromium delivers them ([IR](IR.md#template)). Programs that observe are checked against Chromium only (the interpreter has no layout).

**IntersectionObserver** (M6 overlays, case `floating`): `new IntersectionObserver(callback, { root, rootMargin, threshold })` with the document's viewport as root (`root` absent, null or the document), `observe`, `unobserve` and `disconnect`; the callback receives the entries (`boundingClientRect`, `intersectionRatio`, `intersectionRect`, `isIntersecting`, `rootBounds`, `target`, `time`) and the observer in a task after the frame whose layout changed them ([IR](IR.md#template)). Element roots, `scrollMargin` and targets under an ancestor transformed other than by a translation, or under a `clip-path`, are not covered. Chromium notifies observers with a document root in an order of its own (its observer set's), not in creation order as the runtime does: a program whose observers are notified in one frame may see another order.

**DOM reads and listeners for overlays** (M6 overlays): `element.getClientRects()` (the border box; an inline element's line boxes are reported unsupported), `element.hidden` (the attribute's presence; `until-found` throws `RunicUnsupportedError`), `x instanceof Element` and `instanceof Node` of element values, `document.documentElement.clientWidth/clientHeight`, `getComputedStyle(element).zIndex` (and `direction`), `window.devicePixelRatio`, `event.pointerType`, element `scroll` listeners added by script (`addEventListener`/`removeEventListener`, identified by their function value) and the visual viewport's `resize` and `scroll` listeners (it resizes with the window, its listeners called after the window's; it never scrolls without pinch zoom). Listener options are rejected.

## React

The entry calls `createRoot(document.getElementById('root')).render(<App />)` for a local function component. Every function component is a component with instances: a rendered `<Child/>` gets its own state, created and destroyed with its region (a conditional branch, a list item), so state resets on remount. A component body holds `useState` declarations (non-lazy initialisers), const render values, nested functions and one returned JSX tree; expression-bodied arrow components are accepted. Reads see the render snapshot of the last commit, and closures created in a handler or effect keep the snapshot they were created with (stale closures). Setters with values or updater functions queue in order; discrete events (click, input, change, keydown) render in a microtask, other updates (timers, promises, effects) in a later task.

- **Props:** destructured or through a `props` parameter, typed by TypeScript or, in JavaScript, by the first call site. Callbacks are function props. `children` and other `ReactNode` props rendered as `{children}`, and render props `(x: T) => ReactNode` called as `{row(x)}`, are slots evaluated in the parent.
- **Lists:** `items.map(item => <Row key={…}/>)`, keyed or (without a key) by index, with React's forward-placement reorder; React DOM's focus restore after a commit is reproduced. A `key` elsewhere remounts its element when it changes.
- **JSX:** the native tag allow-list (with `textarea`, `label`, `select`, `option` and inline SVG, below), string and expression attributes (entities decoded), `className`, inline `style` objects (keys written inline, set through the CSSOM as React DOM does), `&&`/`?:` conditionals, fragments, rest props and spread attributes (`{...rest}`, listeners included) and refs passed as props.
- **Events:** event objects (`type`, keys and modifiers, pointer coordinates and buttons, `target`/`currentTarget`, `preventDefault`, `stopPropagation`) for click, double click, context menu, key, pointer, mouse and focus events (`onFocus`/`onBlur` from `focusin`/`focusout`, with `relatedTarget`); continuous events (pointer and mouse moves, enters and leaves) only where React's later render is unobservable; `onScroll` (M6, React's continuous lane, cases `scroll-lane` and `virtual-list` with the React virtualized list): its updates render in a default-priority task after the frame (after the listener's microtasks and the frame's ResizeObserver notifications), and a discrete update before that task renders them with its own, as React does; timers posted by a scroll listener are rejected (Chromium runs them before that render); window and document listeners. Controlled text inputs, text areas (`value` with `onChange`), checkboxes, radio buttons (`checked` with `onChange`, exclusive named groups) and selects (`value` with `onChange`), restored after every dispatch as React DOM does. `onWheel` is rejected.
- **Refs:** `useRef<HTMLInputElement | null>(null)` attached with `ref={r}` to one element of the same component; `r.current` reads the live element (`focus()`, `blur()`, null checks). `useRef` of numbers, strings and booleans is a mutable box that never re-renders. Callback refs, refs passed to components, one ref on several elements, refs in list items or slot content, ref reads during render and refs holding objects are rejected.
- **Effects:** `useEffect` and `useLayoutEffect` with no dependency array, `[]` or a literal array of values; their functions and cleanups read the render that created them. Layout effects run after the DOM update children first; all cleanups of a phase run before its effects; passive effects' state writes render in a later task; unmount cleanups run parent first, layout before DOM removal and passive after.
- Rejected: effects outside the component body's top level or in custom hooks (`E_HOOK`), non-literal or spread dependency arrays and object or function dependencies other than state and props, async effect functions, microtasks queued in layout effects, `useInsertionEffect`, `useMemo`, `useCallback`, lazy initialisers, conditional or list regions whose unmount cleanups React would order by element position, nested prop destructuring, style strings and computed style keys, `select multiple`/`defaultValue`, controlled controls without `onChange`, `focus()` outside discrete event handlers where focus listeners exist, recursive components.

## Vue

The entry calls `createApp(App).mount('#root')` on a local SFC with `<script setup>` (JS or TS). Setup supports `ref`, `computed`, functions, const values and local module imports; `ref` reads see earlier writes immediately and nested mutation is tracked. `computed` values are cached and recompute when what they read changed. Templates support the tag allow-list, static attributes, `:attr` bindings, `:class` (objects, arrays, strings, normalised and merged with a static class) and `:style` (objects, arrays, strings, applied as `patchStyle` does), interpolation and `v-if`/`v-else-if`/`v-else`. Fallthrough attributes and `v-bind="$attrs"`/object spreads are applied as Vue merges them. Vue marks `#root` with `data-v-app`.

- **Components:** child SFCs are instances. `defineProps<T>()` (destructured or as an object, optionally with `withDefaults`), `defineEmits<T>()` (as `on<Event>` callbacks) and `defineModel<T>()` with the parent's `v-model`.
- **Lists:** `v-for` over arrays with `:key`, keyed or by index, with Vue's longest-increasing-subsequence reorder.
- **Slots:** `<slot>` outlets (default, named, scoped, with fallback), typed by `defineSlots<T>()` or inferred; `<template #name>`, `v-slot` and default content in the parent, with destructured slot props.
- **Events and forms:** event objects for click, double click, context menu, key, pointer, mouse and focus events (`@focus`, `@blur`, `@focusin`, `@focusout` with `relatedTarget`), with `withModifiers`/`withKeys` modifiers; several listeners of one event run in order. `v-model` and `:value` on text inputs and text areas (re-applied at every re-render where they differ, as Vue patches them), `:checked`/`v-model` on checkboxes, `v-model` on selects and radio buttons with literal values. `@scroll` is a native listener on the element (as Vue adds it); `.once`, `.capture` and `.passive` are rejected.
- **Refs:** `ref="name"` on an element (or a component that forwards it) bound to a `ref()`/`shallowRef()` of that name or to `useTemplateRef<T>('name')`; the ref holds the element while it is mounted and `null` after removal. Refs read during rendering, writes to template refs, `:ref`, refs in `v-for` or slot content and refs on components, slots or `<template>` are rejected.
- **Watchers and lifecycle:** `watchEffect` (with `onCleanup`/`onWatcherCleanup`) and `watch` of refs, computeds, getters or arrays of them (`immediate`; the callback receives the new and old values) run before the component updates; `onBeforeMount`, `onMounted` (synchronously within `mount()`), `onBeforeUnmount` (DOM attached, parent first) and `onUnmounted` (after removal, children first). `nextTick()`/`nextTick(fn)` resolve when the pending flush ends. Each listener ends with a microtask checkpoint, as Vue attaches listeners to elements.
- Rejected: `deep`/`once`/`flush: 'post' | 'sync'` watchers, `onUpdated`/`onBeforeUpdate`, watching props or reactive objects, watchers whose writes another watcher of the component reads (Vue's queue order), regions whose unmount work Vue would run before later siblings are created, other directive modifiers, `v-model` modifiers and `v-model` on other input types, text controls whose re-renders Runic cannot match (object or function props, listener fallthrough, slot outlets, side-effecting template expressions), `:checked` on radio buttons, `v-show`, dynamic slot names, `$slots`, slot content that may render nothing where the child has a fallback.

Scripts support `$state`, `$state.raw`, `$derived`, `$derived.by`, functions, `let`/`const` values and module imports. Reads see earlier writes immediately; derived values are cached and recompute when what they read changed. Markup supports the tag allow-list (M6: with `dl`, `dt`, `dd`, `figure` and `figcaption`; the inert `sup`, `sub`, `kbd`, `samp`, `mark`, `time`, `data`, `abbr`, `dfn`, `var`, `cite`, `del`, `ins`, `s`, `u`, `blockquote` and `address` in Svelte, React and Vue, case `text-elements`; and `form`, whose submission and reset are not modelled: a submit or reset button's activation and Enter in a form's text field are reported unsupported, `tests/form.test.mjs`; attribute names may hold underscores), attributes with expressions (an empty `class` is omitted; nullable numbers and booleans are absent when nullish, otherwise their string, as `set_attribute` writes them), interpolation and `{#if}`/`{:else if}`/`{:else}`.

- **`<script module>`** (M6): its statements are a module of their own, initialised once in module order (constants, functions, classes, `tv()` definitions of the tailwind-variants pack, imports); the instance script and the template see its names, and other modules import its exports (`import Root, { buttonVariants } from './button.svelte'`). Components a program never instantiates still provide their module scripts.
- **Component tags** resolve through imports, barrels and namespace imports: `<Button>`, `<Card.Root>`.
- **Component styles** (M6, bits-ui's Select viewport): a `<style>` whose rules are all `:global(…)` joins the stylesheet Vite emits and is checked with it. Scoped rules are rejected (`E_TEMPLATE`): lowering does not add Svelte's scoping class.
- **Component values** (M6, SvelteKit phase 2, case `kit-docs`): a component imported and named in an expression (`component={ButtonDemo}`), or the default export of a module an `import.meta.glob` loads, is a value of svelte's `Component` type: one object per component (`===` is identity, `typeof` is `"function"`; `String()`, `JSON.stringify` and key-observing built-ins reject it). A tag naming a variable (`<Markdown viewerData={…} />`) renders the component it holds: its candidates are the program's component values whose required props (destructured from `$props()` without a default, not optional in the props type) the tag passes; the tag becomes one copy per candidate behind an `if` chain on the value, so a new value destroys the old instance and creates the new one, as Svelte does. A nullish value renders nothing; another component, possible only through casts TypeScript cannot check, throws `TypeError`. A tag no component value fits is `E_TEMPLATE`. Props a child neither declares nor collects in rest props are not evaluated (Svelte passes them as getters nothing reads).
- **`import.meta.glob`** (M6) in script modules, with literal patterns (from `/` or relative) and the options `eager`, `import` and `query: '?raw'` (with `eager` and `import: 'default'`: the files' text): Vite 8.3.2's table (its files, sorted, `node_modules` ignored), lazy loaders resolving after Vite's preload helper and Rollup's inlined dynamic import (two chained microtask steps) to the module's namespace object, built from the fields of the module type the call names (`import.meta.glob<{ default: Component }>(…)`, a local object type; required without `import`). Other options and globs in component scripts are `E_GLOB`.
- **`{@html value}`** (M6): HTML is parsed at build time, never at run time. A constant string (the markdown preprocessor's highlighted code) is its own fragment; any other string value may be one of a SvelteKit app's build-time data strings (server data, endpoint responses), each parsed into a fragment; the runtime shows the fragment whose string is the value (nullish and empty: nothing; another string: `RunicUnsupportedError`). Fragments hold static elements of the template allow-list without links, controls or SVG, with plain attributes (no event handlers); others are `E_TEMPLATE`. Svelte's `html()` parses as a `<template>` element's `innerHTML` does; the fragments are parse5's HTML fragment parsing.
- **Markdown and other preprocessed modules** (M6): see [SvelteKit](#sveltekit) generation. Module scripts may destructure a record into constants (`const { title } = metadata`, as mdsx writes them).
- **`<svelte:element this={tag}>`** (M6) with a tag from a finite set of HTML elements of the allow-list (literals, conditionals, literal-union values, props whose sites pass them): one element per tag, recreated with its content when the tag changes; a nullish tag renders nothing.
- **Links** (M6): `<a href>` is focusable and followed by a click or Enter, as a fragment navigation (`popstate`, then `hashchange` when the fragment changed; following the same link again replaces the history entry). `href` values must be a finite set of fragments (`#name`) that name no element and are not the document top (`#`, `#top`); other links (other documents, the top, a fragment naming an element: scrolling to and focusing it) are rejected (`E_TEMPLATE`), as are `:target` selectors (`E_CSS`, Blitz never matches them).

- **Deep state:** `$state` stores proxies of plain objects and arrays, with Svelte's identity: storing a raw object gives a new proxy, and only writes through the proxy are reactive ([ownership](design/M3-COMPONENTS.md#svelte-deep-state-ownership)).
- **Components:** child components are instances; `$props()` with defaults, `$bindable` and rest props (`...rest`, forwarded with `{...rest}` spread attributes, listeners included), `bind:prop`, callback props, `bind:this` on components and on elements into a `$bindable` prop (`ref = $bindable(null)`). Rest props typed by svelte/elements' attribute interfaces (`WithElementRef<HTMLButtonAttributes>`) are attribute bags as before.
- **Lists:** `{#each}` with index, key, destructured items and `{:else}`, with Svelte's keyed reconcile; `{#key}` remounts its content.
- **Snippets:** `children`, named snippets and `{@render}` with arguments.
- **Events and bindings:** event attributes for click, double click, context menu, key, pointer, mouse, wheel, focus and `scroll` events with event objects; `<svelte:window>`/`<svelte:document>` and `window`/`document.addEventListener`. `class:` and `style:` directives (composed as `to_class`/`to_style`). `bind:value` on text inputs, text areas and selects, `checked`/`bind:checked` on checkboxes, `bind:group` on radio buttons with literal values, `bind:this` element refs, labels.
- **Effects:** `$effect` and `$effect.pre` re-run when the state, derived values or proxied properties they read change; `onMount` and `onDestroy`; `tick()`. Cleanups read the component state (`$state` and props) as it was before the flush (reactive class fields and module state as they are now: Svelte gives them their previous values too, which is not modelled), and teardowns run after the DOM is removed. M6: `$effect`/`$effect.pre` also inside functions that run while an instance is created (class constructors, runed's `watch`): a pre effect runs at once, as Svelte runs it; elsewhere they throw `RunicEffectError`. `$effect.root(f)` (case `effect-root`): `f` runs at once; the `$effect`s it creates belong to the root (they survive the instance that created it) and run after the instances' effects of each update until the function it returns destroys the root (their cleanups, then `f`'s). A `$effect.pre` in a root is reported unsupported; Svelte orders a root created during an instance's creation among that instance's effects (here after them).
- **Imperative mounts** (M6 overlays, [design](design/M6-OVERLAYS.md), case `portal`): `mount(Component, { target, props, context })` from `svelte` in a component script's functions (effects, runed's `watch`), with `target` the body (`document.body`, `document.querySelector('body')`; another element is reported unsupported at run time), `props` the component's props or snippet props of the mounting component forwarded to its snippets (they keep the mounting component's scope; snippets with parameters are rejected), and `context` from `getAllContexts()`; `unmount(instance)` (no outro options). The content is the body's last child at its mount, updated with the app, and destroyed by `unmount` (not by destroying the mounting component). Verified with a copy of bits-ui 2.19.2's Portal whose target is the body: bits-ui's own Portal resolves its target through `PortalTarget = Element | string`, a union outside the value model (rejected, `E_TYPE_UNSUPPORTED`). Other mount options (`anchor`, `events`, `intro`) are `E_MOUNT`.
- **`{#key snippet}`** (M6) of a snippet prop renders its content once (an instance's snippets are fixed when it is created).
- **Library features** (M6, as bits-ui uses them): `$props.id()` (`c1`, `c2`, … in creation order); `untrack(fn)`; `on(element, 'beforematch', handler)` from `svelte/events` (Blitz never fires it); contexts through runed's `Context` (set while an instance is created, read up the instances that render it); props whose passed `undefined` takes the default; snippets passed on through rest props and tested for presence. Top-level statements of component scripts other than declarations (`State.create(…)` called for its effect, `watch.pre(…)`, `if`) run while the instance is created, in order with the declarations. `$state.snapshot(v)`. `SvelteMap` from `svelte/reactivity` (`get`, `has`, `set`, `delete`, `clear`, `size`; no initial entries or iteration): its reads depend on the whole map, where Svelte's depend on one key, so it may be read only in `$derived` values and derived class fields (effects would run where Svelte's do not: `E_REACTIVITY`). Props typed wider than the value model (svelte/elements' `value?: any`) take the types their sites pass, also through spreads and rest props passed on; a required prop given through a wrapper's rest props that every site of the wrapper passes. Snippets and children may take fewer parameters than they are rendered with. A bare attribute passes `true` to a component. camelCase props in bags (lowercased where a spread sets them on an element, as `setAttribute` does). A spread's `value` is assigned to the element's property (an attribute only where the property reflects it: `button`, `option`, `data`; reported unsupported on inputs and the like) and an input's `checked` to its live state, as Svelte's `set_attributes` does. `bind:value` on a text input bound to a nullable string. Props typed by a discriminated union (bits-ui's `type: "single" | "multiple"`) take the member's types when every site passes one discriminant literal, also through a wrapper's rest props. `bind:prop` of a variable of the present type to an optional prop that its component only sets to present values (followed through the component's own `bind:`s; otherwise `E_TEMPLATE`); a type assertion on the bound variable (`bind:value={value as never}`). `setContext`/`getContext` from `svelte` with string literal keys in `<script module>` functions: one context per key program-wide, typed by what the program sets; a read where no parent set it gives `undefined`, or throws `RunicUnsupportedError` where its type cannot hold it (`getContext<Required<T>>`). Objects written with getters (`{ get variant() { … } }`): their type's objects hold a getter per property, called at each read (read-only; every literal of that type uses getters).
- **Overlay layers** (M6 overlays): `{@const name = value}` of text, numbers, booleans and attribute bags computed without effects (evaluated as its block renders, where Svelte memoizes it; values with identity are rejected, `E_TEMPLATE`); `{#if}` tests that the props' values decide at every site render only their branch (`{#if type === "file"}` where no site passes `type`), as do tests of a snippet prop every site passes, also through rest props and `mergeProps` bags, or none does (bits-ui's Arrow under shadcn's tooltip, whose `child` snippet leaves its `<svg>` unrendered), and binds in a branch that cannot render do not make a prop written; a prop a child neither declares nor collects is never evaluated (Svelte passes a getter nothing calls); rest props carry numbers, arrays, objects and elements to the components that declare them (onto an element a number is its text; other such values are reported unsupported); `on<event>capture` listeners in bags (capture phase, from the root to the target, also for focus and blur); a nullable spread (`{...portalProps}`) spreads nothing when nullish; a plain object where a bag is expected (`{ props: state.props }`) is a bag of its properties.
- **Spreads** (M6): `{...bag}` onto elements and components takes attribute bags: rest props, `mergeProps` results, bits-ui's `props` objects, class fields typed `Record<string, unknown>` whose derived value is an object literal, and `child` snippet arguments. Snippets a component receives in its rest props are passed on by spreading the rest props or a `mergeProps(…)` constant of them onto a component; another spread reading the rest props is rejected (`E_TEMPLATE`), as it would lose them. Onto an element, booleans of names without a boolean property (`data-*`, `aria-*`, …) become `"true"`/`"false"`, a `style` string is set through `cssText` when it changes, functions under other names are not attributes, and attachments (`attachRef`) run with the post effects of the instance rendering the element; a `defaultValue` string sets an input's `value` attribute (its value until edited) and a text area's text content, and is an expando elsewhere (`tests/default-value.test.mjs`); a style object, `hidden="until-found"`, a non-string `defaultValue` on a text control, an input's `defaultValue` changing or leaving the bag (Svelte assigns `null`), and `defaultChecked` on an input are unsupported (the native runtime reports them, the interpreter throws). Onto a component, entries reach its declared props (a later entry overriding an explicit attribute; a callback of a compatible type adapted, another kind of value throwing `TypeError`) and the rest its rest props, or are ignored by a component without rest props (Svelte passes them as getters nothing reads); `bind:` after a spread that may hold the name is rejected. A prop whose values must be known at build time (a `class` in `cn(…)`) takes the values the spread's bag holds for it (`tests/bag-values.test.mjs`): object literals, `$derived` values, rest props through their component's sites, snippet parameters through the render sites, and `mergeProps` where one of its bags holds the name (a later bag's class through `clsx`, `hidden` and `disabled` false deleted), with an earlier attribute's value where the bag lacks the name. A number in a style object is printed as its string, as `mergeProps` prints styles. A bag key computed from a finite set of names (bits-ui's `[this.root.getBitsAttr("trigger")]`, the names over the dialog's variants: calls of build-time constants' functions, methods and arrow function fields returning one expression, inlined) is evaluated at run time and gives the entry of the name it is; a name outside the set throws `TypeError`. A prop typed wider than the value model that no site passes, written only by `bind:value` of inputs whose type the props decide is not `number` or `range` (shadcn's Input), is a nullable string. A text control bound to a nullable string whose bound value is nullish when it mounts takes the value its attributes gave it (a spread's `defaultValue`): the binding is written once, as Svelte's `bind_value` does, and the caret stays at the start as in Chromium. An arrow function in a class field declared with more parameters is adapted to the declared type.
- Rejected: `$effect.tracking`, `$inspect`, async effect functions, other `svelte` imports (and `setContext`/`getContext` in instance scripts or with other keys), `svelte/events` exports other than `on` and `on` forms not described above, runes and mutable state in `<script module>`, scoped component styles, legacy `on:` directives, actions, function bindings, rest props read by name in script, top-level statements other than those described under library features, `experimental.async`.

## SvelteKit

M6, phases 1 and 2 of the [design](design/M6-SVELTEKIT.md): single-page SvelteKit apps with universal loads, rendered by Kit's client router ported to the compiled language (`frontend/adapters/kit/`, Kit 2.70.1 `client.js`) over the M5 history; phase 2 adds build-time generators, server data and prerendered endpoints as build-time tables, markdown pages, `import.meta.glob`, component values and `{@html}` of build-time strings. Cases `kit-hash` (hash router), `kit-routes` and `kit-routes-missing` (path router), and `kit-docs` and `kit-docs-narrow` (the shadcn-svelte site's markdown pages for Toggle, Tabs and Separator through its velite and mdsx configurations, fixture `kit-docs-svelte`, with the compiler's checked package versions in place of the site's lockfile pins) compare the native app with the app's real Kit build (adapter-static) served to Chromium.

- **Recognition.** `runic.json` is `{ "framework": "svelte", "kit": true, "title": … }` (no `entry` or `alias`: Kit gives both). `@sveltejs/kit` must be **2.70.1**, the files whose code builds the manifest byte-identical to the published package (SHA-256, `compiler/adapters/kit-pins.mjs`); other versions fail with `E_FRONTEND_VERSION` (Kit 3, and its `vite.config` configuration, is not yet supported). The app's `vite.config` and `svelte.config.js` are never run: `svelte.config.js` is read as literals, accepting `kit.router.type` (`hash` or `pathname`), `kit.router.resolution` `client`, `kit.alias` (with `$lib` → `src/lib`), `kit.output.bundleStrategy` `single` or `inline`, `kit.version.pollInterval` 0, `compilerOptions.runes` `true`, and ignoring the build-only `adapter`, `prerender`, `appDir`, `outDir`, `typescript`, `csp`, `csrf`, `env`, `inlineStyleThreshold` and `serviceWorker`; anything else is `E_KIT_CONFIG`, as are `preprocess` and `extensions` unless a preprocess generation step covers them (below).
- **Generation** (`runic generate <app>`, `compiler/generate.mjs`): `runic.json` `generate` lists steps in order, each with its inputs (globs) and pinned tools (`name@version`, the package's files checked against the SHA-256 in `compiler/generate-pins.mjs`): a command (`node <app script>` or a bin of a pinned tool, with `outputs` directories) or a `preprocess` glob, whose files run through `svelte.config.js`'s `preprocess` list (the only place the compiler imports that file) into `.runic/generate/<step>/<file>.svelte`; `extensions` may then name the preprocessed extension (`.md`). Steps run with `TZ=UTC`, `LC_ALL=C` and `SOURCE_DATE_EPOCH=0`. For a SvelteKit app generation then evaluates the server code (below). `.runic/generate.json` records each step's declaration, tools and the SHA-256 of every input and output, and the server phase's sources and output. Builds never run a step: a missing record, a changed declaration, tool, input or output is `E_GENERATED` at `runic.json`. A preprocessed file is the component module of its recorded output (`content/components/toggle.md` → `toggle.md.svelte` beside it; diagnostics are located in that output).
- **Server data and endpoints** (generation, `compiler/adapters/kit-server.mjs`): for each prerendered page route (`prerender = true`, inner levels over outer, a universal module's option over its server module's), once per entry (`entries()` of the page's modules, or the route itself without parameters), the levels' server loads run in Node through the compiler's Vite (the app's aliases, never its `vite.config`) with Kit's request event (no cookies) and their reads (params, url, route, parent) recorded; the universal loads run as Kit's server rendering runs them (`browser` false) for the URLs they fetch; a same-origin fetch calls the matching endpoint's `GET` (which must be `prerender = true`), and endpoints' own `entries()` add URLs. Server data must be JSON values, one per combination of what the load read. Natively a server load's data is a table by those reads (each lookup new objects, as each response Kit parses), passed to the level's universal load as `data` and invalidated as Kit's `load_route` does; a load's `fetch(url)` is a response from the endpoints' table (`ok`, `status`, `text()`, and `await res.json()` parsed into the type the program declares for it), a host round trip after the first navigation. Server modules export `load`, `prerender`, `ssr` and `entries`.
- **`src/app.html`**: `<html>` attributes become the document's, `<body>` attributes the body's; the body holds one element whose only content is `%sveltekit.body%`, and that element (its attributes kept) is the container instead of `div#root`. The head may hold `<meta charset>`, `<meta name="viewport">` and `%sveltekit.head%`. Scripts, links, styles, titles, event attributes and placeholders in attributes are `E_KIT_HTML`; `data-sveltekit-preload-data`/`-preload-code` other than `off`/`false` (in app.html or on elements) are `E_KIT_PRELOAD`.
- **Routes.** The app's own Kit builds the manifest (`create_manifest_data`): route ids, groups, layout chains with `@` resets, rest and optional parameters, matchers from `src/params` (ordinary compiled functions), Kit's sort order, Kit's default layout and error page. A generated root component nests the layouts through `children` with `data` and `params`; a level whose component is unchanged keeps its instance and gets new props.
- **Loads.** `+page.ts`/`+layout.ts` export `load` (declared function or `const load = (…) satisfies PageLoad`; a `: PageLoad` annotation is `E_KIT_LOAD`) and the page options `ssr` and `prerender` (`true` or `false`: natively every route renders on the client; `true` makes generation evaluate it); others (`entries` included: put it in the server module) are `E_KIT_LOAD`. A level's `params` are strings where every route reaching the level has the parameter. Loads get `params`, `url`, `route` and `parent()`; Kit's dependency tracking re-runs a load only when the params, url parts, route or parent data it read changed. `error(status, message)` renders the nearest `+error.svelte` (Kit's `load_nearest_error_page`), an unknown route the root error page with 404; `redirect(status, location)` navigates within the app. `handleError` from `src/hooks.client.ts` gives the error object (`{ event, status, message }` in; no `error`, since unexpected errors are values Kit logs and the compiled program does not inspect). Data merges with parent data as Kit merges it.
- **Navigation.** Link clicks (absolute and relative `href`, fragments of the current page (a fragment naming an element is followed as Chromium follows it: popstate, the element scrolled into view with block start, focused if focusable and otherwise focus cleared and the element made the navigation starting point, then hashchange), `data-sveltekit-noscroll`, `-keepfocus` and `-replacestate` on the link, an ancestor, the container or `<body>`), `goto(url, { replaceState, noScroll, keepFocus })` returning a promise, back and forward, `beforeNavigate` with `cancel()` (links, `goto`, traversals; a cancelled traversal goes back), `afterNavigate`, scrolling to the top or to the fragment's element (which also becomes the sequential focus starting point), Kit's focus reset, the `#svelte-announcer` live region, and `<svelte:head><title>` setting `document.title` (one `<title>` of text and expressions; the window title stays the `runic.json` title). History entries carry Kit's indices as their state. `beforeNavigate`/`afterNavigate` are called as top-level statements of a component script (registered when the instance mounts, removed when it is destroyed); elsewhere `E_KIT_LIFECYCLE`.
- **Modules.** `$app/state` (`page.url`, `page.params`, `page.route.id`, `page.status`, `page.error`), `$app/navigation` (`goto`, `beforeNavigate`, `afterNavigate`), `$app/environment` (`browser` `true`, `dev` and `building` `false`), `@sveltejs/kit` (`error`, `redirect`, types), `./$types` (generated `PageProps`, `PageData`, `PageLoad`, `LayoutProps`, …). Route components declare `data`, `params` and `children` by destructuring `$props()`.
- **Runtime reports** (`RunicUnsupportedError`, as for other unsupported values): navigations Kit performs by loading another document (external links, `data-sveltekit-reload`, unknown paths through links or `goto` in path mode, redirects to other origins), redirect loops, errors without a `handleError` hook (Kit's default logs a stack trace), a hash edited without router state.
- **Rejected:** server loads of routes that are not prerendered (or have parameters but no `entries()`), endpoints no load fetches and that list no entries, endpoints fetched but not prerendered, form actions, server data that is not JSON or not deterministic (`E_KIT_SERVER`); fetches of other origins, other methods or non-endpoint URLs at generation (`E_KIT_FETCH`); at run time, server data of an entry generation did not evaluate and fetches of other URLs (`RunicUnsupportedError`); `hooks.server`, universal hooks and service workers (`E_KIT_HOOKS`); `$app/stores`, `$app/forms`, `$app/paths`, `$app/server`, `$env/*`, `$service-worker` (`E_KIT_IMPORT`, at the import); `page.data`, `page.form`, `page.state`, `navigating`, `updated`, `onNavigate`, `invalidate*`, `preload*` and shallow routing (`pushState`/`replaceState` from `$app/navigation`), which the modules do not export; a `form` prop or rest props in route components (`E_KIT_COMPONENT`); a route module without a component (`E_KIT_ROUTES`); `catch` clauses in route modules and in modules that reach `@sveltejs/kit` (`E_KIT_CATCH`: `error()` and `redirect()` throw the router's errors); document `click` and window `popstate`/`hashchange` listeners (`E_KIT_LISTENER`: the router owns them); `autofocus` (`E_KIT_ATTRIBUTE`); `<iframe>` as in all Svelte code.
- **Known deviations.** Data objects of different route nodes are compared as different (Kit compares their identity after a `parent()` merge, which only matters for objects shared between loads); a reload does not restore Kit's per-entry scroll positions (Kit keeps them in `sessionStorage`); errors thrown while rendering are not routed to `+error.svelte`; route modules initialise with the program, not when their route first loads; server-rendered pages are not modelled: the native app renders the first page on the client as Kit's SPA mode does (`ssr = false`), where hydration would give `$props.id()` the server's `s1`, `s2`, … ids. The differential is incomplete for Kit apps: the router reads the window's scroll position at every navigation.

## Inline SVG

Icons written inline in templates, as lucide draws them, in all three frameworks ([IR](IR.md#template), case `icons`):

- **Elements:** `svg`, `g`, `path`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `rect`, created in the SVG namespace; `{#if}`/`v-if`/`?:` and lists inside an `<svg>`. An `<svg>` needs a `viewBox`; it may stand in text, flex rows and buttons, sized by `width`/`height` or by CSS.
- **Attributes:** on `<svg>` `xmlns` (the SVG namespace only), `width`, `height`, `viewBox`, `class`, `id`, `role` (ARIA, no rendering effect; M6); on every element the paint attributes `fill`, `fill-opacity`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-opacity`, and `class`, `aria-*`, `data-*`; `opacity` and `transform` on groups and shapes; each shape's geometry. Values are static or bound strings and numbers; class toggles (`class:`, `:class`) work. `currentColor` follows the CSS `color` of the element holding the attribute. Colours in other spaces (`oklch()`, as the shadcn themes are) are converted to sRGB for it.
- **React** maps props as react-dom 19.3's `setProp` does: `className` → `class`; `viewBox`, `width`, `height` keep their names; `fillOpacity`, `fillRule`, `strokeDasharray`, `strokeDashoffset`, `strokeLinecap`, `strokeLinejoin`, `strokeMiterlimit`, `strokeOpacity`, `strokeWidth` → their hyphenated names (`getAttributeAlias`); lowercase, `aria-*` and `data-*` names as written; a boolean `aria-*`/`data-*` value is the string `"true"`/`"false"`. Other camelCase props (`clipRule`, `xlinkHref`, `xmlnsXlink`, `preserveAspectRatio`, …) and props with rules of their own (`focusable`, `style`, …) are rejected (`E_JSX`).
- **Rejected** (`E_SVG`): other SVG elements (`text`, `use`, `defs`, `clipPath`, gradients, …), nested `<svg>`, HTML elements, components, slots or text inside an `<svg>`, listeners, spreads, refs and inline styles on SVG elements, `id`, `style` and `color` on SVG children, attributes outside the list. Stylesheet CSS reaches SVG content (Blitz fork): presentation attributes are overridden by any rule, `fill`/`stroke` and their longhands inherit, `currentColor` resolves with each element's own `color`, and `display: none`, `visibility`, `opacity` and transforms (about the user-space origin, as in Chromium) apply to children (case `blitz-svg-css`).
- **Size.** Only programs with an `<svg>` link Blitz's SVG support (usvg, 1.6 MiB in a release build): codegen enables the runtime's `svg` feature for them.

## Packages

npm packages are handled by mapping packs (D9, [design](design/M6-LIBRARIES.md#mapping-packs-d9)), one module per package version in `frontend/packs/`. A bare import resolves through the collector to a package directory; its `package.json` name and exact version select the pack. A package without a pack is rejected (`E_DEPENDENCY`), another version of a packed package too (`E_PACK_VERSION`), and so is every use the pack does not cover (`E_PACK`), each at its source location. ## Native runtime and controls

The Rust backend validates every program and generates an application crate linked against `crates/runic-runtime`. The runtime builds the DOM directly through Blitz's mutator API under `<div id="root">`, keeps node handles, and updates only bindings whose cells changed (or all bindings with `--no-opt`). Conditional content and component instances are mounted and removed as subtrees; keyed lists move existing nodes with the framework's reorder strategy. It supplies the browser behaviour the pinned Blitz lacks or does differently ([gaps](BLITZ-GAPS.md)):

- **Events.** Chromium's sequences on Linux: pointer and mouse boundary events, `click`/`dblclick` by click count, `contextmenu` on press, `wheel`, key events with Playwright's modifier order; listeners run target first then bubbling, then document and window listeners, each with its microtask checkpoint; cancelled events have no default action, and neither has a target its listeners removed. Disabled controls get pointer events only.
- **Focus.** Focus moves on mousedown (to the nearest focusable element, nowhere for other content); Tab and Shift+Tab follow `tabindex` order (positive values first); `focus()`/`blur()` run their listeners nested. Every move dispatches `blur`, `focusout`, `focus`, `focusin` with `relatedTarget`. Removing the focused element, or a keyed move detaching it, dispatches `blur` and `focusout` at once while it is still in the document; a focused control that becomes disabled (natively also one that loses its box) is blurred by the focus fixup (a task after the frame, M6). After a move-induced blur, Tab resumes after the moved element, not from Chromium's live range at the detach position (case `reorder-navigation`, a known gap).
- **Controls.** Checkboxes and radio buttons (groups by name in a tree, arrow keys, Tab entering a group at its checked button; checking one, by user or script, unchecks the group); text areas and labels; selects drawn by the runtime (closed control at Chromium's metrics, keyboard on the closed control, a popup drawn into the page with Chromium's keyboard and pointer model). Script-set values update the live control only when they differ, so echoes preserve selection and composition; read-only and disabled edits are blocked; `maxlength` (UTF-16 units) and control characters are stopped before mutation; Alt with navigation or editing keys does nothing in text controls, as on Linux Chromium.
- **Layout and scrolling.** `getBoundingClientRect`, `offset*`, `client*`, `scroll*` read the native layout with Blink's pixel snapping; `scrollTop`/`scrollLeft`, `scrollTo`, `scrollBy`, `scrollIntoView` (every scroll container, whole pixels) and the window equivalents scroll at once. A rendering step after each task runs the window's `resize` event, `scroll` events (one per moved scroller), media query list `change` events, then the focus fixup.
- **Inline styles and the document element** go through the CSSOM (`runic-css` over Stylo): serialisation, `setProperty` and each framework's update model, and (M6) script access to an element's inline style properties (`node.style.transitionDuration`).
- **Library DOM APIs** (M6): `isConnected`, `hasAttribute`, `getAttribute` (`element.id`), `closest(tag)`, `querySelectorAll`/`querySelector` with a subset of selectors (type, `#id`, `.class`, `[attr]`, `[attr=value]`, `:not()`, descendant and child combinators; others reported unsupported), `x instanceof HTMLElement` (false for SVG elements), `getComputedStyle(e).getPropertyValue("direction")` (computed; other properties rejected; the interpreter reports it as layout), `event.detail` (the click count of mouse button events; 0 for keyboard and simulated clicks); `requestSubmit()` is reported unsupported (form submission is not modelled); `new Image()` throws `RunicUnsupportedError`; `element.getAnimations()` (no options) returns the element's running CSS animations and transitions as Animation objects (transitions first, then animations in `animation-name` order; none for an element that is not rendered), one object per animation while it runs, with `finished` (fulfilled with the animation at the frame it ends, before that frame renders; rejected with an `AbortError` when a style change, the element's removal or `display: none` cancels it, at the style resolution that cancels it), `playState` (`running`, also while delayed, `paused`, `finished`, `idle` once cancelled; reading it brings styles up to date) and `pending` (until a frame has seen the animation); other members are rejected (`E_MEMBER`), and an element whose `animation-fill-mode` is `forwards` or `both` (possible only through inline styles) is reported unsupported; the interpreter reports programs reading them as layout; `MutationObserver` observes child lists (case `overlay-host`); observing attributes is reported unsupported; `beforematch` is never fired. M6 (bits-ui's Command): `CSS.escape`; `nextElementSibling`/`previousElementSibling` (a sibling outside the program's elements is reported unsupported) and `matches(selector)` of the selector subset; `parent.appendChild(child)` of a child of `parent`, which moves it to the end (another node, or one holding focus, is reported unsupported; once script reordered an element's children, the framework inserting into it is reported unsupported, as the frameworks place blocks by anchors the runtime does not keep); `setAttribute(name, value)` (the framework writing an attribute script set is covered where it writes the value the element has, as the frameworks skip writes of values they set before; a different value is reported unsupported); bits-ui's `getFirstNonCommentChild(el)`, whose result is an element, or a text node where the program only tests it for truth and reads its data attributes (none). The interpreter reports programs moving nodes or writing attributes as needing the native DOM. An element without layout boxes (`display: none`, or inside such an element) has an empty rectangle at the origin, in `getBoundingClientRect` and in probe geometry, as in Chromium.
- **Event loop.** Input events and timers are tasks, each followed by its microtask checkpoint; state writes queue the framework's flush job; default-priority tasks (React's scheduler, M6 rejection reports) run after the current task, and those queued inside a frame (its rendering step's events, ResizeObserver callbacks) after the frame's layout (M6); a discrete event's update renders pending default-priority updates with it (React's sync lane); host replies (clipboard, history traversals) are tasks after the one that asked. The focus fixup blurs a focused element that became disabled or lost its box in a task after the frame, after the default-priority tasks queued before it (Chromium's style update starts a 0 ms timer; its order against a React render queued by the same frame's scroll events is not stable in Chromium). Timers use the system clock natively and a virtual clock in probes.
- **Animations.** Every style resolution runs CSS transitions and animations at the document timeline's time: real time natively (from the shell's first access to the document, where blitz-shell starts its animation clock; the shell redraws while animations run), the virtual clock in probes, whose `wait` resolves styles at every 16 ms frame so that animations started by timers begin at the frame. Each frame has an animation step (the probe's frames and wait frames, the window's redraws before they render): animations the app holds that ended settle their `finished` promises there, as a task. A style change that cancels an animation shows the element's unanimated style in the same resolution, and cubic-bezier easings are solved to Chromium's precision (both through the [Stylo fork](BLITZ-GAPS.md#fixed-in-the-stylo-fork)). Text in anonymous blocks (direct text of flex and grid containers, including default `inline-flex` buttons) follows its container's restyles, colour transitions included (a Blitz fork patch; case `blitz-anonymous-restyle`).
- **Imperative mounts and ResizeObserver** (M6). Mounted instances render in the body after the container, each before an anchor of its own, and update after the root in each flush pass. After each frame's layout the ResizeObserver notifications due are delivered (each observer's callback a task), with a layout after each round.
- **Rendering.** The canvas is painted white beneath the document. Form controls use Chromium's default font size, `line-height: normal` and radio and checkbox metrics, and buttons Chromium's button layout and baselines; grid containers take their baseline from their first item (Blitz fork); `svg` elements clip their drawing (`overflow: hidden`, as in Chromium's UA sheet). The CPU (vello_cpu) and GPU (vello) renderers are selected per project. Both draw filters and backdrop filters (forks, [research](research/M6-CPU-RENDERER.md#the-gpu-renderer)); the GPU renderer draws windows with area anti-aliasing (as the CPU renderer and Skia; anyrender's default for windows is 16x MSAA), and its fork samples gradients and box shadows at pixel centres. Pixel conformance is pinned to the CPU renderer; `conformance/run.mjs --renderer gpu` runs the same gates on GPU builds, drawn on Mesa's software Vulkan driver (lavapipe) from the locked shell: the representative cases, `filters`, `backdrop-filters` and `gradients` pass it.

## Verification

`conformance/run.mjs` drives the original framework in headless Chromium and the native app's probe build with the same input: clicks, double clicks, context menus, hovers and wheel turns (at an element's centre or a given position in it), key presses and typing, focus, option choices, viewport resizes and emulated preferences, history traversals, reloads and virtual-time waits. It compares DOM semantics (tags, attributes, text, live values, selections, focus), host effects (console lines, with Chromium's reports of unhandled promise rejections since M6, while other uncaught exceptions fail the run; clipboard text, location, history length), geometry within 2 px and, with `--pixels`, screenshots within a mean absolute error of 3/255, over the whole viewport and over each element a case names in `pixelRegions`. Chromium's document timeline is stopped and every CSS animation is sought to the virtual time since the harness first saw it, at the points where the probe resolves styles (Playwright's fake clock does not move the timeline). A case sets its environment: time zone, locale, start URL, clipboard text, random seed (the harness replaces Chromium's `Math.random`/`crypto.randomUUID` by the probe's seeded generator), `localStorage`, and the fake clock for programs that read the time. `conformance/differential.mjs` compares generated code with the reference interpreter on seeded random traces; programs that read layout or listen for scroll events are reported incomplete there and checked against Chromium only. Content mounted in the body after the container is compared as `portals` (M6). The probe runs two frames after the mount before its first snapshot, as the browser waits for two animation frames. Comparisons observe committed output after natural paint and focus settling and never force blur. The Svelte reference is compiled for production. `conformance/interp-vs-browser.mjs` compares the interpreter with the framework without native builds. [M5 results](../conformance/results/m5.md) list the cases, results and known deviations.
