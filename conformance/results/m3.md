## Known deviations

Differences from the frameworks that M3 accepts rather than rejects. Each is either inherent or scheduled; M2's list still applies except where noted.

| Area | Deviation | Plan |
|---|---|---|
| Update granularity | Svelte re-runs all text and attribute updates of a block together; Vue and React re-render components. A value read without reactivity (a `Map` in `$state`, a plain `let`, a module array) therefore refreshes there when a neighbour changes, but natively only when its own dependencies change, even with `--no-opt` for expressions that read only globals | M4 reactivity model |
| Prop expressions | The interpreter re-evaluates a prop expression on every render, generated code only when its dependencies changed. A prop that builds a fresh object (`opts={{a: 1}}`) therefore resets a child's local override in the interpreter but not natively (Svelte keeps the override) | M4 granularity |
| Event dispatch | Natively each listener on the bubbling path runs as its own task with an update in between, so a later listener sees updated list locals and is skipped if the update removed it. The interpreter and the frameworks run the whole path on the state before the first listener | Fixed in M4 (per-event dispatch) |
| Timers in the interpreter | The interpreter renders after a `wait`, not after each timer callback, so child props and remounts within one `wait` lag behind generated code | Fixed in M4 (flush per task) |
| Refs read while rendering | A ref set during an update does not mark its cell dirty, so a binding that reads it (`{el ? 'bound' : 'none'}`) is not refreshed natively; Svelte refreshes it after mount. Vue and React adapters reject render-time ref reads | Fixed in M4 (ref writes extend the flush) |
| Render errors in lists | An exception during a keyed or unkeyed list update drops the old and new blocks without removing their DOM; the interpreter instead rejects events until rendering succeeds | M5 error model |
| Navigation after a move-induced blur | Continues from the moved element natively, from Chromium's detach position in the browser (case `reorder-navigation`) | M5 focus model |
| Svelte proxies | Lazy proxy snapshots are not modelled: a raw write in a later handler stays visible natively, and an object reached back through a cycle keeps its proxy identity (case `ownership-cycles`) | low priority |
| Duplicate keys | throw (as Svelte) where React and Vue warn | inherent |
| React mutation | A child re-renders natively when a shared object it receives is mutated without a state update | M4 (Rules of React as compile errors) |
| Style attributes | Frameworks set dynamic `style` through the CSSOM, so the attribute holds Chromium's serialisation (`width: 20%;`); natively it holds the literal string. Rendering is identical | M5 (Stylo serialisation) |
| Focus requests | `focus()`/`blur()` apply when the running callback returns rather than at the call; the DOM does not change while a callback runs, so only the order relative to other requests in the same callback is kept | inherent until DOM reads (M5) |

Blitz rendering gaps found in M3 (focus ring, inline input line box, placeholders, checkbox appearance and box model, text input line height, shrink-to-fit width rounding) are listed with their fixture workarounds in [BLITZ-GAPS.md](../../docs/BLITZ-GAPS.md).
